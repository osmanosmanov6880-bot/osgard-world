# NEBULA R11 — проверка на реальном оборудовании

Этот документ описывает **настоящий аппаратный тест**, а не оценки FPS по размеру модели
и не синтетические результаты CI. Исполнитель должен открыть production WebGL-сборку
на **своём физическом устройстве**. GitHub Actions с headless Godot не является
проверкой производительности видеокарты пользователя.

## Что тестировать

Откройте https://osgard.world/games/remix/arena-v2/nebula-3d/?r11=1
и сделайте Ctrl+Shift+R. Дождитесь появления игрового корабля и стабильной загрузки.
Начинайте тест только при активной вкладке, без ускоренной записи экрана.

- **F3** — «МАКСИМУМ / ВЫСОКАЯ / ОПТИМИЗАЦИЯ». Меняет дистанцию детализации
  R10/R11 и мощность постобработки. В режиме оптимизации дорогостоящий
  полноэкранный шейдер отключается.
- **F4** — скрыть/показать игровой HUD; полезно для честных скриншотов.
- **F6** — показать/скрыть аппаратные счётчики FPS, CPU frame time, draw calls
  и количества примитивов.
- **F7** — старт аппаратного бенчмарка: 2 секунды прогрева + 20 секунд измерения.
- **F8** — включить/отключить экранную кинообработку для сравнения.
- **F9** — копировать фактический JSON-отчёт. Если браузер заблокировал буфер,
  найти строку `NEBULA_R11_BENCHMARK_JSON:` в консоли браузера.
- **F2** — одна из трёх камер для повторяемого сравнения.

Маршрут: взлететь из АВРОРЫ, пролететь между основными зданиями и над
R11-грузовым доком, затем повернуть к AEGIS. Для сопоставления результатов
используйте один и тот же маршрут, камеру, разрешение и режим качества.

Снимите **три отдельных 20-секундных теста**: «МАКСИМУМ», «ВЫСОКАЯ» и
«ОПТИМИЗАЦИЯ». Если FPS крайне низкий, выполните тест на средней настройке.
Запишите ОС, браузер, ширину/высоту экрана, тип устройства и известную модель GPU.

## Какие метрики собираются

`avg_fps`: FPS из среднего межкадрового времени внутри реального игрового цикла.

`one_percent_low_fps`: приближение FPS по 99-му процентилю межкадрового
интервала. Это метрика микроподвисаний, не GPU-only время.

`p95_frame_ms`, `p99_frame_ms`: длительность кадра в миллисекундах.
`max_draw_calls` / `max_primitives`: счётчики RenderingServer.
`adapter_reported`: имя, сообщённое браузером; оно может быть
**подменено/обезличено** из соображений приватности и не является
подтверждением конкретной видеокарты.

`excluded_long_frames`: исключённые интервалы длиннее 350 мс, которые
могут возникать при сворачивании вкладки. Эти исключения должны быть
минимальными, иначе тест нужно повторить.

Файл также сохраняется в Godot `user://nebula_r11_hardware_benchmark.json`.
В браузере это sandbox-хранилище, а **не** обычный файл в папке Downloads.
Копирование F9/консоль гораздо удобнее.

## Критерии приёмки (цели, НЕ результаты)

| Уровень | Цель среднего FPS | P95 кадра | Поведение |
| --- | ---: | ---: | --- |
| Настольная дискретная графика, MAX | >= 60 | <= 20 мс | Эффекты активны |
| Ноутбук / интегрированная графика, HIGH | >= 40 | <= 30 мс | Ограниченное свечение |
| Слабое устройство, ECO | >= 30 | <= 35 мс | Постшейдер отключён |

Отдельно проверить запуск, сохранение/загрузку, читабельность HUD на 1280x720,
1920x1080, 2560x1440 и мобильный WebGL (если браузер поддерживает его).

На каждом устройстве сохранить общий вид стартовой площадки, вид в полёте
и кадр с деталями брони. Проверить отсутствие пересвета, неправильно
пересекающихся геометрических элементов, исчезновения объектов при LOD
и заметных скачков цветокоррекции.

## Ограничения

CI подтверждает импорт Godot, скрипты, миссии и WebAssembly-экспорт.
Без подключения реального компьютера с графическим браузером
CI не является доказательством стабильных 60 FPS на физическом GPU.
Не записывать придуманные цифры в отчёт и не объявлять проект
«AAA-фотореализмом» без независимых визуальных кадров и аппаратных данных.
