# NEBULA R59 — AURORA PAINT: настоящие 3D-покрытия кораблей

**Статус:** исходный feature-кандидат, НЕ production, НЕ независимая приёмка. Зависимости: PR #762 (R58), #760 (R57) и опубликованный R56. Физические устройства Android/iPhone **NOT_PERFORMED**.

## Почему это не картинка

R59 позволяет тратить честно заработанные в игре CR на индивидуальные металлические покрытия **каждого** реального 3D-корпуса NX-08, NX-12 и NX-21. Краска меняет `StandardMaterial3D.albedo_color`, шероховатость, металличность и излучающий свет материала; 3D-полосы создаются **отдельными MeshInstance3D** прямо в модели в `fleet_airframes_r55.gd`. Настоящий игровой самолёт и независимый `SubViewport` ангара используют один и тот же код. Изменения модуля брони/щита/радара R56 и пилотажа R58 при перекраске НЕ сбрасываются.

| Покрытие | Стоимость в игровых кредитах | Эффект |
|---|---:|---|
| Заводской титан | 0 CR, всегда принадлежит владельцу корпуса | Исходный серебристый металл |
| Полярный кобальт | **680 CR** | Холодный синий металл, бирюзовые световые вставки |
| Пламя Разлома | **1080 CR** | Тёмный графит, янтарные физические рейки |
| Чёрный Монолит | **1650 CR** | Тёмный чёрный материал, золотые рёбра |

Для каждого оплаченного окрашивания создаются **13 независимых настоящих 3D-деталей** поверх уже существующей геометрии корпуса. Это отдельная подсистема с минимальной нагрузкой, не высокополигональные 4K/8K PBR-ассеты и не претензия на фотореализм.

## 5 инженерных блоков

1. **Строгий модельный каталог:** `hangar_liveries_r59.gd` — стоимость, названия, валидные 3D-палитры, `safe_owned`, `safe_equipped`, отдельные принадлежащие/установленные покрытия для каждого из трёх корпусов. Фальшивые идентификаторы, посторонние корпуса и повторные записи из JSON отбрасываются.
2. **Оригинальный рендер:** `fleet_airframes_r55.gd` — замена настоящих материалов у объёмных NX-08, NX-12, NX-21. 13 физических MeshInstance3D на платном покрытии; без смены геометрии базового корпуса, без подмены фотографией и без вмешательства в купленные R56 детали.
3. **Одинаковый 3D-ангар и полёт:** `ship.gd` и `hangar_ship_preview_r44.gd` вызывают `set_livery_r59()` для живого корабля и Godot SubViewport; не два разных прототипа.
4. **CR-покупка и понятный интерфейс:** `world.gd` покупает покрытие **один раз** для выбранного принадлежащего корпуса, сохраняет отдельное владение и автоматически экипирует. Повторное нажатие на уже купленное покрытие меняет только выбор и не списывает CR. Покупки вне видимого ангара, недоступные корпуса и посторонние SKU запрещены. В уже существующем разделе «ФЛОТ» доступно ателье с состояниями «УСТАНОВЛЕНО / ПРИМЕНИТЬ / N CR» и видимыми реальными цветами, без пятой вкладки, которая переполняла бы телефон шириной 320px.
5. **Сохранение и техническая приёмка:** два аддитивных поля `livery_owned_r59` и `livery_equipped_r59` в прежнем JSON `version:1`. Натуральные Godot smoke tests должны доказать 3D-материал, 13 мешей, принадлежность конкретному кораблю, правильные списания 680/1650, возврат после смены корабля, недопустимый SKU, сохранение после повторной загрузки и блокировку покупок, когда ангар скрыт. `check_source.py` обязан отклонять нереальную замену материала моками.

## Границы качества и публикации

- Это **локальная валюта CR**, без серверного античита и без реальных платежей; игрок может изменить локальные сохранения, это не защищённая экономика.
- Полноценные AAA-модели и 4K-текстуры не заявляются. Реальные устройства iPhone/Android, GPU-производительность, нагрев и многочасовая устойчивость: **NOT_PERFORMED**.
- Зависимости строго по порядку: R57 и R58 должны пройти их последние 6/6 тестов и быть приняты в source; затем R59 — полная 6/6 нативная Godot 4.7.2, WebAssembly, Chromium desktop/mobile и security/frontend. Только затем доверенный экспорт из `master`, точные хеши четырёх файлов `index.html`, `index.js`, `index.wasm`, `index.pck`, отдельный release gate и независимая публичная **HTTPS 4/4** с откатом.
