# EMPIRE Ω R138 — крупный блок IV: запрет случайного продакшн-выпуска

27.10.2026 · **только исходники неопубликованной ветки R90**. Этот документ не даёт производственного разрешения, не выдаёт FPS или AAA-оценку.

## Найденный реальный опасный механизм

До R138 `.github/workflows/omega-godot-web.yml` запускался от обычного `push` в master, пересобирал Godot 4.4.1 и **без отдельного подтверждения** делал `git push origin HEAD:master` с новыми `public/games/omega-3d-preview/index.wasm`/`index.pck` и вызывал `gh workflow run deploy-frontend.yml`. Независимый `omega-web-direct-deploy.yml` автоматически слушал `workflow_run` на успех frontend/Omega и мог использовать настоящий SSH ключ. Поэтому простое слияние черновика [PR #500](https://github.com/osmanosmanov6880-bot/osgard-world/pull/500) было потенциальным **непреднамеренным production deploy**.

## Исправлено в исходниках R138

1. **Omega Web exporter** теперь запускается **исключительно вручную** через `workflow_dispatch`, а не при `push`/автосборке. Перед **установкой Godot, экспортом, записью master или уведомлением frontend** запускается исходный `omega-r138-manual-release-guard.py`. По умолчанию пустые переменные → **HARD FAIL / NO DEPLOY**.
2. **Omega direct SSH deploy** также **полностью лишён** автоматических triggers `workflow_run` от frontend/игры и master push. Никакого SSH без отдельного ручного запуска и повторного того же Python-гейта до secrets, сетевых соединений и SCP.
3. Две независимые стороны согласия: оператор вручную вводит точные `approved_source_sha`, `release_ticket`, текст `I_AUTHORIZE_OMEGA_PRODUCTION`; **отдельно администратор репозитория** должен настроить переменные `OMEGA_RELEASE_ENABLED=true`, `OMEGA_RELEASE_APPROVED_SHA=<ровно тот же SHA>`, `OMEGA_RELEASE_APPROVED_TICKET=<тот же ticket>` и все четыре `OMEGA_RELEASE_ART_GO=APPROVED`, `OMEGA_RELEASE_GAMEPLAY_GO=APPROVED`, `OMEGA_RELEASE_PHYSICAL_GO=APPROVED`, `OMEGA_RELEASE_ROLLBACK_GO=APPROVED`. Любой пустой/подменённый SHA, обычный push, workflow_run, другой ref, чужой ticket или отсутствие одной независимой подписи **не допускает реального действия**.
4. Оба старых источника дополнительно сохраняют старый `omega-build-freshness.py` при ручном одобрении. Откатный скрипт, исходные SHA R87, другие сервисы и общая `deploy-frontend.yml` **не меняются**.
5. Тесты `scripts/test_omega_r138_release_lock.py` и встроенная проверка требуют 21 сценарий отрицательного согласия, отсутствие обоих автоматических триггеров, исходное расположение pre-SSH/pre-master-release блокировки и неизменный оригинальный source-freshness. Новый Actions QA работает на неизменном PR head с `contents: read`, не получает ключей и не запускает production.

## Строгие пределы этой работы

- **Код R138 сейчас находится в отдельном PR, а не в действующем master.** Текущая публичная R87 всё ещё защищена отказом объединять главный PR #500; нельзя утверждать, что исходные автоматические workflow продакшна уже изменились до реального согласованного merge R90 → master.
- Это **автоматическая блокировка**, а не подписание четырёх реальных результатов. Актуальное самостоятельное доказательство R136: семь исходных публичных R87 SHA-256 по живому HTTPS совпали, R137 исходная изолированная TLS/Nginx rollback QA требует полного exact SHA повторного CI. Реальная аттестация HTTPS staging VPS не равна локальному Nginx в runner.
- Игра B1/B4 требует **3 самостоятельных 15–20-минутных прохождений человеком и 40 оригинальных миссий**; Green CI не доказывает, что человек справился.
- AAA ART: требуются оригинальные два ранее утверждённых пользовательских изображения, SHA референсов и независимое визуальное `APPROVED` на оригинальных кадрах Godot с одинаковыми условиями.
- PHYSICAL: по состоянию R135 не представлены 36 независимых ПК/Android/iPhone реальных GPU видеозаписей и Godot p50/p95/p99. Никаких выдуманных 60 FPS, генерации изображений или фиктивных чек-листов.
- Без конкретного исходного GO **никаких master merge, ручных новых production dispatch, SSH, VPS**.

## Будущая процедура (только после того как B1+B2+B3+B4 подтверждены людьми)

1. У независимых участников получить настоящие исходные записи GAME, ART и физического GPU и реальный staging rollback; проверить подлинность и SHA.
2. Зафиксировать один защищённый Git commit и исходный исходный WebGL релизный манифест, один ticket. Только администратор отдельно конфигурирует `OMEGA_RELEASE_*\` из независимой ревью-документации; пока не готово — переменные **НЕ настраивать**.
3. Вручную запустить `omega-godot-web.yml` с точным master HEAD SHA и ticket. Проверить оригинальный нативный Godot, WebGL, source provenance, итоговый manifest на том же источнике.
4. После повторного отдельного GO вручную вызвать `omega-web-direct-deploy.yml` с SHA `release.json` и ticket. Проверить фактический HTTPS SHA, WASM, PCK, 390px/mobile + desktop и регламент возврата всех семи R87 байтов.
5. Любое несоответствие → HARD FAIL, restore R87 (под отдельным контролем), документированный инцидент. **До этих условий главный PR #500 остаётся DRAFT.**
