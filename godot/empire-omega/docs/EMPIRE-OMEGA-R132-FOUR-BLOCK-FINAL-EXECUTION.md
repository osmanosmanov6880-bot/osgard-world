**Результат:** полностью воспроизводимый оригинальный Godot WebGL/desktop, машина и трафик, 34 NPC, доказанная транзакционная игровая петля и сохранение.

2. Full exact R132 HEAD Godot **42** suites, 4 реальных Chromium desktop/mobile/F9/host-rAF теста, три pinned CC0 textures и оригинальные WebAssembly/PCK SHA. На merge R90 повторить **всё** для итогового SHA. Архивировать исполняемый ZIP и настоящие PNG.
3. Отдельно пройти без подсказок 15–20 минут **3 независимыми игроками**, в реальной игре: идти → E сесть → трафик → открыть Tab → экономическое действие → миссия → запись → закрытие/reload → продолжение. Сохранить три оригинальных захвата экрана + SHA и mission/state diffs, не смешивая с 75 автоматическими physics-кадрами.
4. Подтвердить **каждую из 40** миссий по назначению, префиксу save/reload и отсутствию блокировок/дублированных наград. При падении — исправить игровой источник, добавить native regression, прогнать повторно.

## Блок II — Качество настоящего кадра (B2 + B3)
**Результат:** не PR со словом «AAA», а графика настоящего Godot, совпадающая с двумя **исходными** одобренными пользователем картинками.

1. Зафиксировать **оригинальные, неизменённые** два референса и их SHA. Получить 4 контрольных кадра на одинаковых реальных Godot камерах/условиях: desktop 1440×900, desktop 1920×1080, mobile portrait 390×844, dusk/night. Не придумывать референс повторно ImageGen.
2. Покомпонентная пара «референс / реальный рендер» с задачами по **архитектуре, дорогам/бордюрам, теням/солнечному свету, машинам, людям, деревьям, подсветке/дождю, темно-золотому HUD, цифрам/пинам и русскому тексту**. Приоритет — отличия, занимающие >5% экранной площади, а не микро-детали вне камеры.
3. Каждое визуальное исправление — в реальном исходнике Godot через ограниченные PBR ArrayMesh/MultiMesh/LOD и исходные физические положения; без дублирования collision bodies, NPC, World3D, GPU-проб. Оригинальный license/asset URL + SHA/коммерческое разрешение для каждого внешнего материала.
4. На физическом Android проверить 320/390px настоящий touch, невозможность нажатий за кадром, 44–46px hit zones, RU/EN/ZH, крупный текст миссии/кнопку «?», закрытие журнала и экранов. Готовность определяет реальное выполнение действия, а не только снимок.
5. Зафиксировать независимый художественный протокол: `APPROVED` / `BLOCKED`, имя человека, дата, два исходных референса, реальные кадры и перечень оставшихся различий.

**BLOCK DONE:** reviewer подписал два покадровых сравнения как `APPROVED`; работоспособный UI и игровой мир не заменены 2D-имитацией; ни один мобильный контроль не перекрывает задание и машину.

## Блок III — Устройства и доказательства (B5)
**Результат:** аппаратное измерение, а не скорость браузерного таймера в виртуальной машине CI.

1. Запустить именно с **точным проверенным SHA**, который тестируется на desktop GPU, Android GPU и физическом iPhone. 4 одинаковых сценария × 3 независимые попытки × 3 платформы = **36** оригинальных записей.
2. Сохранить файл видео и SHA каждого запуска, реальные Godot R36 p50/p95/p99, модель/GPU renderer, browser, качество, разрешение, холодный старт, нагрузку, touch event и two-finger на Android/iPhone. Не подменять это Mesa llvmpipe/SwiftShader requestAnimationFrame.
3. Контрольные **цели**, не обещанные результаты: desktop p95≤16.7ms и p99≤33.3ms; phone LOW p95≤33.3ms и p99≤50ms, без crashes/потери input. Провалы — конкретный узел/шейдер/LOD, повторный замер.
4. Исходные записи загрузить только в закрытое хранилище, исключив приватные данные; сдать в настоящий `omega-r127-physical-device-gate.py`. Независимый оператор подтверждает, что GPU и телефон действительно физические.

**BLOCK DONE:** 36/36 проверенных оригинальных записей и отчёт независимой аппаратной приёмки; нет выдаваемых за GPU данных CI Mesa.

## Что является завершением всего проекта

**Полное GAME+ART+PERF+RELEASE DONE = только когда все четыре блока фактически имеют связанные артефакты и подписи.** Один зелёный Godot/Chromium CI доказывает инженерную воспроизводимость, но **не доказывает** выполнение 15–20 минут настоящим человеком, AAA-фотореал, устройство iPhone/Android или безопасный production rollback. До этого не изменять public master/R87. Следующий инженерный шаг — [R132 PR](https://github.com/osmanosmanov6880-bot/osgard-world/pulls) с 42 native suites и 4 Chromium exact HEAD плюс B3-мобильное реальное задание.
