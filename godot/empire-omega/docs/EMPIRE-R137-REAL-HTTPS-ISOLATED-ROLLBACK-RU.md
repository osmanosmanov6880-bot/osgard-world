## Четыре крупные части B6

1. **Источником оригинала является настоящий публичный HTTPS** `https://osgard.world/games/omega-3d-preview/`, а не `git checkout master`. Семь исходных R87 файлов и `release.json` загружаются при подтверждённом TLS, ответах строго 200, без redirect, без gzip/byte rewriting, только с разрешённого домена. Проверяются все 7 исходных SHA из `omega-r128-r87-immutability.py`, исходный R87 commit, Magic WebAssembly и Godot PCK. Любая ошибка = отказ, не «пропуск».
2. **Реальный Godot 4.4.1 кандидат экспортируется заново** из точного HEAD будущего PR (WebGL `index.wasm`/`index.pck`). Объекты записываются **только в новую директорию `RUNNER_TEMP`**. Переиспользуется проверенная логика R134: исходная R87 сначала физически заменяется файлами новой игры в локальной временной папке, затем заново восстанавливаются все семь оригинальных байтов и сам `release.json`. Сверяются восстановленные SHA с независимой оригинальной HTTP-загрузкой.
3. **Настоящий Nginx + HTTPS, а не макет**: восстановленная R87 раздаётся только через `https://127.0.0.1:4887` из изолированной временной папки с настоящим MIME `application/wasm`, COOP/COEP/CORP и private localhost TLS. Оба теста запускают исходный native Godot WASM/PCK: Chromium **390×844 touch** и **1366×768 Mesa/Xvfb**, требуют подлинного WebGL2, отсутствия ошибок и фактических игровых пикселей, не splash. Тестовый сертификат самоподписанный **только для этого runner**, не доверие к публичному origin.
4. **Финальная запись fail closed**: `R137_FINAL_TRUE_HTTPS_RECOVERY_AND_CHROMIUM.json` связывает точный SHA новой исходной игры, реальную HTTPS R87, 7/7 исходных и восстановленных бинарников и два независимых браузерных результата. Скриншоты и SHA отчёты сохраняются только в GitHub Actions; исходные публичные бинарные файлы и приватный TLS-ключ не загружаются в GitHub artifact.
