# HORIZON R12.1 + R14 — обязательная интеграция двух систем камеры

**Первопричина реального сбоя:** после успешного локального проверки чёрных полос PR #278 слился с активно изменяющимся `master`. Официальный Godot Web экспорт №40072220247 остановился на `v37_safe_chase_camera.gd`: в `main.gd` осталась старая одиночная трассировка луча вместо двухступенчатого безопасного алгоритма R14. Это НЕ проблема самого Godot Web.

**Исправлено в работающей игре:** теперь `main.gd` одновременно:
- использует квадратную базу 900×900 и `Camera3D.KEEP_WIDTH` для реального полного портретного кадра;
- создаёт желаемую позицию через `SAFE_CAMERA.desired_position` и учитывает скорость/ориентацию машины;
- проверяет стены двумя физическими лучами через `SAFE_CAMERA.solve`, без проезда камеры сквозь стены и без старой небезопасной схемы;
- сохраняет адаптивное увеличение сенсорного HUD и переключение ориентаций.

**Критерии:** оба независимых нативных сценария `v37_full_height_portrait.gd` и `v37_safe_chase_camera.gd` должны проходить на одном и том же `main.gd`. Официальный сборщик должен пройти *все* игровые нативные сценарии; не считать WebAssembly выпущенной до этого. Дополнительно новый PR снова компилирует настоящий Godot и проверяет PNG четырёх размеров через Chromium.
