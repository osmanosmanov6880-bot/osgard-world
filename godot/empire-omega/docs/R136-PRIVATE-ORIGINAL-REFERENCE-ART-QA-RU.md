## Блок 2. Реальный ART — теперь можно проверить исходный референс без генерации картинок

Создан инструмент **\`scripts/omega-r136-original-reference-parity.py\`**, который принимает **два настоящих неизменённых файла от пользователя**: (A) оригинальный утверждённый референс визуального игрового мира, (B) оригинальный утверждённый референс графитово-золотого командного центра.

Отдельно инструмент принимает настоящий **GitHub Actions artifact ZIP** исходного Godot/Chromium, содержащий \`omega-r109-evidence/exact-tested-checkout.txt\` (40-значный SHA) и два из оригинальных PNG \`omega-r90-report/data/<SHA>.png\`. Все входные изображения проверяются по файловым сигнатурам и размерам; оригинальные PNG при \`audit\` дополнительно проходят CRC и полную проверку PNG-декодирования через уже существующий \`omega_r73_field_qa.py\`. JPEG-референсы принимаются байт-в-байт без транскодирования.

В **приватной директории вне GitHub** создаются два пары «оригинал / настоящий рендер Godot», SHA-256 для всех четырёх неизменённых файлов, \`manifest.json\`, локальная \`comparison.html\` с исходными изображениями рядом и прозрачным наложением с ползунком, \`review.template.json\` для независимого человека. Программа НЕ обращается к внешним серверам, НЕ отправляет фотографии, НЕ редактирует оригиналы и НЕ ставит оценку «98% похожести», если камеры не совпадают. **Она никогда не объявляет ART APPROVED или PRODUCTION GO.**

**Конкретная схема начала (только с уже существующими настоящими файлами):**

\`\`\`bash
python3 scripts/omega-r136-original-reference-parity.py inspect \
  --browser-zip /PRIVATE/REAL_ACTIONS_BROWSER_EVIDENCE.zip
\`\`\`

Скопируйте ровно имена **двух разных** оригинальных PNG из результата: один реальный игровой вид, один действующий кабинет. Затем, при наличии двух исходных утверждённых картинок:

\`\`\`bash
python3 scripts/omega-r136-original-reference-parity.py prepare \
  --root /ABSOLUTE/PRIVATE/omega-art-review \
  --sha <EXACT_40_HEX_SHA_FROM_INSPECT> \
  --browser-zip /PRIVATE/REAL_ACTIONS_BROWSER_EVIDENCE.zip \
  --world-frame omega-r90-report/data/<REAL_WORLD_FRAME_SHA>.png \
  --cabinet-frame omega-r90-report/data/<REAL_CABINET_FRAME_SHA>.png \
  --world-reference /PRIVATE/ORIGINAL_USER_APPROVED_WORLD.png \
  --cabinet-reference /PRIVATE/ORIGINAL_USER_APPROVED_CABINET.jpg \
  --run-id <TRUE_GITHUB_ACTIONS_RUN_ID> \
  --artifact-id <TRUE_GITHUB_ARTIFACT_ID>
python3 scripts/omega-r136-original-reference-parity.py audit \
  --root /ABSOLUTE/PRIVATE/omega-art-review
\`\`\`

Числа \`--run-id\`/\`--artifact-id\` в локальном отчёте — **заявленные** идентификаторы; их подлинность проверяется отдельной перепроверкой в GitHub, а не доверием локальному JSON. Если исходных референсов нет, команда **не создаёт материал, возвращает HOLD**. Скриншоты текущей Godot R135 именно из реального run #40534942845, artifact #12749957022, шесть PNG, в том числе 960×540 ПК и 390×844 телефон; настоящий source SHA находится внутри ZIP. Событие «композит готов» — это **только материал для художественного ревью**, не замена независимому ART-APPROVED.

**Вопросы, которые должен закрыть живой арт-директор:** композиция/ракурс, архитектурная масса, правдоподобие транспорта и людей, дорога/свет/влажность, степень насыщенности деталей, типографика и вертикальная сетка графитово-золотого кабинета, RU/EN/ZH и качество телефонного кадра. Приоритизировать расхождения, занимающие 5%+ кадра. Финальный «APPROVED» требует имя человека, дату, два неизменённых SHA оригиналов и сравнение с actual Godot, и независимую проверку оригинальных файлов. В настоящий момент **два исходных файла в репозитории не найдены и ART APPROVED не зафиксировано**.
