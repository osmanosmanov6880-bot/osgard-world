# OSGARD EMPIRE Ω — HORIZON R12: реальный вертикальный экран без чёрных полос

## Доказанная исходная проблема

При сквозной проверке настоящей опубликованной Godot R11 в эмулированном мобильном Chromium 390×844 была получена PNG-картинка оригинальной игровой сцены. Видимое изображение находилось **только между y=312 и y=530**, то есть **219 из 844 рядов / 25.9%** экрана. Остальные 74.1% оставались чёрными. Успешный HTTP, наличие WebGL2 и большой PNG не означали работоспособный мобильный UX.

**Причина в коде**: `project.godot` использовал `canvas_items` с неявным Godot `stretch/aspect=keep`, сохраняя настольный аспект 1600×900.

## Текущий реализованный проход

1. В исходной конфигурации Godot задаётся `window/stretch/aspect="expand"`, штатный режим Godot 4.4 для экранов с разным соотношением сторон.
2. Новый модуль `horizon_portrait_screen.gd` измеряет реальные CSS-пиксели Web через доступный только при Web-сборке JavaScriptBridge; принимает смену ориентации и задаёт 2D scaling 2.4 для портретных телефонов шириной 260–900 px. Для desktop/landscape коэффициент остаётся 1.0.
3. `main.gd` применяет настройки **до создания HUD/сенсорных элементов**, подписывается на изменение размера и проверяет коэффициент перед записью, чтобы избежать циклов перерисовки.
4. Нативный тест `v35_portrait_viewport.gd` проверяет проектную настройку, 390×844, 360×780, 412×915, 768×1024, desktop/landscape и обратное переключение без воздействия на физику.
5. Настоящий Playwright теперь открывает WebGL2 на мобильном Chromium, декодирует PNG и считает занятые игрой строки. После публикации **принимается только покрытие больше 68% высоты**, плюс более 62% непрерывной отрисовки. Прежний реальный кадр (25.9%) гарантированно провалит этот тест.
6. При проходе PR обязательно проверять Godot export; затем после защищённого SSH подтверждать новый кадр, а не только контрольные суммы.

## Не заявляем преждевременно

До повторного экспорта Web и получения зелёной мобильной PNG-проверки исправление является **кандидатом**, а не подтверждённым публичным результатом. Эмуляция Chrome не заменяет испытания на iPhone/Android и не подтверждает AAA-фотореализм.
