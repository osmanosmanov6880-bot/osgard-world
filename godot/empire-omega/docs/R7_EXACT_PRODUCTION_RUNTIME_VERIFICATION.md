# EMPIRE Ω — проверка точного публичного бинарника Godot (HORIZON R7+)

## Устранённая слабость

Ранее последний шаг `omega-web-direct-deploy.yml` проверял на сайте только JSON поля
`engine='Godot 4.4.1'`, `native_tests='passed'` и заголовки `index.wasm`.
Старый R5/R6 на сайте мог ошибочно пройти эту проверку даже после SSH загрузки новой R7.

## Новый контракт

`scripts/omega-live-integrity.py` после реального SSH-обновления сравнивает:
- полный `release.json` на GitHub и на `osgard.world`, включая точный `source_commit`;
- точные имена и SHA-256 всех файлов (native HTML, Godot JS, WebAssembly, PCK, audio worklets и заставки);
- скачанные **байты** каждого публичного файла, хешируя поток частями;
- ошибочно отдаваемый HTML вместо бинарника, повреждения и пустые файлы;
- избыточные размеры и подозрительные имена файлов.

Запросы отправляются к реальному HTTPS-сайту с cache-busting query. Сравнение по живым
байтам является доказательством того, что игра не только собрана, но и реально обслуживается
сервером именно той сборкой. Это не тест производительности GPU, качества освещения или
управления на настоящем телефоне.

`--self-test` проверяет отказы при подмене SHA, устаревшем `source_commit`,
отсутствующем файле, некорректном пути, пустом или огромном ответе.
Отдельный PR CI проверяет неизменность самого проверенного Game Web артефакта в репозитории.

## Команды

```bash
python3 scripts/omega-live-integrity.py --self-test
python3 scripts/omega-live-integrity.py --expected public/games/omega-3d-preview/release.json --base https://osgard.world/games/omega-3d-preview --nonce manual
```

Только успешная верификация опубликованного файла и отдельный browser/mobile игровой QA
позволяют закрывать статус новой R7; запуск предыдущей версии на сервере не считается выпуском.
