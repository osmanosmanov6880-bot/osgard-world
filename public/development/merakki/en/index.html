01 / EXPERIENCE

A clear path from selection to an understandable order.

The interface focuses on choosing a dish, configuring extras and keeping cart contents transparent. The prototype does not simulate a completed payment or claim an order was submitted.

01

Multilingual storefront

RU, EN, SV, DE, FR and AR, including right-to-left layout for Arabic.

02

Resilient cart

Data normalization, quantity bounds, state recovery and cross-tab synchronization.

03

PWA readiness

Manifest, service worker, static offline shell and versioned cache.

02 / OPERATIONS

Behind the interface: explicit operational logic.

The source project contains a separate dashboard and API boundaries for orders and financial events; live integrations require a separate verification gate before activation.

01 / DATA

Order queue

Cursor pagination with deterministic created_at and UUID ordering; PostgreSQL timestamp precision is preserved.

02 / MONEY

Refunds and revenue

Partial refunds are tracked separately from captured amounts; currencies are not mixed into one headline KPI.

03 / TRUST

Safer export

CSV omits personal contact fields and neutralizes values that resemble spreadsheet formulas.

03 / DELIVERY STATUS

A clear boundary between demo and production.

We distinguish implemented scope from unverified integrations — without a fictional “ready to take payments” status.
