01 / OPERATING MODEL

Красивый интерфейс.
Продуманная логика.

PHANTOM собран вокруг главного сценария площадки: гость выбирает время и формат посещения, система проверяет ограничения, оператор видит состояние брони и может управлять изменениями без потери истории.

01 — BOOKINGPUBLIC FLOW

Запрос без хаоса

Расписание, длительность пакета, число игроков, закрытые интервалы и пересечения проверяются до подтверждения. Приём реальных заявок остаётся отдельным конфигурационным решением.

02 — CAPACITYRULES ENGINE

Вместимость как правило

Слоты и ресурсы считаются по времени и длительности, а не только по свободному месту в таблице. Временное удержание и подтверждение защищены от гонок на запись.

03 — CONTROLADMIN SURFACE

Оператор видит главное

Недельный календарь, фильтруемый реестр, статусы, перенос, аудит и экспорт CSV дают одну рабочую поверхность вместо набора несвязанных экранов.

04 — DELIVERYNOTIFICATION OUTBOX

Сбой — это состояние

События уведомлений сохраняются в SQLite, имеют ключ идемпотентности и отдельный статус доставки. Временные ошибки получают повторные попытки, а ошибки авторизации — явное завершение.

05 — SAFETYOPERATIONS

Сначала безопасный запуск

Админ-API защищён авторизацией, действия журналируются, резервное копирование документировано, а новый инсталляционный контур не принимает брони по умолчанию.

06 — EXPERIENCERESPONSIVE WEB

Атмосфера без помех

Визуальный язык obsidian, champagne и ночного violet поддерживает клубный характер, а адаптивная сетка сохраняет иерархию на мобильных устройствах.

02 / INTERFACE MICROSCOPE

Три взгляда на одну операцию.

Переключайте демонстрационные состояния, чтобы увидеть логику рабочей поверхности. Здесь используются синтетические данные: это самостоятельный UI-образец, а не подключённая к реальной площадке админ-панель.

03 / ENGINEERING NOTES

Не декорация поверх формы.

В релизе акцент сделан на жизненный цикл данных, повторяемость действий и эксплуатационные ограничения. Эти элементы сложнее показать одним красивым скриншотом — поэтому они разобраны по слоям.

A / 01

Domain logic

Отдельная логика расписания, часовой зоны площадки, длительности пакетов, закрытых периодов и проверки пересечений.

A / 02

Persistence

SQLite и атомарные операции для подтверждения и переноса. Идемпотентная обработка публичного запроса к бронированию.

A / 03

Operations

Аудит статусов, календарь до семи дней, реестр, CSV, health snapshot, защищённое резервное копирование.

A / 04

Delivery

Отдельная очередь уведомлений с политикой повторов. В релизе 3.3.0 есть адаптер Resend и интерфейс HTTPS relay для каналов доставки.

04 / RELEASE & BOUNDARIES

Проверяемый релиз.
Честный статус.

Публикация кейса не означает, что система уже подключена к конкретной площадке. Описываем реализованный проект и результаты тестов отдельно от того, что требует инфраструктуры и согласования перед запуском.

SOURCE PROJECT

3.3.0

В исходном пакете PHANTOM сборка и автоматические тесты прошли локально; архив повторно проверен после чистого извлечения. Это подтверждает исходный релиз, но не заменяет проверку публичного production-развёртывания.

  • ✓
    Build & automated tests

    npm run build, npm test и проверка шаблона конфигурации пройдены в исходном проекте.

  • ✓
    Release archive integrity

    Архивы полного проекта и статического предпросмотра проверены на целостность и контрольные суммы.

  • ✓
    Mail integration boundaries

    Resend протестирован подменным транспортом. Реальная доставка email не подтверждалась; для SMS нужен настроенный совместимый relay.

  • ✓
    Production safeguards

    Публичный приём бронирований отключён по умолчанию. Публичный HTTPS-деплой самого PHANTOM и браузерный E2E в отчёте не заявляются как пройденные.

Граница кейса. Страница и переключаемая панель — публичная презентация с синтетическими данными. Она не подключена к SQLite/API PHANTOM, не принимает настоящие бронирования и не отражает занятость реального клуба. Источником статуса релиза служат файлы поставки PHANTOM 3.3.0; интеграция с площадкой и production-запуск требуют отдельной настройки.
