# OSGARD Full Source Release Acceptance

## Почему создано
Ранние регрессионные проверки использовали синтетические ZIP для гарантированно повторяемых тестов. В этом этапе GitHub Actions собирает **реальный исходный OSGARD WORLD** командой `npm ci && npm run build`, затем проверяет собранную структуру через новый упаковщик и игровой архивный контракт.

Workflow: `.github/workflows/full-source-release-acceptance.yml`.

Выполняются подряд: исходные тесты ZION, реальная сборка `dist`, построение детерминированного ZIP и манифеста, независимая проверка ZIP, маршруты 11 ZION и 8 прочих игр, хеш окончательного ZIP. Все временные файлы хранятся в `RUNNER_TEMP`. Не вызываются ssh, rsync, cloudflare deploy, Stripe, денежные или production-операции.

## Приёмка
- Цель — получить один **успешный запуск** этого workflow на коммите новой ветки. Если сборка или архивная проверка падает, проверьте реальный путь и размер файлов вместо отключения защит.
- Сохраняйте точный commit SHA, лог CI, SHA-256 финального ZIP и версию манифеста. Доверенный CI сам по себе ещё не подпись происхождения.
- Не утверждайте успешное тестирование в браузере, пока не пройден staging на реальном URL.
- Для выпуска нужны отдельные проверки конфигурации прокси, Core API, готовности восстановления и отката.

## Риски
Проверки требуют, чтобы игровой архив имел 19 игровых точек входа по согласованным адресам. Ошибки старой сборочной цепочки или перемещённые файлы будут блокировать CI. Это **полезный обнаруженный дефект**, не основание искусственно ослабить требования.
