# OSGARD RELEASE BUNDLE — интеграционная приёмка 17.10.2026

**Функция:** создание воспроизводимого релизного ZIP из собранного каталога `dist`, детерминированного манифеста SHA-256 и независимая проверка результата двумя ранее реализованными валидаторами. Скрипт не публикует сайт и не использует облачные или продакшен-ключи.

## Команды
```sh
npm ci
npm run build
python3 scripts/release-bundle.py build dist --commit "$(git rev-parse HEAD)" --zip /private/osgard-release.zip --manifest /private/osgard-release-manifest.json
python3 scripts/release-bundle.py verify /private/osgard-release.zip --manifest /private/osgard-release-manifest.json
python3 -m unittest discover -s tests -p test_release_bundle.py -v
```

Для Windows замените подстановку shell на явно полученный SHA из `git rev-parse HEAD`.

## Что реально проверяется
- Установка неизменяемого времени ZIP-записей, стабильного порядка путей и режима прав доступа.
- Манифест всех файлов `dist`, размеры и SHA-256, повторное чтение при упаковке.
- Совпадение каждого ZIP-файла с записью манифеста, отсутствие лишних файлов.
- ZIP-safety gate: CRC, безопасные пути, лимиты, подозрительные секретные имена.
- Базовые HTML-маршруты `/`, `/play`, `/games`, `/intelligence`, `/privacy`.
- Fail-closed при отрицательных и частичных сценариях, без перезаписи готовых выходов.

## Чего это ещё НЕ доказывает
Контракт требует только базовые маршруты, а не работоспособность **всех 19 игр**. Не проверяются сетевой API, доступность на реальных устройствах, право собственности на SDK, реальная доставка Cloudflare/VPS, живой откат, состояние пользовательской базы или контентная безопасность JS. Коммит в манифесте указывается оператором и остаётся утверждением до доверенного CI-attestation.

Следующий настоящий этап: построить ZIP через доверенную CI-сборку с журналом SHA, опубликовать в изолированном staging, пройти автоматический smoke по 19 играм и Core API, затем испытать откат. Никаких финансовых переключателей включать нельзя до отдельной приёмки.

Архив и манифест могут раскрывать структуру продукта. Сохраняйте их в утверждённом приватном хранилище. Приватные ключи и копии Core SQLite не входят в архив.
