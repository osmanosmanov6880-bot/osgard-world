## Capability boundaries and brief coverage

- **Catalog:** 19 catalog entries have distinct capability and availability labels. A reachable route or launch page does not establish playable gameplay for every entry.
- **REMIX console:** `/games/remix/` is the canonical challenge/API console, with server-position controls, read-only session verification after reload, bounded input requests, offline recovery, and result-fetch retries. `/play/remix` redirects there; the legacy hard-coded result/session publication has been removed. REMIX does not currently complete a verified authenticated CORE game lifecycle. Client-supplied player IDs do not prove authenticated ownership.
- **Unity:** the ordinary `/games/remix/player/` route declares the reviewed export unavailable and links to the console. Engine initialization and correct gzip/WASM delivery were demonstrated, but playable scene behavior was not. Re-enabling it requires the original Unity project with a working scene and gameplay scripts/assets, or an already corrected complete WebGL export, followed by successful real-engine scene/input checks before its availability metadata is changed. The C# project is absent from this repository; the rejected binary reactivation experiment is preserved as historical evidence in [REMIX Unity quarantine](REMIX-UNITY-QUARANTINE-2026-10-17.md).
- **Result guard:** the release adds a separate Python guard around the unchanged legacy API. It checks the observed phase before forwarding input and freezes the first valid terminal state/result in a persistent SQLite volume. Frozen results survive guard replacement with that volume retained. This does not restore active matches after the legacy service restarts, authenticate players, verify a replay, or make the legacy phase check and input update atomic. The freeze applies to the first terminal observation through the guard, not to earlier history or direct upstream access. See the [service contract and guard boundaries](REMIX-SERVICE-CONTRACT-2026-10-17.md).

The current release therefore closes specific client, delivery, and API-boundary defects. It does not establish completion of all 255 brief sections. The earlier pass records below remain evidence for their historical revisions and scopes.
