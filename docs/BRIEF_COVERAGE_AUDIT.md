- **REMIX console:** `/games/remix/` is the canonical challenge/API console; `/play/remix` redirects there. This does not establish integration with the complete cross-game CORE progression/result-publication lifecycle or secure second-player admission.
- **Unity:** the ordinary `/games/remix/player/` route declares the reviewed export unavailable and links to the console. Engine initialization and correct gzip/WASM delivery were demonstrated, but playable scene behavior was not. Re-enabling it requires the original Unity project with a working scene and gameplay scripts/assets, or an already corrected complete WebGL export, followed by successful real-engine scene/input checks before its availability metadata is changed. The C# project is absent from this repository; the rejected binary reactivation experiment is preserved as historical evidence in [REMIX Unity quarantine](REMIX-UNITY-QUARANTINE-2026-10-17.md).
- **Result and ownership guard:** the separate Python guard around the unchanged legacy API checks Core identity for newly bound owned matches and requires their owner on both API versions, including frozen results. It also checks the observed phase before input and freezes the first valid terminal state/result in persistent SQLite; retained-volume guard replacement preserves those snapshots. A snapshot does not restore active legacy matches, verify a replay, or make the separate legacy phase check and input update atomic. Freezing begins with the first terminal observation through the guard. See the [original service boundaries](REMIX-SERVICE-CONTRACT-2026-10-17.md) and [current ownership contract](REMIX-CORE-OWNERSHIP-2026-10-17.md).
