# OSGARD Play и cinematic intro — реализация

Состояние исходников: 21 октября 2026 года. Изменения встроены в существующий React 19 / TypeScript / Vite проект.
Раздел `/play`, страницы миров и общее вступление используют настоящий entry приложения; отдельная демонстрационная страница продукт не заменяет.
Production-публикация этого выпуска не выполнена. Процент совпадения с референсами, включая 95%, не измерялся и не заявляется.

Сохранены VECTOR//ZERO, «Империя времени», NULL//SHIFT, «Теневой протокол» с фразой «Добавь тень. Измени город» и остальные проекты текущего каталога.
Фактические статусы и адреса запуска берутся из реестра; названия концепций из визуального референса игры не подменяют.
Поиск, фильтры, избранное и недавние миры связаны с URL и локальной коллекцией; избранное не является сохранением игрового прогресса.
Каталог и общедоступные демо доступны гостю. Серверная авторизация и приватные данные не изменены.

`PlayGameRoute` загружается отдельным lazy route из `src/main.tsx`; код iframe/fullscreen не входит в начальный модуль каталога.
`PlayExploreSections` подключается при приближении к нижним секциям, явном переходе по якорю либо запросе каталога через фильтры.
При отсутствии IntersectionObserver предусмотрен доступный fallback; асинхронная серверная проверка рендера включает весь каталог.
Открытие страницы мира не запускает игровой runtime: iframe появляется после кнопки запуска.
Допускаются только адреса своего origin внутри `/games/`; директории статических экспортов получают явный `index.html`.
Загрузка HTML и подтверждённая игровая сессия различаются: lifecycle-сигналы проверяются по origin, окну iframe и ID игры.
Есть повторный запуск, выход из fullscreen, остановка iframe и переход к игре отдельно; старые игровые механики и хранилища сохраняются.

## Графические ресурсы

Для Play подготовлены 3 большие композиции и 19 отдельных обложек: 22 PNG-оригинала и 46 WebP в `public/brand/play/`.
Для intro подготовлены 3 отдельных слоя: широкий фон, самостоятельный мобильный фон и прозрачный металлический знак; 6 WebP находятся в `public/brand/intro/`.
Итого оригинальная коллекция содержит 25 PNG и 52 WebP. PNG поставляются отдельным архивом графики.
Imagegen-обложки и окружения — художественные изображения, а не скриншоты интерфейса или игрового процесса.
Intro-знак получен редактированием пользовательского референса; он не заявляется как независимо придуманный новый логотип.
Надписи, карточки, кнопки, орбиты и анимация остаются HTML/SVG/CSS-компонентами.
Размеры, SHA-256, точные prompts и происхождение: [Play art](PLAY-CINEMATIC-ART.md), [Play provenance](play-art-provenance/asset-inventory.json), [Intro provenance](intro-art-provenance/README.md).

## Общее вступление и переходы

`src/OsgardTransitionProvider.tsx` оборачивает BrandShell в общем entry; `src/OsgardCinematic.tsx` и его CSS импортируются по необходимости.
Provider хранит активную сессию `{ id, kind, phase, replay }`; новый ID отделяет её от callback предыдущей сессии.
Виды: `intro`, `transition`, `play`. Фазы intro: awakening → activation → reveal → online → enter.
Ключ первого показа — `localStorage["osgard:intro:v1"] = "seen"`; при запрете storage остаётся защита от повторного автопоказа внутри документа.
Повтор из footer запускает событие `osgard:replay-intro` и после завершения возвращает фокус на кнопку повтора. Если она больше не может принять фокус, например отключена новой системной настройкой движения, фокус переходит на `#product-main`.

| Этап | Intro | Короткий переход |
| --- | --- | --- |
| Watchdog ожидания optional visual import | 800 мс | 300 мс |
| Полная последовательность после монтирования visual | 3,6 с | 0,9 с |
| Верхняя граница ожидания импорта + последовательности | 4,4 с | 1,2 с |

Таймер последовательности начинается вместе с visual, поэтому холодный импорт не отнимает время появления знака и надписей.
Если импорт слишком медленный или завершился ошибкой, watchdog освобождает страницу; поздний результат не восстанавливает завершённый overlay.
Событие завершения принимается только от корневой анимации с ожидаемым именем; повторное завершение защищено ref и ID сессии.
Независимый таймер provider, error boundary и обработчик ошибки эмблемы ограничивают сбой optional-визуала.
«Пропустить» и Escape закрывают слой; Tab удерживается внутри диалога, фон получает `inert` и `aria-hidden`, после закрытия фокус восстанавливается.
Реальный маршрут рендерится под слоем сразу. Вступление использует конечные CSS-анимации и DOM/SVG, без отдельного Canvas/WebGL runtime.

## Навигация и настройки

`src/osgardRouting.ts` задаёт allowlist React-маршрутов, а `src/browserNavigation.ts` проверяет и исходный, и целевой путь.
SPA-перехват охватывает обычные same-origin клики между известными React-страницами, включая `/account`, `/workspace` и остальные интерфейсы кабинета.
API/auth-адреса, вход через `/workspace?returnTo=…` и standalone игровые экспорты сохраняют нативные переходы; неизвестные пути не присваиваются SPA.
Модифицированные клики, новая вкладка, downloads, external и `data-native-navigation` также остаются нативными.
Проверки сессии при открытии кабинета, серверная авторизация, сохранения и существующие redirect/reload после входа не изменены. Несохранённые формы сохраняют native beforeunload для ссылок и подтверждение отменяемого Back/Forward.
Back/Forward, query, hash, существующие поля history.state и позиция прокрутки сохраняются; фильтры и якоря не перезапускают вступление.
Первое вступление доступно на всех известных React-страницах, включая кабинет. Короткий переход используется при смене главного раздела; кабинет и его рабочие страницы составляют отдельную группу. Внутри этой группы, при фильтрации и переходах по якорям эффект не повторяется; игровые iframe и отдельные runtime остаются без intro.

- `prefers-reduced-motion: reduce`, ручное `osgard:motion=off` / `data-motion=off` и Save-Data полностью пропускают optional sequence.
- Изменение настройки во время показа завершает активный слой и снимает захват ввода.
- При ≤2 логических CPU или ≤2 GB доступного deviceMemory включается `lowPower`: меньше частиц, отключены лишние слои и фильтры.
- Reduced/static CSS дополнительно отключает внутренние анимации; настройки доступны в существующем BrandShell.

## Подтверждённые игровые исправления

- `public/games/vector-zero/index.html`: добавлен отсутствовавший HUD target, исправлена работа Canvas context и подписи магнитных пластин; пауза/справка возвращают к текущей попытке без reset и повторного события старта. Проверка исполняет реальный runtime и его обработчики.
- `src/TimePrototype.tsx`: необязательная телеметрия изолирована от локальной игры, в том числе при отсутствии `crypto.randomUUID` в HTTP-preview. Общий event queue и ключ `osgard.time.empire.save.v1` сохранены.
- `scripts/build-brand-routes.mjs` формирует `games/time/index.html` с актуальным entry для настоящего Time runtime; standalone `games/time-empire/` остаётся отдельным экспортом.

## Проверка и локальный запуск

Команды выполняются из корня репозитория:

```bash
npm ci
npm run check
node scripts/play-cinematic-smoke.mjs
node scripts/vector-zero-runtime-smoke.mjs
npm run qa:time-ui
node scripts/osgard-cinematic-smoke.mjs
npm run qa:redesign
npm run build
npm run qa:redesign-build
python3 scripts/install-play-cinematic.py --self-test
npm run dev
```

Build gate сохраняет предел initial JS **95 KiB gzip**; сравнивается реальная зависимость entry/route chunks.
Smoke-проверки покрывают каталог и lazy-разделение, игровые lifecycle/управление, таймеры, отказы импорта/storage, motion-настройки, навигацию и восстановление фокуса.
Они дополняют браузерную проверку и не заменяют её.
Существующие `academy-home-smoke.mjs`, `ecosystem-browser.spec.mjs`, `ecosystem-mobile-lab.spec.mjs` и `osa5-visual-smoke.mjs` проверяют актуальные маршруты и интерфейс. Браузерные сценарии используют реальные переходы, ленивый каталог, iframe игры и конечные анимации. Мобильные измерения завершаются до интерактивной проверки каталога; исходный предел CLS 0,1 и профиль замедления сохранены.

## Браузерные QA fixtures и ограничения

Через Vite dev server доступны `/scripts/play-cinematic-viewport.html?width=390&height=844&route=/play` и `/scripts/osgard-cinematic-viewport.html`.
Первая страница открывает настоящий Play в заданном viewport; вторая монтирует настоящий OsgardCinematic с выбором intro/перехода/lowPower.
Fixtures не являются страницами продукта и не включаются в production build. Intro-fixture сбрасывает только ключ intro для проверки первого посещения.
Визуально проверяются desktop/mobile, весь таймлайн, отсутствие пересечений текста, фильтры, карточки, гостевой запуск, skip/Escape и reduced motion.
В доступном тестовом браузере WebGL2 недоступен: запуск Godot нельзя считать подтверждённым; его существующий экспорт не заменён заглушкой.
Подготовка выпуска, allowlist файлов, резервная копия и откат описаны отдельно: [PLAY-CINEMATIC-DEPLOY.md](PLAY-CINEMATIC-DEPLOY.md).
