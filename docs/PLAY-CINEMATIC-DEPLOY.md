# Выборочный выпуск OSGARD PLAY и глобального вступления

По умолчанию эти инструменты готовят и устанавливают **интерфейс PLAY и проверенные исправления VECTOR//ZERO и «Империи времени»** внутри существующего document root. Для общего вступления и SPA-переходов предусмотрен отдельный явный режим `--global-frontend`, описанный ниже. Скрипты не запускают GitHub Actions, не подключаются по SSH и не публикуют сайт сами.

## Что входит в обычный PLAY-архив

Allowlist зафиксирован в коде установщика и не расширяется параметрами манифеста:

| Путь в `dist` | Назначение |
| --- | --- |
| `assets/<name>-<hash>.js`, `assets/<name>-<hash>.css` | Собранные модули и стили. Уже существующий файл с тем же именем и другими байтами блокирует установку. |
| `brand/play/*.webp` | Изображения PLAY. |
| `brand/play/ui-icons.svg` | Единственный разрешённый SVG-спрайт интерфейса с исходными формами Lucide. Остальные SVG этим исключением не разрешены. |
| `play/index.html` | Главная каталога. |
| `play/world/<id>/index.html` | Страницы существующих миров. |
| `games/index.html`, `entertainment/index.html` | Псевдонимы каталога. |
| `games/time/index.html` | Только React-оболочка настоящего маршрута «Империи времени», указывающая на новые hash-named bundles. Остальные файлы `games/time/` не допускаются. |
| `games/vector-zero/index.html` | Единственное фиксированное исключение для standalone runtime: исправлены HUD target, Canvas context, подписи магнитных пластин и возврат из паузы/справки без сброса попытки. Никакие соседние файлы игры не допускаются. |

`games/null-shift-godot/`, `games/remix/player/`, остальные игровые runtime, backend, корневой `index.html`, Nginx и секреты **не входят** в архив. Установщик не удаляет каталоги и не очищает document root. Неизменённые hashed bundles остаются на месте; новые bundles устанавливаются перед HTML.

Для `games/vector-zero/index.html` манифест содержит `expected_previous`: SHA-256 исходного файла из commit `825f28a66877fb07cd9da07fda9c7d3cbc6b87db`. Установщик применяет исправление только поверх этих проверенных байтов или пропускает уже идентичный новый файл. Если на сервере опубликована более свежая или другая VECTOR//ZERO, **весь выпуск отклоняется до записи**. Не меняйте checksum ради обхода этой защиты: сначала нужно отдельно сравнить и объединить изменения игры.

### Почему включена оболочка Time

`scripts/build-brand-routes.mjs` после Vite создаёт `dist/games/time/index.html` из текущего app shell. Этот HTML ссылается на новый entry bundle, а `src/main.tsx` для `/games/time` лениво подключает `TimePrototype`. В существующем `nginx.conf` работают `index index.html` и `try_files $uri $uri/ /index.html`; поэтому маршрут с опубликованным каталогом `games/time/` получает собственную оболочку. Без её замены iframe `/games/time` продолжил бы подключать старый entry и старую игру, даже если новые JS уже скопированы в `assets/`.

Обновление этой одной оболочки доставляет исправление, при котором необязательная телеметрия не блокирует локальную игру в HTTP-окружении без `crypto.randomUUID`. Общий event queue и ключ сохранения не меняются. Standalone `/games/time-empire/` — отдельный маршрут с собственным правилом Nginx; он не включён в выпуск. Корневой `index.html` также остаётся вне allowlist.

## Явный глобальный режим: вступление и переходы

Общее вступление монтируется в React entry, который используется на главной и в остальных разделах. Если установить лишь PLAY HTML, другие существующие оболочки продолжат ссылаться на старый entry. Для этого выпуска выбирайте `--global-frontend` **на этапах упаковки, установки и отката**.

Глобальный архив имеет отдельный `kind: osgard-global-frontend-release`. Его фиксированный allowlist включает те же hashed JS/CSS, PLAY WebP, единственный SVG-спрайт и проверенный VECTOR HTML, а также:

| Точный набор | Назначение |
| --- | --- |
| Корневой `index.html` и 82 React-оболочки | Ровно 83 пути `GLOBAL_HTML_PATHS` в установщике. Они соответствуют `scripts/build-brand-routes.mjs`, включая 19 существующих игровых страниц, Time, OSA, Development и интерфейсы аккаунта. Глобальный режим не допускает произвольный `**/index.html` и даже неизвестный `play/world/<id>`. |
| `brand/intro/energy-platform.webp` | Основная панорама вступления. |
| `brand/intro/energy-platform-1280.webp` | Облегчённый вариант панорамы. |
| `brand/intro/energy-platform-mobile.webp` | Художественно адаптированный фон телефона. |
| `brand/intro/energy-platform-mobile-780.webp` | Дополнительный мобильный размер. |
| `brand/intro/osgard-emblem.webp` | Эмблема с прозрачностью. |
| `brand/intro/osgard-emblem-640.webp` | Малый размер эмблемы. |

Упаковщик вычисляет список маршрутов из **фактических деклараций** `build-brand-routes.mjs` и фактического `redesignCatalog.ts`, не выполняя запись HTML. Он сравнивает результат с фиксированными 83 путями в установщике. Если маршруты добавлены, удалены или структура построителя изменилась, упаковка блокируется до проверки реестра. Все 83 HTML и все шесть intro WebP обязательны. Неизвестные intro-файлы не попадают в архив.

Обновляется только публичная HTML-оболочка `/account`, `/workspace` и других маршрутов: сессии, пользовательские данные, backend и серверная авторизация в пакет не включаются. Standalone `games/null-shift-godot/index.html`, `games/remix/player/index.html`, `games/time-empire/index.html`, их `.wasm`, `.pck`, Unity assets и сохранения остаются за пределами allowlist. Прежнее условие `expected_previous` для единственного исправления VECTOR действует и здесь.

React-интерфейсы кабинета, включая `/account` и `/workspace`, участвуют в SPA и первом вступлении. Переход между кабинетом и другими главными разделами использует короткую анимацию; переходы внутри кабинета обходятся без повторного эффекта. Ссылки входа `/workspace?returnTo=…`, API/auth-адреса и существующие перенаправления после входа сохраняют нативную загрузку. Несохранённые формы сохраняют защиту при уходе и отмене Back/Forward.

Ни манифест архива, ни имя backup не могут включить глобальный режим автоматически. Глобальный архив отклоняется обычным PLAY-вызовом; PLAY-архив отклоняется как неполный глобальный выпуск. Для глобального режима применяются все проверки, backup, атомарная замена отдельных файлов и защита конфликтов, описанные далее.

### Команды глобального выпуска

После окончательной сборки и QA, из корня проекта:

```bash
node scripts/osgard-cinematic-smoke.mjs
node scripts/osa5-brand-smoke.mjs
node scripts/redesign-build-check.mjs
python3 scripts/install-play-cinematic.py --self-test
python3 scripts/package-play-cinematic.py \
  --global-frontend \
  --dist dist \
  --output /tmp/osgard-cinematic-global.tar.gz
```

`osgard-cinematic-smoke.mjs` выполняет настоящие модули маршрутизации, контроллер вступления и обновление metadata в управляемом окружении: history, storage, таймеры, отмена перехода и недоступный импорт. Он проверяет облегчённую заставку на слабом устройстве, отсутствие заставки при reduced motion/Save-Data и полную длительность после загрузки визуального модуля. Ожидание модуля ограничено 800 мс для intro и 300 мс для короткого перехода; после успешной загрузки следуют 3,6 с intro или 0,9 с перехода. Общий предел короткого перехода — 1,2 с. Реальный контент уже отрисован под слоем. Этот тест не заменяет скриншоты и проверку поведения браузерных диалогов. `redesign-build-check.mjs` сохраняет существующий предел начального JS 95 KiB gzip.

Сначала просмотр фактического плана без файловых изменений:

```bash
python3 /tmp/install-play-cinematic.py \
  --global-frontend \
  --root /srv/osgard/html \
  --archive /tmp/osgard-cinematic-global.tar.gz \
  --backup-dir /var/backups/osgard-play
```

Для установки добавьте `--apply` к последней команде. Применяйте PLAY и global через один и тот же backup directory, чтобы они использовали общий lock. Backup глобального выпуска называется `frontend-YYYYMMDDTHHMMSSZ-<sha12>-<random8>`. Для отката подставьте **реальное** `backup_name` из отчёта:

```bash
python3 /tmp/install-play-cinematic.py \
  --global-frontend \
  --root /srv/osgard/html \
  --backup-dir /var/backups/osgard-play \
  --rollback frontend-20261021T120000Z-825f28a66877-a1b2c3d4
```

Команда выше — пример dry-run. После проверки добавьте `--apply`. Без флага глобального режима такой backup не принимается.

## 1. Собрать и проверить пакет

Из корня проекта:

```bash
npm ci
npm run build
python3 scripts/install-play-cinematic.py --self-test
python3 scripts/package-play-cinematic.py --dist dist --output /tmp/osgard-play-cinematic.tar.gz
```

Перед окончательной сборкой зафиксируйте исходники. Упаковщик записывает Git SHA, время, размеры и SHA-256 каждого файла. Незакоммиченный локальный пакет допускается только с `--allow-dirty`; в манифесте он явно помечается `working_tree_dirty: true` и не выдаётся за сборку чистого commit.

Путь `--output` должен быть новым и находиться вне `dist`. Существующий архив не перезаписывается. Оба Python-скрипта должны лежать рядом при упаковке; для установки достаточно `install-play-cinematic.py` и самого архива. Сопоставьте напечатанный `archive_sha256` после переноса архива на сервер.

## 2. Сначала dry-run на подтверждённом document root

Установщик требует **Python 3.9+ на POSIX/Linux** с `O_NOFOLLOW` и directory file descriptors. Далее приведены команды режима PLAY; для общего вступления используйте глобальные команды выше. `/srv/osgard/html` — пример: замените его фактическим каталогом сайта. Укажите реальный абсолютный путь, без симлинков в нём и его родителях. Backups должны находиться вне document root.

```bash
python3 /tmp/install-play-cinematic.py \
  --root /srv/osgard/html \
  --archive /tmp/osgard-play-cinematic.tar.gz \
  --backup-dir /var/backups/osgard-play
```

**Без `--apply` файловых изменений нет**, включая создание backup directory. JSON-отчёт перечисляет `replace`, `create`, `unchanged`, checksum архива и идентификатор исходников. Если указан hashed asset с уже существующим именем и другими байтами, пакет отклоняется: такой файл может обслуживать остальные разделы платформы.

## 3. Установка

Завершите другие операции публикации, меняющие эти же файлы. Собственный lock установщика координирует его запуски с одним `--backup-dir`; другие deploy-скрипты этот lock не используют.

```bash
python3 /tmp/install-play-cinematic.py \
  --root /srv/osgard/html \
  --archive /tmp/osgard-play-cinematic.tar.gz \
  --backup-dir /var/backups/osgard-play \
  --apply
```

Для записи нужны соответствующие права на docroot и backup directory. Установщик проверяет весь архив до изменений, затем создаёт отдельный каталог вида `play-YYYYMMDDTHHMMSSZ-<sha12>-<random8>` с правами `0700`. В нём находятся:

- `release-manifest.json` — исходный манифест выпуска;
- `transaction.json` — путь docroot, контрольные суммы, прежние метаданные, список новых файлов и журнал применения;
- `before/` — проверенные копии только заменяемых файлов.

Каждый файл записывается во временный файл в том же каталоге, синхронизируется и заменяется через `os.replace`. Права и владелец существующих файлов сохраняются. После применения снова проверяются SHA-256 всех файлов выпуска. Ошибка запускает выборочный откат; при конфликте с последующим внешним изменением установщик оставляет backup и сообщает, какие файлы требуют проверки.

Это атомарность **отдельного файла**, а не всего сайта. HTML переключается после bundles и изображений. Веб-сервер, backend и игровые процессы не перезапускаются.

## 4. Откат

Используйте `backup_name` из успешного отчёта. Сначала тот же dry-run, затем при проверенном результате добавьте `--apply`:

```bash
python3 /tmp/install-play-cinematic.py \
  --root /srv/osgard/html \
  --backup-dir /var/backups/osgard-play \
  --rollback play-20261021T120000Z-825f28a66877-a1b2c3d4
```

```bash
python3 /tmp/install-play-cinematic.py \
  --root /srv/osgard/html \
  --backup-dir /var/backups/osgard-play \
  --rollback play-20261021T120000Z-825f28a66877-a1b2c3d4 \
  --apply
```

Имя выше — пример, не существующий backup. Откат проверяет манифест, исходные копии и текущее содержимое **всех затронутых файлов до начала восстановления**. Если файл после релиза изменили, откат отклоняется с конфликтом. Нет `--force`, который молча затёр бы новую работу. Уже возвращённые исходные файлы и уже удалённые новые файлы допускают повторный безопасный запуск.

Откат восстанавливает только заменённые файлы и удаляет только созданные данным релизом. Пустые каталоги остаются. Для нескольких последовательных релизов откатывайте сначала последний. При аварийном завершении или отключении питания сохранённый `inflight`-журнал позволяет выполнить этот же rollback; SIGKILL и потерю питания невозможно превратить в гарантированный автоматический откат работающего процесса.

## Docker

Отдельного `--container` режима намеренно нет. Узнайте тип реального document root, читая только метаданные mounts:

```bash
docker inspect --format '{{json .Mounts}}' osgard-world
```

Если `/usr/share/nginx/html` — **bind mount**, запускайте host Python с `--root`, равным подтверждённому `Source` этого mount. Для именованного volume сначала подтвердите его mountpoint:

```bash
docker volume inspect --format '{{.Mountpoint}}' CONFIRMED_VOLUME_NAME
```

Далее применяется обычный установщик к реальному host path. Если docroot находится только в writable layer контейнера, текущий installer туда не устанавливает. Не заменяйте эту процедуру загрузкой полного `dist`, очисткой `/usr/share/nginx/html` или копированием всего дерева обратно через `docker cp`: это лишит выборочный выпуск защиты игровых сборок. Для такого окружения сначала нужен отдельно проверенный способ доступа к docroot.

## Проверка после установки

Установка файлов не является доказательством работы публичного сайта. После неё отдельно:

1. Откройте `https://osgard.world/play` и убедитесь, что HTML ссылается на bundles из выпущенного манифеста; учтите CDN/browser cache.
2. Проверьте каталог и страницы миров на desktop и 390 px: изображения, фильтры, избранное, клавиатура, reduced motion.
3. Запустите VECTOR//ZERO, «Империю времени», NULL//SHIFT и «Теневой протокол»; проверьте остановку iframe и полноценный прямой запуск. В VECTOR//ZERO проверьте подписи пластин, Escape → справка → возврат с сохранением попытки. У `/games/time` проверьте ссылку на новый entry bundle, запуск игры и сохранение прогресса. Убедитесь, что `brand/play/ui-icons.svg` загружается и интерфейсные значки видимы.
4. Сопоставьте заранее зафиксированные SHA-256 защищённых Godot/Unity runtime до и после установки. Проверяйте реальные `.wasm`/`.pck`/Unity files, а не только ответ HTML 200.
5. Проверьте главную и другой раздел OSGARD. При проблеме выполните проверенный выборочный rollback по сохранённому backup.

Для глобального выпуска дополнительно проверьте первое посещение и повторный вход, прямые `/play`, `/account` и `/workspace`, переходы между главной/OSA/PLAY/Development/кабинетом без перезагрузки, глубокие ссылки с query/hash, телефон, облегчённый режим, `prefers-reduced-motion` и кнопку пропуска. Проверьте несохранённую форму перед уходом, нативный вход через `/workspace?returnTo=…`, вход/выход из аккаунта и возврат назад/вперёд. Встраиваемая `/games/time` и другие игровые runtime не должны получать вступление поверх управления. Эти проверки выполняются отдельно после установки человеком; успешная установка архива не подтверждает их автоматически.

Архив проверяется на целостность, но не подписывается цифровой подписью: устанавливайте пакет из проверенного выпуска и сверяйте его переданный SHA-256. Существующие ACL/xattrs/SELinux labels скрипт не переносит; если они обязательны в вашем hosting, нужна проверка соответствующей политики до применения. Backup — отдельная локальная копия; внешний off-host backup обслуживается отдельно.
