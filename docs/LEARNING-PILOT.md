# OSA Learning — практика, сдача работы и организация пилота

Платёжный блок отложен по указанию пользователя. Это продолжение серверного Core: никаких платёжных вызовов, писем, приглашений или публикации сайта в этом проходе нет.

## Что работает

- `/learning/campus` — выбор проекта, персональный серверный маршрут, итоговая работа и расписание.
- В каждом из восьми существующих уроков — отдельный блок «Сохранить практику в проект». Гостевой прогресс остаётся на месте.
- Сервер сверяет ответ самопроверки с теми же материалами, что использует страница урока. Практический текст требует человеческого разбора.
- Прогресс привязан к аккаунту, проекту и хешу версии материала. Запись другого участника, ручная отметка Core или старая версия урока не заменяет актуальную личную практику.
- Итоговая сдача ссылается на неизменяемый снимок проекта. После неё автор может дорабатывать текущий проект, не меняя сданную работу.
- Разбор по пяти критериям, оценка 0–2 и обязательное основание по каждому. Свою сдачу нельзя оценить как разбор другого участника.
- Владелец проекта задаёт аудиторию, гипотезу, статус пилота и расписание, назначает ведущего из участников с правами редактирования.
- Расписание экспортируется в `.ics`. Отмена присутствует в файле; автоматической подписки и уведомлений нет.
- Посещение — самоотчёт текущего аккаунта после начала занятия. Чужое посещение через этот интерфейс не проставляется.
- Экспорт Core включает учебные попытки, сдачи, разборы, расписание и посещения. Восстановление старой версии проекта не удаляет эти таблицы.

## Запуск и первый путь

1. Распакуйте полный ZIP. Запустите `START-CORE-WINDOWS.bat` при установленном Python 3.10+.
2. Откройте `/workspace`, войдите, создайте проект и включите Learning в контракте. Создавать платный заказ не нужно.
3. Откройте `/learning/campus`, выберите проект. Нажмите «Продолжить».
4. В уроке изучите материал, выберите ответ самопроверки, выполните упражнение.
5. В блоке серверной практики нажмите «Подключить серверный проект», выберите проект и запишите результат упражнения. Сохранение отправляет текст и выбранный ответ на ваш сервер.
6. Если ответ неверен, запись сохраняется с соответствующим статусом, но урок не засчитывается. После разбора можно отправить новую попытку. Верный ответ с текстом практики засчитывается для актуальной версии материала; содержание текста автоматически не оценивается.
7. Пройдите восемь уроков. В Core заполните аудиторию и критерии, добавьте минимум три источника со ссылками, артефакт и практическое сравнение до/после на новом примере.
8. На странице Campus откройте «Итоговая работа», заполните описание и доказательства. Проверка готовности показывает, что осталось; это проверка наличия данных, не экспертная оценка.
9. Сдайте текущую версию. Она останется в истории. Авторство сдачи фиксируется сервером.
10. Другой аккаунт создаётся его владельцем. Владелец проекта добавляет его редактором по логину через Core. Этот участник открывает сданную версию и записывает разбор. Автоматического назначения наставника нет.
11. При замечаниях измените проект и сдайте новую версию. Старый разбор остаётся у старой сдачи.

Сессия Core относится к адресу и вкладке браузера. Новая независимая вкладка или другой браузер может требовать входа; после входа в тот же аккаунт на тот же сервер загружаются те же учебные записи. Проверены две HTTP-сессии; два физических устройства в этом проходе не использовались.

## Расписание

В «Пилот и расписание» владелец вручную задаёт реальные параметры. По умолчанию нет названия действующего набора, дат или выдуманного ведущего. Статус «проводится» — отметка владельца, а не подтверждение состоявшегося занятия.

Занятие содержит название, формат, начало и окончание в UTC, ведущего, необязательную HTTPS-ссылку и повестку. В карточках время отображается в часовом поясе устройства. Длительность — не более восьми часов. Редактор может участвовать и разбирать работы, но не меняет расписание. Наблюдатель только читает.

Файл `.ics` содержит UTC-время, уникальные идентификаторы и состояния отмены. Текст экранируется, строки переносятся по UTF-8-байтам. Файл нужно вручную импортировать в календарь; обновления и отмены не доставляются автоматически. Не считайте импорт подтверждением участия или уведомлением ведущего.

## Согласия и конфликты

Learning требует разрешения в контракте. После его отключения новые записи и чтение через учебный модуль блокируются; собственный полный экспорт через Core остаётся доступным. Восстановление старой версии может восстановить старые согласия — при необходимости включите Learning заново. Учебная история при этом сохраняется.

Проект, включая учебные тексты и обратную связь, доступен его участникам. Это не отдельный приватный кабинет каждого ученика внутри одного общего проекта. Для разделения работ создавайте отдельные проекты и выдавайте доступ только нужному проверяющему.

Запись содержит ожидаемую версию и ключ операции. При конфликте сервер не затирает более новую версию. При сетевом сбое можно повторить тот же запрос; повтор не создаёт вторую попытку или сдачу. При запрете sessionStorage незавершённый запрос доступен в памяти до перезагрузки. Не очищайте его перед проверкой серверной истории, если результат неизвестен.

Несохранённый текст защищён предупреждением перед уходом. Переход между формами с несохранёнными данными требует подтверждения; автоматической черновой отправки нет.

## Статусы и критерии

Правильные ответы, длина практического текста и наличие ссылок не доказывают компетентность. Рубрика требует оснований, но оценки всё равно вводит человек. Все пять оценок 2 дают статус «критерии отмечены участником»; иначе — «нужны доработки». Это не независимый экзамен, не сертификат и не подтверждение квалификации наставника.

Число аккаунтов с доступом не является числом фактически обученных людей. Посещения и статус занятия — самоотчёты. Гипотезы скорости и качества по-прежнему проверяются на новых заданиях с учётом исправлений и помощи.

## Проверки и ограничения

`npm run qa:core-learning` проверяет соответствие серверного каталога исходным урокам, HTTP/SQLite-сценарии и календарный экспорт/незавершённые запросы в Node. Suite включает прежние 16 проверок Core и новые учебные сценарии. Точные результаты — `LEARNING-TEST-REPORT.json`.

Браузерный проход форм, клавиатуры и экранного диктора, реальный наставник, реальные ученики, проведение занятий и продолжение на двух физических устройствах ещё не проверены. Медиастатусы сохранены: неподтверждённые видео и аудио не объявлены опубликованными. AI-наставник не подключён; живое сопровождение не обещается без назначения человека.

Для исходников: `npm run core:curriculum` обновляет `server/curriculum.json` из `osaLessonGuides.ts`; `qa:core-curriculum` проверяет точное соответствие. Сборка автоматически обновляет этот файл перед упаковкой сервера. Статический ZIP включает интерфейс, но не запускает сервер.

После обновления материалов и пересборки перезапустите Core: сервер читает каталог при старте. Старые попытки сохраняются в истории, а актуальный прогресс сверяется с новой версией.

## Панель организатора

На `/learning/organizer` доступны сводка проектов, назначения проверяющих, сроки, очередь работ и отчёты. Назначение не отправляет сообщение. Для назначенной сдачи право нового разбора закреплено за выбранным проверяющим, пока владелец не изменит или не снимет назначение. См. `PILOT-ORGANIZER.md`.
