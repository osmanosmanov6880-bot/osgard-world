# OSA CINEMA V63 — PRIVATE BYTE VAULT

Дата: 29 октября 2026. Новая ветка `feature/osa-cinema-v63-private-media-vault-20261029` основана на V62 #665. Статус до прохождения CI — кандидат; **не публичная премьера**.

## 1. Фактическая загрузка файлов

Добавлен `server/core_cinema_vault.py`: настоящие двоичные данные хранятся в новой таблице `cinema_vault_assets` как BLOB внутри приватного SQLite-файла OSGARD Core, а не в веб-каталоге `dist`. Сервер считает SHA-256 **из полученных байтов**, фиксирует имя, MIME, размер, автора, дату и необязательную ссылку на существующую запись реестра V62.

Допустимые типы: PDF/TXT/PNG/JPEG/WebP/MP4. Простая проверка сигнатуры формата предотвращает наиболее явную подмену типа, но **не** подтверждает отсутствие вредоносного содержимого или пригодность к профессиональному видеопроизводству.

Лимиты строгие: **8 МиБ на файл, 32 МиБ и 16 файлов на кинопространство**. Крупные съёмочные мастера и юридические оригиналы здесь хранить нельзя.

## 2. HTTP API и контроль доступа

- `POST /api/core/cinema/spaces/{id}/vault/upload` получает `application/pdf`, `video/mp4` и другие разрешённые настоящие байты; требует действующую Bearer-сессию, роль owner/editor, `Idempotency-Key`, `X-Space-Version`, кодированное имя; отвергает ошибочную длину, чужую запись, неподдерживаемый MIME.
- `GET /api/core/cinema/spaces/{id}/vault` выдаёт только метаданные после проверки доступа owner/editor/viewer.
- `GET /api/core/cinema/spaces/{id}/vault/{assetId}/download` выдаёт ровно сохранённые байты только авторизованному участнику после повторной серверной проверки SHA-256, заголовком `Content-Disposition: attachment`, типом `application/octet-stream`, `Cache-Control: no-store`, `nosniff`, `X-Frame-Options: DENY`.
- `POST /api/core/cinema/spaces/{id}/vault` с `asset.delete` удаляет BLOB только для owner/editor с ожидаемой версией, оставляет служебное событие аудита; старые резервные копии могут сохранять удалённые байты.
- Origin/Host и существующая сессионная авторизация Core сохранены. Отзыв членства отменяет дальнейшее чтение и повтор ранее успешного upload-idempotency ключа.
- Хеш запроса включает реальные байты, имя, версию, MIME, ссылку; повтор с другим содержимым получает 409.

## 3. Реальное приложение

Пятый раздел **«Файлы / File vault»** в `/osa-cinema/studio/collaboration` работает через Core, на русском и английском, без фиктивных вложений. Отображает квоту, файлы и подтверждённые из байтов SHA-256. Загрузка, ссылка на метаданные V62, ручное удаление с повторным подтверждением. Наблюдатель может скачать по правам, но не может загружать/удалять.

Скачивание дополнительно сверяет SHA-256 в браузере через `crypto.subtle` в HTTPS/localhost **перед** сохранением файла. Нет постоянной публичной ссылки, прямого воспроизведения видео или выдачи приватного пути к SQLite.

## 4. Инженерная приёмка

## Ограничения для мирового релиза

V63 — **self-hosted пилот приватного хранения небольших рабочих вложений**, а не мировая медиосеть. Нет KMS/шифрования на уровне приложения, AV-песочницы, модерации, object storage, CDN, transcoding, HLS, DRM, масштабируемого Postgres, SSO, SLA или проверенной юридической chain-of-custody. SQLite-бэкап включает BLOB, поэтому его необходимо защищать и хранить вне публичной папки. При удалении BLOB исторические копии могут сохранять прежний контент.

**Видеопремьера ZERO WINDOW по-прежнему NO-GO:** 0/13 актёрских сцен снято; юридическая проверка и права не подтверждены. Локальный MP4-прокси в Vault не разрешает публикацию фильма.
