# OSA CINEMA V47 — полная производственная программа до премьеры

**26.10.2026. Baseline: `master` f538502be933a178827fb91a9a296ed88127c461; PR #545 MERGED.** Этот документ — рабочая карта, а **не** подтверждение готового/лицензированного фильма.

## Цель и границы

Цель — превратить существующие реальные *приватные* 239-секундные RU/EN workprint и 45-секундные RU/EN preview в четыре человечески утверждённых, правомерных, доступных и устойчиво проигрываемых аудиовизуальных мастера. Восемь существующих интерактивных сцен — исходный **сценарно-образовательный канон**, но не восемь готовых видеофильмов. Существующий V46 на `/osa-cinema` остаётся доступным без изменений. Никаких выдуманных кинокадров, фиктивного дубляжа, лицензий, зрительских отзывов и «публикация SUCCESS» без настоящих доказательств.

Файл `docs/OSA_CINEMA_V47_EXECUTION_BOARD.json` — машинная доска задач, **всегда NO_GO**, пока внешние подтверждения отсутствуют. Отдельная историческая политика `docs/OSA_CINEMA_V20_PRIVATE_RELEASE_POLICY.json` продолжает запрещать публикацию, подтверждение прав и checkout; V47 не изменяет её.

## БЛОК A — художественный монтаж и звук (режиссёр, монтажёр, звукорежиссёр)

**Вход:** точные оригинальные SHA, зафиксированные в V16; RU/EN 239s и 45s приватные MP4, 6 отдельных MP3 и V17–V23 отчёты. Хранить локально вне GitHub. Применять V23 локальную A/B-студию, V18 EDL и объективные FFmpeg QC.

1. Просмотреть все четыре видео целиком; пометить 64 кандидата склеек в каждом длинном workprint и 10 в каждом preview, фиксируя реальные frame/timecode и связь с утверждённым текстом.
2. Прослушать все RU/EN оригинальные и черновые дорожки полностью, сравнить с действительной речью и сценарным каноном, сверить падения громкости, шумы, черные/статичные фрагменты и музыкальные переходы.
3. Для 8 канонических сцен подготовить режиссёрскую матрицу: `01→08`, номер акта, RU/EN тезис, реальный in/out, source SHA, визуальное решение, факт/источник, аудиособытие, замечания, ответственный. Проектные визуальные предложения в V47 JSON **не подтверждают** существование кадров или уже выполненный монтаж.
4. Снять/создать недостающие планы **только с разрешёнными источниками**. Не объявлять прежние still-image WebP движущимся кино.
5. Создать 4 отдельных финальных кандидата (RU/EN фильм и preview) с новыми SHA. Обязательно QA полной декодируемости, синхронизации, целевой платформенной громкости, credits и достоверного языка; зафиксировать отдельные человеческие approvals.

**Выход:** 4 реальные финальные кандидатные MP4 + V24 PASS без незакрытых объективных дефектов + подписанные художественные протоколы. **HOLD**, если редакционная оценка/язык недоказаны.

## БЛОК B — озвучка, RU/EN WebVTT, доступность (языковые редакторы)

1. По каждой фактической звуковой дорожке получить подтверждённый полный текст реальной речи. Черновые субтитры не могут заменять человеческое прослушивание.
2. Для каждого из 4 MP4 создать соответствующий WebVTT; синхронизировать cue с финальным аудио, проверить паузы, переносы, реплики и шумовые метки, скорость чтения, краевые тайминги и видимость на 390px.
3. Использовать локальную V19 Caption Studio, V19 strict-cues и V23 A/B для прослушивания. Повторить после каждого изменения SHA мастера.
4. Доступность: клавиатура, фокус, выбор языка, screen readers, captions toggling, предупреждение о вспышках при необходимости, reduced motion.

**Выход:** 4 человечески утверждённых WebVTT + связка с SHA 4 MP4. **HOLD** при любой непроверенной речи/таймкоде.

## БЛОК C — права (продюсер, независимый юрист)

Для **каждого** фактически используемого кадра/изображения/музыки/записи/голоса/лица/логотипа/генеративного ассета создать приватную матрицу `source-id → owner → origin → license/consent PDF → allowed territories/term/platforms/derivatives/translations/commercial use → exact final SHA → legal review`. Отсутствие документа => убрать актив либо HOLD. Соглашения, персональные данные, доверенные подписи и секретные ключи **не загружать** в репозиторий. V25 проверяет байты PDF, **не юридическую силу**; V30 криптографические подписи, **не истинность свидетельств**.

**Выход:** независимое заключение юриста и полное покрытие прав на реальные финальные версии. **HOLD** без письменного подтверждения.

## БЛОК D — воспроизводимый owner-prefight (владелец/инженер)

1. Подготовить приватные `masters/`, `captions/` и отдельные reports вне checkout по V28/V29. Нужны четыре настоящих MP4 и четыре VTT, а не CI-синтетика.
2. V29 RUN-001, затем независимо закрепить `V28_CANDIDATE_MANIFEST.json`; V29 RUN-002 с `--pinned-plan` и настоящим rights usage; сохранить контрольные SHA.
3. Прогнать V38/V41 локально (V35→V36→V37→V30 при наличии действительных документов): реальная сверка байтов + привязка подписей + отменяемая изолированная проверка. Использовать доверенный hash реестра публичных ключей *из независимого канала*.
4. Исполнить 8 независимых человеческих gate из V27 (точные имена и роли в JSON). Никогда не считать синтетический PASS юридическим или творческим GO.

**Выход:** закрытый достоверный evidence dossier на exact hash финальных файлов. **HOLD**, если хоть одна роль, SHA или документ не подтверждены.

## БЛОК E — staging/media delivery, реальные устройства (DevOps + QA)

1. Только после прав и издательской готовности создать приватный rights-cleared staging с доступом по принципу необходимости. Оригиналы не выкладывать в открытый URL, GitHub artifact или Pages.
2. Проверить CORS при необходимости, MIME `video/mp4`, `text/vtt`, `HEAD 200`, `GET 200`, `Range 206`, некорректный `416`, целостность full body/SHA, byte seeking, restart/resume и signed URL/auth.
3. На физическом Android/iOS и desktop Chrome/Safari/Firefox проверить RU/EN, фактические subtitle cues, focus/keyboard, slow network, invalid URL, playback failure, accessibility и security.
4. Документировать restart/rollback, мониторинг playback errors, recovery и доказательства exact deployed SHA. Рабочий V46 и остальные маршруты OSGARD не должны измениться.

**Выход:** действительные production-инфраструктура и доказательства доставки; без них HOLD.

## БЛОК F — независимое разрешение и публичная премьера

Юрист → языковые редакторы → режиссёр и звук → субтитры → HTTPS → независимый browser QA → **правомочный издатель подписывает разрешение на конкретные SHA** → release engineer удостоверяет откат и мониторинг. Внешние approvals не создаются агентом. Финальный релиз *отдельным новым изменением* проходит CI exact HEAD, merge reviewed SHA, production SSH exact master SHA и независимый browser acceptance с оригинальными evidence artifacts. До полного набора — NO_GO.

## БЛОК G — коммерция и управление правами после премьеры

Платёжная модель (билет, лицензия, подписка) — отдельный запрос и решение **только после** разрешённого доступа к реальным видео. В отдельном PR проверить charge/refund/tax/privacy/terms/entitlement/chargebacks, региональные ограничения и recovery. Исторические V20 `false` нельзя превратить в `true` на основании одного технического прогона. Изменение правил потребует отдельного правового review и новой политики. Этот V47 ничего не монетизирует.

V47 считается закрытым **как пакет планирования**, когда JSON-доска, документ, source-contract test и CI одобрены на exact SHA. Это **не закрывает** блоки A–G по производству реального фильма. Для любой последующей публикации нужен отдельный независимый approval и отдельный PR.
