# OSGARD — независимая проверка ZIP перед публикацией

## Для чего
Старые тесты проверяют файловое дерево `dist` и выбранные пути. Новый ZIP gate проверяет **уже созданный архив** до загрузки на Cloudflare/VPS. Это отдельный шаг, который не меняет существующий сайт.

## Команды
```sh
python3 scripts/verify-release-zip.py /path/to/OSGARD-RELEASE.zip
python3 -m unittest discover -s tests -p test_release_zip_gate.py -v
```

Проверки: CRC каждого распакованного потока, не менее одного `index.html` в корне, имена без `../`, Windows-разделителей и абсолютных путей, запрет симлинков и специальных файлов, известных secret-looking имён, коллизий регистра, пустых файлов, лимит 20 000 файлов, 25 МиБ на файл, 1 ГиБ на распакованное содержимое, ограничение подозрительного расширения при декомпрессии. Выводятся SHA-256 ZIP и главной страницы для сверки артефакта между сборкой и публикацией.

**Ограничения:** Gate не доказывает корректность содержимого HTML/JS, соответствие исходному коммиту, отсутствие всех возможных секретов внутри файлов, подлинность издателя, отсутствие вредоносного кода, работоспособность API или успешное развёртывание. Уникальные контрольные суммы без подписи не дают аутентичности. Cloudflare Pages может потребовать отличные от этих лимиты в конкретной конфигурации — тогда пересмотрите настройки с отдельным документированием. Никогда не публикуйте личные данные, приватные ключи или резервные копии.

## Следующий шаг эксплуатации
1. Создать релизный архив существующим процессом сборки.
2. Проверить его этим скриптом и сохранить JSON-результат в артефакты CI, не подменяя архив после проверки.
3. Сопоставить ZIP SHA-256 с файлом, отправленным на хостинг.
4. Проверить маршрут, Content-Type, кэш, старт игры и мобильное управление на тестовом адресе.
5. Выпустить только после проверки production health и возможности отката.

Реальная публикация, DNS, Stripe и ключи не изменяются этой итерацией.
