## Сохранённая последовательность гостевой проверки движка

Все четыре JSON скопированы из исходных QA-отчётов **без изменения байтов**.
Проверены допустимые поля, фиксированный origin, маршруты только собственных
QA-записей и отсутствие полей токенов, паролей, cookies, заголовков авторизации
или тел HTTP-ответов. Core-аккаунты в этих гостевых проверках не создавались.

| Отчёт | Результат и объём |
|---|---|
| [Transport blocked](evidence/remix-two-player-transport-blocked-2026-10-17.json) | `FAIL`, `PermissionError`: одна попытка GET, **0 POST**, ни одной созданной QA-записи |
| [Format failure](evidence/remix-two-player-format-failure-2026-10-17.json) | `FAIL`: 9 запросов, 4 завершённые проверки, 5 POST; оба разных игрока получили подтверждение своего `sequence: 1`, затем проверка остановилась на ожидаемом `409` |
| [Read-only follow-up](evidence/remix-two-player-read-followup-2026-10-17.json) | `PASS`: **5 GET, 0 POST**, две проверки; тот же QA-матч завершён с двумя игроками и двумя кадрами, повторный GET сохраняет итог; отчёт содержит SHA исходного `FAIL` |
| [Complete guest exercise](evidence/remix-two-player-live-2026-10-17.json) | `PASS`: **29 запросов = 21 GET + 8 POST, 8 проверок, 43.361 с**; отдельные новые challenge и match, два игрока, два принятых кадра |

Причина остановки второго отчёта — предположение QA-скрипта, что каждый `409`
обязан быть JSON. Уже [зафиксированный v1-контракт](REMIX-SERVICE-CONTRACT-2026-10-17.md)
допускает `409 text/plain` для повторного номера команды. Исправление допускает
этот формат только для ожидаемого отказа ввода, сохраняя точный статус,
`no-store` и предел размера; текст не сохраняется. Успешные ответы по-прежнему
строго проверяются как JSON. HTML-ошибки и скрытое изменение числа кадров
приводят к провалу проверки. Исходные отчёты `FAIL` сохранены.

Полный успешный прогон исчерпал разрешённые **8 POST**: один challenge, один
match, два принятых ввода, два намеренных повтора `sequence: 1` с отказом `409`
и два поздних `sequence: 2` с отказом `409`. Итог до и после позднего ввода
совпадает; начальный и конечный маркеры релиза совпадают. Повторы для проверки
отказа не являются автоматическим восстановлением неопределённого POST.

## Проверка исходников до итогового CI

Зафиксированные локальные прогоны: **52 Core и 4 проверки темпа CI gateway**,
**33 REMIX participant backend**
и **10 participant live-probe fixture**, **26 guest-probe fixture**, **28 REMIX
invitation client VM**. Core-набор включает существующие recovery-тесты,
INHERIT backend и автономные проверки его live-probe. Окончательный INHERIT
client прошёл **30 VM-проверок**, независимо повторённых после исправления
запоздавших ответов при переключении мира. Журнал операции сохраняется,
новый выбор и аккаунт не меняются; восстановление выполняется через GET.

Первый [CI run 39061441165](https://github.com/osmanosmanov6880-bot/osgard-world/actions/runs/39061441165)
на `b9004a9e9bda` завершился `failure`. У INHERIT gateway быстрые последовательные
запросы исчерпали Core-ограничение Nginx (`5r/s`, `burst=20`) и получили `429`.
Исправлен темп только CI bridge: минимум 250 мс между началами запросов,
включая выход из QA-сессий, в пределах прежних дедлайнов и без повторного POST.
Браузерный job дал **96 PASS, 6 skipped, 2 FAIL**: один сценарий недоступного
журнала REMIX на desktop и mobile. Реальный `DOMException.code=22` ошибочно
обрабатывался как внутренний код, а последующий GET приглашения стирал причину.
В обоих traces запрос принятия приглашения отсутствует. Исправлены классификация
ошибки и сохранение причины в контексте аккаунта; две новые VM-проверки охватывают
фоновые GET, явную повторную попытку после восстановления хранилища и смену
аккаунта. Ошибки первоначального прогона не считаются пройденными проверками;
окончательный кандидат должен пройти новый CI.

Эти прогоны не заменяют итоговый CI или браузерную проверку. Гостевой live-отчёт
подтверждает совместимость опубликованного движка с двумя игроками; защищённый
v2-приём второго Core-аккаунта и новый INHERIT ещё требуют публикации и своих
live-проверок. Хэш результата обозначает сохранённый терминальный снимок.
Проверка replay, Unity, восстановление активного движка, production restart,
полный CORE progression и выполнение всех 255 пунктов этим документом
не подтверждаются.
