# OSA CINEMA V50 — безопасный выпуск готового фильма

Дата подготовки: 27 октября 2026. Это инструкция для единственного оставшегося этапа — передачи оригинального медиаархива на действующий VPS OSGARD. Исходная инфраструктура V49.2 уже входит в `master`, а read-only SSH-аудит V50 подтвердил наличие Docker, Nginx, Python, административных прав и 4 037 МиБ свободного места. **На момент аудита MP4 на VPS отсутствовали, постоянный медиа-том не был подключён.**

## Готовый авторский пакет

Точное имя `OSA_CINEMA_V50_MEDIA_ONLY_20261027.zip`, размер **186045021 байт**, SHA-256 `f501e1dec7e8ad83ac135e67ba99d16629246f0a4ca519e5ab2073b904724166`. Внутри строго 12 файлов: 4 MP4, 4 VTT, `index.html`, `manifest.json`, `SHA256SUMS.txt`, `assets/osa-premiere-poster.jpg`. Дорожки VTT автоматически подготовлены и не выдаются за дословно проверенные.

В ZIP для Windows находятся: указанный медиаархив, `OSA_CINEMA_V50_UPLOAD_FROM_WINDOWS.cmd` и `OSA_CINEMA_V50_UPLOAD_TO_GITHUB_RELEASE.ps1`.

**Действие владельца:** распаковать ZIP на Windows, запустить `OSA_CINEMA_V50_UPLOAD_FROM_WINDOWS.cmd`. Скрипт использует установленную официальную GitHub CLI (`gh`), выполняет авторизацию в браузере при необходимости, проверяет SHA-256, создаёт черновик GitHub Release, прикладывает медиаархив и публикует релиз. Публикация GitHub Release запускает GitHub Actions; **не считать это автоматическим подтверждением публикации на OSGARD**.

Прямая ссылка на workflow: https://github.com/osmanosmanov6880-bot/osgard-world/actions/workflows/osa-cinema-v50-media-release.yml

## Что делает GitHub Actions

1. Загружает ровно один Release asset, сверяет его фиксированные SHA-256 и размер, запрещает лишние файлы, symlink и испорченный ZIP.
2. Сверяет 12 исходных файлов с pinned V48.1 manifest и отдельно закреплёнными SHA HTML-оболочки, афиши и манифеста.
3. По уже существующему `OSGARD_DEPLOY_*` SSH-каналу передаёт 186 МБ в приватную директорию VPS и повторно сравнивает SHA-256.
4. Без Docker-recreate и без изменения других сервисов размещает релиз в `$HOME/.local/share/osa-cinema-media/releases/` (постоянная хост-копия). Если активный read-only bind mount появится в будущем, задействует его вместо копии в контейнер.
5. Создаёт копию фильма в действующем контейнере, включает исходный маршрут Nginx `/osa-cinema/premiere/`. До последующих проверок `release.json` отсутствует; ссылка в существующем кинозале скрыта.
6. Проверяет реальные HTTP 200/206/416, MIME и SHA всех 185899405 байт. Реальные Chromium-тесты проверяют 1536px/390px, русский/английский, seek, captions и трейлер.
7. ТОЛЬКО при полном PASS пишет доказательный `release.json`; браузерная кнопка появляется, когда исходный RU MP4 действительно отвечает с ожидаемой длиной. При любом провале — rollback именно этого релиза.
8. После будущих фронтенд-деплоев workflow восстановления читает хост-копию. Он восстанавливает **только ранее одобренную** публикацию с действительным `release.json` и точными SHA; не создаёт сам новую премьеру.

## Статусы

`LOCAL_VERIFIED` — архив готов и проверен, но VPS ещё без фильма.

`MEDIA_STAGED_AWAITING_REAL_HTTPS_AND_BROWSER_QA` — фильм загружен, но не утверждён в качестве публичной премьеры.

`PUBLIC_RECEIPT_INSTALLED` + успешный ответ публичного URL — реальная премьера подтверждена.

При отсутствии подтверждения реальных байтов и браузера статус должен оставаться `NO_GO`. Исторический `docs/OSA_CINEMA_V20_PRIVATE_RELEASE_POLICY.json` не изменяется; платёжный checkout остаётся отключённым.

## Безопасность

Никакие SSH-ключи или токены не включены в ZIP и не запрашиваются у владельца в чате. GitHub Actions применяет сохранённые ранее секреты для существующего SSH-деплоя. При ограничениях диска, чужом релизе, неподдерживаемом Docker-монте, неверных SHA, неработающем Nginx или браузерном тесте процесс немедленно останавливается с логированием причины. Медиа остаются под контролем владельца.
