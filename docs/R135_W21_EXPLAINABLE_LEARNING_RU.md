# OSGARD R135 W21 — методика «почему → что произошло → что делать»

**Цель:** сделать существующие шесть глав настоящим обучением причинности, а не
набором команд «нажми следующую кнопку». Работа исключительно с данными
учебного симулятора, без реальных датчиков или подключения к оборудованию.

## Два уровня объяснения

Игрок сразу видит короткую причину на выбранном языке. В нижнем ряду панели
всегда есть две настоящие кнопки: **УПРАВЛЕНИЕ** и **ПОЧЕМУ?**. Вторая
раскрывает подробную информацию внутри прокручиваемой карточки. Обе
кнопки доступны через Tab/Enter и сенсорное управление. При закрытии
разбора текущая глава и пройденные сценарии не сбрасываются.

## Три проверяемые причины

| Реальная внутриигровая неисправность | Короткий смысл | Что раскрывается |
|---|---|---|
| OPTICAL ALIGNMENT | Смещение учебной оптической метки | Почему ошибочное измерение требует правильного узла и ракурса |
| COOLING AIRFLOW | Виртуальный поток воздуха ниже цели | Почему учебный индикатор охлаждения относится к боковому осмотру |
| SERVICE INTERLOCK | Виртуальный контакт люка не подтверждён | Почему блокировка запрещает запуск до полного закрытия |

Для каждого кейса переход `challenge_step` определяет следующее
действие: остановка → люк → нужный ракурс → сканирование → закрытие
→ безопасный пуск. Если пользователь ошибается, показывается **именно**
тип ошибки из реально вычисленного `challenge_feedback`:

- `WRONG ORDER` — этап нарушен; нельзя обходить порядок.
- `INCORRECT VIEW` — подсвеченный узел не совпал с камерой.
- `WAIT FOR THE STOPPED, OPEN HATCH` — сканирование преждевременно.
- `SAFETY INTERLOCK` — игровая защита сработала и должна сработать.

## Источники истины

`R135LearningCoach.explain(state, chapter, locale)` — чистая функция,
не изменяющая `R135ServiceDirector`. Она читает только настоящий
`summary()`: вид, неисправность, шаг, обратную связь, ошибки,
учебный сигнал и достижение. Не вызывает `set_motion`, `toggle_access_lid`,
`scan_diagnostic`, файловую систему, сеть, реальные API оборудования или LLM.

## Обязательная приёмка

1. Нативный Godot 4.4.1: старые тесты W19, профиль W20 и новый тест W21.
   Реально проверяются ошибка порядка, реальная блокировка люка, неправильный
   ракурс, верный скан, безопасное завершение.
2. Desktop Chromium 1366×768 и мобильный профиль Pixel 7: реальная кнопка
   **ПОЧЕМУ?**, текст короткой причины и развернутый разбор, сохранённые
   восемь рабочих команд, оригинальные снимки от WebGL.
3. Источник и файлы сборки должны совпадать с успешным нативным прогоном
   и последующей независимой проверкой. Никакой автоматической публикации
   поверх W19/W20 без отдельного release pin.
4. Отдельное пользовательское тестирование: человек после ошибки может своими
   словами объяснить, **почему** действие было отвергнуто и **что** делать
   дальше. Пока таких данных нет, педагогическое качество не «доказано».

**Не путать:** W21 — обучающая 3D-симуляция; текст не является процедурой
обслуживания промышленного оборудования в реальном мире.
