# OSA CINEMA V61 — COLLABORATION CORE (реальная серверная интеграция)

Дата подготовки: 29 октября 2026. Ветка: `feature/osa-cinema-v61-collaboration-core-20261029`. Статус до CI: **кандидат на пилотную серверную приёмку**, НЕ запуск мировой облачной инфраструктуры.

## Блок 1 — авторизованный Core и SQLite

Вместо имитации многопользовательской панели V61 интегрирует OSA CINEMA в уже имеющийся сервер **OSGARD Core** (`server/core_server.py`). Новые SQL-таблицы в отдельном модуле `server/core_cinema.py`:
- `cinema_spaces`: собственник, проект из фиксированного набора `zero-window|threshold`, название, атомарная версия.
- `cinema_members`: только существующие зарегистрированные пользователи, роли `editor|viewer`; владелец определяется непосредственно через `owner_id`.
- `cinema_tasks`: задачу нельзя поместить в чужое кинопространство; известные категории, реальная дата, 13 сцен S01–S13 для ZERO WINDOW и `PREVIZ` для THRESHOLD, строго плановые статусы.
- `cinema_audit`: серверный журнал выполненных операций с автором, временем, сущностью и типом, но без содержимого приватных заметок.

Сервис переиспользует действующие HTTP-сессии Core, ограничения Origin/Host, закрытый путь `/api/core/`, JSON-валидацию и SQLite `BEGIN IMMEDIATE` с **Idempotency-Key**. Строго разделяет владельца, редактора, наблюдателя и исключённого пользователя. Любое изменение требует `expectedVersion`. Повтор старого редакторского запроса после исключения пользователя запрещается на уровне сервера, даже если ранее этот запрос был успешен.

Лимиты пилота: до 10 собственных кинопространств, максимум 20 участников и 100 задач на пространство, 2000 записей журнала на пространство. Эти ограничения предотвращают безграничное использование пилотной базы; коммерческое масштабирование и миграции требуют отдельного проекта.

## Блок 2 — реальный адаптивный рабочий кабинет

Маршрут `/osa-cinema/studio/collaboration`:
- Вход через уже существующий аккаунт OSGARD Core. Нет токена — экран реального входа; нет Core-сервера — сообщение об офлайн-режиме, без вымышленных участников и задач.
- Показ настоящих серверных пространств, выбор фильма, создание серверной базы задач.
- Задачи создаются и редактируются на сервере: категории, сцены, ответственные, плановые даты, описания, четыре статуса.
- Владелец управляет ролями по **точному username существующего аккаунта**, без фиктивной отправки email; участник с ролью viewer не получает кнопок изменения.
- Журнал последних 100 реальных серверных операций; скачивание доступного JSON-снимка для собственного архива.
- Реальная обработка 401/403/404, потери Core, ошибки версии и повторной сетевой отправки. Никаких обещаний автоматической синхронизации в реальном времени или облачного SLA.
- Два языка RU/EN, настоящие CSS-макеты Obsidian × Brass, клавиатурные элементы, мобильные 320/390 px, печать. Новых сгенерированных изображений нет.

## Блок 3 — безопасность, доступ и контроль правды

- Новый маршрут получает `noindex,follow`, настоящий статический HTML-shell и не входит в публичный sitemap.
- Содержимое HTTP GET/POST требует Bearer Core. Сам HTML-shell публично доступен, но серверные данные не выдаются без авторизации. Это не скрытый веб-сайт: это приложение с защищённым API.
- Нет сервера загрузки видео, права кинопоказа, внешних email-инвайтов или платежей.
- Не допускаются поля `releaseAuthorized`, `publicVideoUrl`, `rightsIndependentlyVerified`, `publish`; статус `filmed` запрещён.
- Задачи не меняют первичный файл V53: ZERO WINDOW всё ещё 0/13 реально снятых актёрских сцен. Превиз THRESHOLD остаётся локальным материалом; ни один фильм не объявляется выпущенным.

## Блок 4 — проверяемый CI

- `scripts/core-cinema-smoke.py`: настоящие HTTP + SQLite тесты и старые Core-регрессии: авторизация, изоляция, роли, отзыв доступа, идемпотентность, конкурентные записи, восстановление SQLite, жесткое NO-GO.
- `scripts/osa-cinema-v61-core.spec.mjs`: Playwright desktop/mobile против запущенного на GitHub Actions `server/core_server.py` с тестовой SQLite в /tmp. Работающий логин, создание, задачи, редакторы, наблюдатели, журнал, CSV/JSON архив и мобильная ширина — не только статическая страница.
- `scripts/osa-cinema-v61-build-preflight.mjs`: SEO, физический маршрут, отсутствие публикации/видео, ссылочная целостность API.
- GitHub Actions запускает TypeScript, production build, 95 KiB gzip бюджет, отдельные V55–V60 регрессии, реальные Python интеграционные тесты и Chromium.

### Что V61 НЕ утверждает

Это **self-hosted pilot**, а не распределённое SaaS-облако. Нужны деплой с HTTPS reverse proxy, резервное копирование, мониторинг, секреты, независимый security audit, тестирование долговременной нагрузки, политика хранения персональных данных, recovery-план и процедуры инцидентов. В будущем возможен Postgres + регионы и отдельное защищённое хранилище исходных медиа, но они не считаются реализованными в V61.

**Граница ответственности:** управление задачами студии и правами команды ≠ независимая проверка прав фильма и разрешение публичной премьеры.

## V61.1 — архитектура бюджета общего JavaScript
- V61 выявил превышение общего gzip-бюджета стартового OSGARD на 92 байта при добавлении новой top-level React.lazy зависимости.
- Новый экран загружается внутри уже лениво загружаемого кинозального сегмента `OSACinemaStudio.tsx`; в общем `main.tsx` используется существующий сегмент, а не ещё одно top-level связывание. Все хуки Studio сохраняют неизменный порядок, условный вывод производится после хуков.
- Это уменьшает стоимость расширения новых независимых кабинетов для трёх стартовых страниц без увеличения лимита 95 KiB и без изменения запретов публикации видео.
