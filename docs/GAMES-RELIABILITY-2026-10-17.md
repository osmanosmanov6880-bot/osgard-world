## Итог и область работы

Связанный пакет исправляет воспроизведённые отказы игровых клиентов, управление на мобильных устройствах, жизненный цикл встроенного проигрывателя и проверку релизного архива. Основа — `94331ca78e5bc53d2e53c48744580a28b9419ca7`, интеграционная ветка `integration/consolidated-release-candidate-2026-10-17`, [draft PR #128](https://github.com/osmanosmanov6880-bot/osgard-world/pull/128). Проверенный master на старте — `b11f138d196bdc98bb95a8778c87db1ffda6ea6f`.

Исходные 14 pull-request workflows / 15 jobs были зелёными. Это не означало работоспособность всех игровых клиентов: прежний браузерный набор содержал один сценарий ZION-030, а часть внешних проверок пропускалась. В этом проходе ошибки сначала воспроизводились в настоящем Chromium, затем исправлялись.

Локальный итог: **36 passed, 0 failed, 4 blocked** в 40 игровых случаях. Основной каталог: **34/38 passed**, то есть 17 из 19 основных клиентов на desktop/mobile. Облегчённый NULL SHIFT проверен отдельно: **2/2 passed**. `totalAccepted=false`: основной Godot export отсутствует, REMIX match service не предоставлен локальной статической сборкой. Эти ограничения не превращены в успешные игровые проверки.

Работа ограничена текущим OSGARD WORLD. KRAKEN, AETHERION, нативные клиенты, AR, полноценные серверные игровые системы и дальнейшие платформы из мастер-плана этим проходом не объявляются реализованными.

## Исправления поведения

- **SWARM:** устранено затенение DOM-узла строкой в mission brief, вызывавшее TypeError при запуске. На touch добавлена отсутствовавшая кнопка специальной роли BOOST; кнопки размещены без наложения. Опциональный диагностический API только читает реальную симуляцию.
- **VECTOR ZERO:** resize использовал несуществующий `ctx`; исправлено обращение к настоящему контексту canvas. Добавлен отсутствовавший элемент статуса, на котором падал HUD. Поле доступно для фокуса клавиатурой.
- **EMPIRE ORBIT:** динамический world script загружался относительно неверного каталога. Исправлен абсолютный путь и предотвращена повторная загрузка. Устранён декоративный overflow, растягивавший мобильный viewport и мешавший touch.
- **INHERIT:** мобильная панель больше не обрезает инструменты, бюджет и историю. Размещение с клавиатуры использует тот же обработчик, что и pointer. Tab/Escape больше не выбирают `undefined` вместо инструмента. Закрытые панели исключены из взаимодействия и tab-order; cache version обновлён.
- **NULL SHIFT lightweight:** исправлена ошибка `lastHUD` / `lastHud`, останавливавшая синхронизацию 3D-интерфейса.
- **Империя времени:** два внешних CSS `@import` могли сорвать загрузку общего lazy stylesheet и привести к React error boundary при HTTP 200. Playfair Display, Fraunces и Inter Tight теперь поставляются локально с исходными OFL-лицензиями и SHA-256 в `FONT-NOTICES.txt`. Некорректные SVG path, получавшие список координат polygon, заменены соответствующими polygon.
- **Статический каталог и проигрыватель:** история запуска сохраняется ровно один раз, включая путь через lifecycle; retry не дублирует её. Ctrl/Meta/Shift/Alt-click сохраняет браузерное поведение. Поздний `started` после фатальной ошибки больше не объявляет сессию активной. Ошибка скрывает часы; retry восстанавливает состояние; закрытие очищает iframe.
- **Мобильная навигация:** загрузка Inter меняла меню с двух строк на одну и сдвигала содержимое. В локальной лаборатории до исправления CLS был 0.294377. Меню сохраняет один ряд с внутренней прокруткой и видимым фокусом; существующий порог CLS 0.1 не ослаблялся.

## Защита от ложного зелёного результата

Без `--expected-blocked` любой blocker даёт ненулевой exit code. CI явно перечисляет только `null-shift,remix`, а JSON продолжает сообщать `blocked` и `totalAccepted=false`.

- Godot blocker допускается только для основного catalog URL и HTTP 404. HTTP 403/500, пустой HTTP 200 и повреждённый lightweight дают `failed`, несмотря на allowlist.
- REMIX blocker требует свидетельство фактически неудачного запроса к match service. Клиентское исключение без `fetch` даёт `failed`. Строковый статус интеграции и числовой `httpStatus` хранятся отдельно.
- До загрузки страницы запрещаются небезопасные HTTP-методы вне собственного временного static server, включая другие localhost-порты. Запросы прерываются, отражаются в `blockedRequests` / `not-tested`, успешный ответ не имитируется. Для отдельно разрешённой интеграционной среды существует явный `--allow-api-mutations`.
- Отрицательные Chromium fixtures подтвердили классификацию статусов, отказ повреждённого fallback, блокировку POST/PATCH на других origins, разрешение GET и поведение явного opt-in. Это тесты политики runner; они не учитываются как прохождение игр.

## Архив и staging admission

`verify-game-archive.py` сохраняет прежний API и счётчики 11 ZION + 8 legacy. HTML разбирается через `HTMLParser`; проверяются реальные declarative dependencies, локальные вложенные документы, литеральные CSS `url()` и `@import`, включая рекурсивные импорты и циклы. Навигационные ссылки не выдаются за ассеты. Пустые файлы, HTML-ошибки вместо ресурсов, неверные бинарные сигнатуры и выход за корень архива блокируются. Ограничены размеры файлов, суммарное чтение и количество ссылок. Канонический `about:blank` разрешён только как встроенный документ.

Это не исполнение JavaScript и не полный граф динамических `import`/`fetch`, Unity, Three.js, Workers, `srcdoc`, SVG/webmanifest internals или строковых вариантов `image-set()`. Полный контракт и ограничения описаны в [GAME-ARCHIVE-ACCEPTANCE.md](GAME-ARCHIVE-ACCEPTANCE.md).

В `staging-release-acceptance.py` закрыта возможность проверить чистый каталог `dist`, а передать другой ZIP: каталог теперь сверяется по каждому файлу с тем же manifest, который привязан к ZIP. Сравниваются manifest digests. ZIP binding проверяет корректный Git SHA и точные целочисленные типы schema/file_count. Исправлено распознавание настоящей табуляции в проверке `_headers`.

Архивный набор тестов: **62/62**. Весь Python-набор: **208/208**. Даже `ready_for_staging_review` означает только результат статической проверки; поля `staging_deployed` и `production_modified` остаются false.

## Выполненная проверка и повторение

- `npm run build`, TypeScript, 11 целевых npm QA-команд, final build budgets и frontend preflight — успешно.
- `python3 -m unittest discover -s tests -v` — 208 passed.
- `npm run qa:games-browser -- --expected-blocked null-shift,remix` — 36 passed, 0 failed, 4 blocked; 40 случаев.
- `npm run qa:browser -- --retries 0 --reporter line` — 42 passed, 6 skipped, 0 failed. Все 10 новых catalog/Time tests прошли. Шесть skip — три desktop-only case captures в mobile project и три mobile-only lab cases в desktop project.
- Независимое review проверило runtime fixes, parser/path/budget semantics, provenance binding, browser policy и CI integration. Подтверждённые замечания исправлены.

Playwright закреплён в lockfile. Для нового checkout: `npm ci`, `npx playwright install --with-deps chromium`, `npm run build`, затем команды выше. CI строит штатный SPA `dist`: копирование `public/games` поверх собранного маршрута удалено. Игровой runner и существующие user journeys имеют отдельные output directories и сохраняются как Actions artifact.

Точный commit SHA и GitHub CI необходимо сверять в PR; старые зелёные проверки исходного head не являются проверками нового коммита. CI Full Source Acceptance обычно собирает синтетический PR merge SHA — его нельзя выдавать за head SHA. ZIP создаётся с SHA фактически проверяемого дерева и затем независимо проверяется командами `release-bundle.py verify` и `staging-release-acceptance.py`.

## Состояние допуска к публикации

PR остаётся draft. Merge и deployment в этом проходе не выполняются. Изменения `public/games/**` и `src/**` попадут под существующий VPS deploy workflow при будущем merge в master; push в текущую integration branch сам по себе production deployment не запускает.

До production readiness остаются: основной Godot export и его отдельный runtime adapter; настоящий REMIX match service и серверные игровые интеграции; проверка опубликованного staging с MIME/CSP/cache/redirects; физические мобильные устройства; изолированное восстановление реальной Core backup. Платежи, авторизованные серверные сценарии, live rooms и полноценное прохождение всех игр этим локальным набором не сертифицируются.
