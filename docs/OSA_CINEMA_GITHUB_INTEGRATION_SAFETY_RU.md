# OSA CINEMA — безопасная интеграция локального комплекта с основным GitHub

**Статус этой поставки:** автономный локальный комплект с исправленными защитами, но не новая запись в репозитории. GitHub-подключение в текущем сеансе вернуло `link_id must identify an eligible linked account`; ни push, ни pull request не подтверждались.

## Не перезаписывать серверные доказательства заглушками

Файл `docs/OSA_CINEMA_V18_PRIVATE_FOUR_TRACK_QA.json` внутри **локального ZIP** является тестовым примером (четыре пустые дорожки, аномальный SHA-256). В локальном комплекте утверждения о проверенном аудио/видео исправлены на `false` и добавлен `TEST_FIXTURE_NOT_ACTUAL_MEDIA_EVIDENCE`. Он существует только для воспроизводимости тестов. **Не копировать этот файл поверх настоящего V18 QA в GitHub.**

Скрипт `scripts/osa-cinema-v20-release-audit.mjs` в этом комплекте также явно различает согласованность документов и независимую проверку исходных медиабайтов. Его перенос в основной репозиторий требует сравнения с актуальным `master`, сохранения оригинальных медиадоказательств и повторного CI — в том числе профилированного V18/V20 аудита. Исходный GitHub-релиз не должен превращаться в тестовую заглушку при синхронизации.

## Безопасная последовательность после восстановления подключения

1. Взять *текущий*, а не сохранённый старый `master` репозитория `osmanosmanov6880-bot/osgard-world`.
2. Создать отдельную ветку для модуля первого запуска. Добавить `START_OSA_CINEMA.cmd`, `START_OSA_CINEMA.sh`, `scripts/osa-cinema-v32-first-run.mjs`, `scripts/osa-cinema-v32-first-run.test.mjs`, `scripts/osa-cinema-v32-package-integrity.mjs`, `scripts/osa-cinema-v32-package-integrity.test.mjs`, `docs/OSA_CINEMA_V32_FIRST_RUN_AND_RELEASE_GATES_RU.md`, `docs/OSA_CINEMA_OWNER_CRITICAL_EVIDENCE_RU.md` и `.github/workflows/osa-cinema-v32-first-run.yml`.
3. Учесть, что `CHECKSUMS.sha256` входит **только в локальную закрытую ZIP-поставку**: при простом копировании новых скриптов в checkout GitHub проверка пакета без отдельной упаковки закономерно остановится. Сначала должен быть собран и независимо проверен релизный архив с контрольными суммами. Пересмотреть и по отдельности включить документальные исправления V20 аудита. **Сохранить настоящий GitHub V18 QA, если в нём реальные SHA-256 и аттестации.** Из локального архива его не переносить.
4. Не включать в коммит `CHECKSUMS.sha256` из ZIP, реальные MP4/WebVTT, локальные PDF, пароли, приватные Ed25519-ключи или личные каталоги. `README_START_HERE_RU.md` — инструкция автономного пакета, не предназначена для перезаписи основного GitHub README.
5. Запустить Node 22 + FFmpeg + FFprobe, все `.test.mjs`, отдельно реальный Chrome/мобильный Playwright и CI приложения. Слить PR только при всех зелёных проверках.
6. Публичные URL, коммерческий checkout, `publicationAuthorized` и `rightsCleared` не изменять до внешнего письменного решения.

## Что можно и нельзя утверждать

- **Можно:** 114 синтетических инженерных проверок, закрытая инвентаризация ZIP, fail-closed при подменах, исправленные предупреждения о происхождении QA.
- **Нельзя:** реальное происхождение содержимого фильма, достоверный язык озвучки, законность каждой лицензии, полномочия человека-подписанта, испытания Windows/macOS на физических устройствах или выпуск фильма в production.

Итог: локальный пакет служит для технической подготовки и передачи владельцу, оставаясь `NO-GO` для коммерческой премьеры.

## Машинно проверяемая локальная Git-интеграция

В автономную поставку добавлен инструмент `launchers/OSA_V32_SAFE_GITHUB_IMPORT.mjs`. Режим `plan` проверяет: полную SHA-256-целостность исходного ZIP, отсутствие символических ссылок в путях, подлинный Git checkout с веткой `master`, чистоту рабочего дерева, допустимый `origin` и отсутствие расхождений с любым существующим новым V32-файлом.

Режим `apply` дополнительно выполняет `git fetch origin master` и подтверждает, что локальный `HEAD` точно соответствует свежему `origin/master`. **Только после этого** инструмент создаёт ветку, копирует отсутствующие файлы из закрытого перечня, проверяет каждый SHA-256 и создаёт локальный коммит. Он не делает push и не открывает PR. Конфликт или отсутствие доступа к удалённому GitHub — повод прекратить перенос, а не отключить проверки.

Никакой перенос старого QA V18, других V19–V31 скриптов, коммерческих флагов, MP4, WebVTT, PDF или ключей инструментом не разрешён. Сохраняйте оригинальные данные основного GitHub независимо от локальных тестовых заглушек.
