# OSA CINEMA V40 — изолированная и отменяемая проверка закрытого фильма

**Режим:** инженерная проверка на компьютере владельца. **Публичный показ и платная премьера: NO-GO.**

## Изменение по существу

В V39.1 истечение времени переводило панель в HOLD, но внутренняя асинхронная проверка V38 могла продолжать читать файлы. V40 запускает V38 в отдельном дочернем Node.js-процессе. При тайм-ауте, выходе из кабинета или выключении HTTP-сервера применяется `AbortController` и реальное завершение процесса. Поздний результат не может восстановить старый отчёт.

Пароль `OSA_CINEMA_OWNER_PASSWORD`, переменные с токенами/ключами и `NODE_OPTIONS` дочернему процессу не передаются. Пути к локальным источникам передаются ограниченным JSON по stdin, **не через командную строку дочернего процесса**. Потоки stdout и stderr отделены: stdout ограничен 16 КБ, необработанный stderr владельцу или браузеру не показывается. Любое превышение, авария, неправильный формат или отмена возвращают `HOLD`. Исходные MP4, WebVTT, PDF и юридические документы остаются вне HTTP-сервера и вне GitHub.

Сама проверка V38, контрольные суммы, подлинные V16/V18/V20, восемь реальных локальных медиафайлов и опциональные независимые Ed25519-подписи сохраняются без ослабления. Подписи свидетельствуют о контроле ключа, **не** о законности лицензии.

## Как запустить

1. Подготовьте актуальную папку исходников `osgard-world` с V40 и установленными **Node.js 22+**, `ffmpeg` и `ffprobe`. Старый автономный ZIP V34 не включает V40.
2. Отдельно от репозитория подготовьте приватные папки: V29-отчёты с `CHECKSUMS.sha256`, четыре финальных MP4 и четыре соответствующих WebVTT. На Linux/macOS права папок `0700`, файлов `0600`.
3. На Windows дважды щёлкните **`START_OSA_CINEMA_V40.cmd`**, на macOS/Linux выполните `sh ./START_OSA_CINEMA_V40.sh` в папке проекта. Оба запуска используют совместимый мастер V39 для запроса путей и пароля без помещения пароля в параметры процесса.
4. Откройте выводимый `http://127.0.0.1:PORT`, войдите по паролю, нажмите «Проверить файлы и отчёты». Проверка работает локально в отдельном процессе.
5. При успехе доступна только обезличенная сводка `NO_GO`. При ошибке, тайм-ауте или отмене прежняя сводка отзывается; никто не может скачать доказательные материалы через браузер.

## Обязательная приёмка

* Отдельные тесты проверяют отмену реального запущенного subprocess, отсутствие переменных с секретами, закрытие по logout, лимит 16 КБ, отказы на некорректный JSON/exitCode, а также обязательный `NO_GO`.
* Сквозной тест с реальными Node, FFmpeg и FFprobe использует **только синтетические** четыре MP4 + четыре VTT, затем запускает V29 → V38 через авторизованную веб-панель с новым V40 worker.
* CI Windows, macOS, Linux и Ubuntu FFmpeg — необходим до слияния с `master`; локальный Linux сам по себе не подтверждает тестирование на физических устройствах владельца.

## Что V40 не решает

Программа **не** выдает лицензии, не подтверждает действительность договоров или права подписантов, не проводит реальное прослушивание RU/EN, не публикует фильм и не включает платежи. Для коммерческой премьеры остаются финальные проверенные MP4/VTT, правовая/редакторская приёмка, настоящий HTTPS и QA устройств, а также отдельное разрешение правомочного издателя на точные SHA-256 материалов.
