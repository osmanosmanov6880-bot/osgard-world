# OSGARD R135 W16 — honest Android Chrome / iPhone Safari hardware acceptance

## Implemented capture path
After this PR is accepted and the next reviewed frontend deploy succeeds, open:
\`https://osgard.world/games/r135-device-capture/\`

The **same-origin** page embeds the genuine Godot WebGL lesson. It reads the actual
\`/games/r135-service/release.json\` bytes and verifies SHA-256 before any
measurements. It does not send evidence to an API, access camera/microphone,
record names, or install trackers.

Supported: a real Android phone using Chrome, or a real iPhone using Safari.
No Web Inspector/CDP is needed on iPhone. The page records the engine's exposed
FPS samples and requestAnimationFrame callback intervals for 65 seconds.
These are NOT GPU frame-completion timings, thermals or measured tap latency.

## Physical operator procedure
1. Use a real phone. Open the capture page. Confirm the actual game loads;
   **W18 must first be publicly accepted**. If the manifest source, version,
   or hash is wrong, stop: the tool refuses W11/W14.
2. Choose ECO or HERO both in the real game and on the capture controls. Keep
   the phone in portrait or landscape for the entire session. Check the
   physical-device attestation **only on a real device**.
3. Start 65-second capture, keep browser foreground and phone visible. A
   backgrounded page, orientation change, different graphics mode, inadequate
   raw samples or incorrect release is rejected.
4. After the measurement, take an ORIGINAL native PNG screenshot on that
   phone. Select that unmodified PNG in the page and export its JSON report.
   Transfer BOTH JSON + PNG to a private evidence folder. The SHA is derived
   from real uploaded PNG bytes; screenshots are never generated by tests.
5. Fully close/restart browser between repetitions, and repeat each matrix
   cell **twice independently**. Change only the relevant ECO/HERO or
   portrait/landscape axis, and make each screenshot filename unique.
6. A second real person verifies device model, OS/browser identity, tested
   touchscreen actions, original screenshots, thermal/battery observations
   and the honest caveat that rAF != GPU completion. Only that reviewer may
   change the two review fields in the combined JSON after hands-on inspection.

## Required matrix (16 original physical sessions)
- Android Chrome: portrait ECO×2, portrait HERO×2, landscape ECO×2,
  landscape HERO×2.
- iPhone Safari: portrait ECO×2, portrait HERO×2, landscape ECO×2,
  landscape HERO×2.

## Offline assembly and structural validation
With Node.js 22 and all original PNGs in the **same folder** as their JSONs:

\`\`\`bash
node scripts/r135-device-matrix-assemble.mjs \
  scripts/r135-w18-release-pin.json \
  ./private-r135-w16-captures \
  --out ./private-r135-w16-captures/w16-sessions.json
\`\`\`

The assembler refuses symlinks, duplicate session IDs, missing or modified
screenshots, unsafe file paths and incorrect PNG signatures. The output status
is \`PENDING_INDEPENDENT_PHYSICAL_REVIEW\`; both reviewer flags are FALSE by
default and the CLI may exit code 3 to indicate incomplete human review.

After genuine independent review, run:

\`\`\`bash
node scripts/r135-hardware-matrix.mjs \
  scripts/r135-w18-release-pin.json \
  ./private-r135-w16-captures/w16-sessions.json
\`\`\`

The validator checks 8 cells × 2 sessions, source/manifest pin, original PNG
SHA, raw vs reported frame callbacks, actual sampled Godot FPS, correct
orientation and quality. Even with a structurally complete report, it only
returns \`REVIEW_REQUIRED_NOT_HARDWARE_CERTIFIED\`. Independent on-device
assessment, unsupported device bugs, heat and touch quality remain separate
manual gates. Synthetic CI fixtures are NEVER evidence of real phones.

## Safety and accessibility
No camera, location, external telemetry, personal accounts or external
microphone is requested. The page uses same-origin assets only. Android/
Safari user-agent text and a checkbox are not cryptographic proof of
physical hardware. Screenshots may contain personal notifications; capture
with Do Not Disturb and review them before sharing. No 8K/AAA, GPU thermal,
WCAG or physical-device claim is accepted without source proof.
