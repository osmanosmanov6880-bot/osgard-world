# OSA CINEMA V30 — криптографическая сверка восьми внешних согласований

**Результат этого этапа: приватный контроль подлинности подписей, НЕ разрешение коммерческого показа.** V30 реализован как локальная программа, которой передаются **настоящий отчёт V29 с четырьмя закреплёнными MP4 и четырьмя WebVTT**, доверенный реестр восьми публичных ключей, восемь подписанных заявлений и восемь приложенных PDF-документов. Проверяются хеши, принадлежность ключей, срок действия, уникальность ролей, связь с конкретным релизом. Не анализируется юридическая достаточность лицензий и не проверяется истинность утверждений подписантов.

## Этап A — материалы и доказательства владельца

1. Сформировать приватный каталог из четырёх оригинальных финальных кандидатов MP4 и четырёх фактических WebVTT по инструкции V28. Не публиковать их в GitHub, чате или на общем URL.
2. Запустить V29 для получения первичного реестра SHA-256. Затем **повторно** запустить V29 с `--pinned-plan` на первоначальный V28-манифест. Без закрепления тех же восьми файлов V30 не принимает выпуск.
3. Включить в закрытый каталог прав реальные PDF-договоры/лицензии и реестр использования `--rights-usage`. V25 сверяет только байты PDF, а содержимое должен отдельно оценить компетентный юрист. V29 должен подтвердить четыре реальных MP4, четыре локальных HTTP-проверки, покрытие всех документов и отсутствие дополнительных технических блокеров.
4. Загрузить в V30 только конечный `V29_OWNER_PREFLIGHT_NO_GO.json` из проверенного второго прогона. Отчёт V29 сознательно содержит `result: NO_GO`.

## Этап B — восемь независимых ролей

Роли берутся без переименования из `EXTERNAL_GATES` в `scripts/osa-cinema-v27-release-board.mjs`:

- Компетентный юрист, проверяющий коммерческие права;
- Независимый проверяющий действительный русский и английский языки озвучки;
- Режиссёр/звукорежиссёр, утверждающие обе финальные звуковые дорожки и монтаж;
- Редактор, сверяющий действительные WebVTT против звуковых мастеров;
- Инженер, проверяющий реальную HTTPS-видеодоставку;
- Независимый QA-специалист с испытаниями на физических Android/iOS и ПК;
- Издатель, дающий письменное разрешение для точных файлов;
- Инженер релиза, проводящий production rollback и наблюдение после выпуска.

Каждая роль должна иметь **собственную независимую пару Ed25519-ключей**. Закрытый ключ остаётся у подписанта и НИКОГДА не помещается в GitHub, чат, реестр или ZIP. Публичный ключ добавляется владельцем в приватный доверенный реестр. V30 запрещает повторное применение одного и того же ключа в нескольких ролях.

## Этап C — фиксация доверенных ключей

Формат файла `PRIVATE_TRUSTED_SIGNERS.json`:

```json
{
  "schemaVersion": 1,
  "project": "OSA CINEMA",
  "signers": [
    {"gate":"<ТОЧНЫЙ_ИЗ_EXTERNAL_GATES>","keyId":"legal-review-key-1","publicKeyPem":"-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n"}
  ]
}
```

*Это иллюстрация структуры, а не действительный реестр: должны быть ровно восемь уникальных ролей и восемь ключей.* Уполномоченный владелец фиксирует SHA-256 **байтов** файла `PRIVATE_TRUSTED_SIGNERS.json` вне этой папки, например в бумажном журнале или защищённом корпоративном канале. Пользователь должен вручную сверить личности и публичные ключи с действительными подписантами; сама программа не проверяет их юридические полномочия.

## Этап D — подпись точного выпуска

Получить отпечаток выпуска, используя реальный V29-отчёт:

```bash
node --input-type=module -e "import {readFileSync} from 'node:fs'; import {releaseFingerprint} from './scripts/osa-cinema-v30-external-attestations.mjs'; console.log(releaseFingerprint(JSON.parse(readFileSync(process.argv[1], 'utf8'))))" "PRIVATE_REPORTS/RUN-2/V29_OWNER_PREFLIGHT_NO_GO.json"
```

Каждый подписант составляет **своё** unsigned JSON-заявление (без поля `signature`) с полями: `schemaVersion` = `1`, `project` = `OSA CINEMA`, `releaseFingerprint` = полученный SHA-256, `gate` = ровно назначенная роль, `keyId`, `evidenceFile` (PDF в закрытом каталоге), `evidenceSha256` (реальный SHA-256 PDF), `decision` = `approved`, `signedAt` и `expiresAt` в ISO UTC с миллисекундами (например `2026-10-25T12:00:00.000Z`). Требуется ровно один PDF на роль, имена имеют вид `approval_1.pdf` и т. п. Подписывать нужно **после** действительной редакторской, правовой и production-проверки, а не ради заполнения чек-листа.

Подписант создаёт подпись **на своём компьютере**:

```bash
node scripts/osa-cinema-v30-sign-approval.mjs --statement PRIVATE_UNSIGNED/approval_1.json --private-key PRIVATE_KEYS/legal_ed25519.pem --out PRIVATE_SIGNED/approval_1.json
```

Все восемь подписанных объектов собираются владельцем в файл `PRIVATE_APPROVALS.json`:

```json
{"schemaVersion":1,"project":"OSA CINEMA","approvals":["ЗДЕСЬ_ВОСЕМЬ_ОБЪЕКТОВ_С_ПОДПИСЯМИ_НЕ_СТРОКИ"]}
```

Подменять PDF, подпись, роль, ключ, дату или хотя бы один SHA-256 после подписи нельзя. Для нового монтажа создаётся новый релизный отпечаток и **все подписи оформляются заново**.

## Этап E — одна приватная команда проверки

```bash
node scripts/osa-cinema-v30-external-attestations.mjs --preflight PRIVATE_REPORTS/RUN-2/V29_OWNER_PREFLIGHT_NO_GO.json --registry PRIVATE_TRUSTED_SIGNERS.json --registry-sha256 <ЗАРАНЕЕ_ЗАКРЕПЛЕННЫЙ_SHA256_РЕЕСТРА> --attestations PRIVATE_APPROVALS.json --evidence-dir PRIVATE_SIGNOFF_PDFS --out PRIVATE_REPORTS/V30_EXTERNAL_SIGNATURES.json
```

Возможные результаты:

- `EXTERNAL_ATTESTATIONS_HOLD` — неполный или некорректный набор подписей и документов, остаётся NO-GO;
- `ALL_EIGHT_SIGNATURES_CRYPTOGRAPHICALLY_VERIFIED_PRIVATE_ONLY` — **только** все восемь утверждений криптографически связаны с конкретными файлами и документами. Это не означает, что договоры действительны, устройства реально испытаны или издатель обладает полномочиями.

**Даже второй статус не меняет** `publicFilmPublicationAuthorized=false`, `paidCheckoutEnabled=false` и `decision=NO_GO_UNTIL_INDEPENDENT_FINAL_HUMAN_AND_PRODUCTION_RELEASE`. Только после отдельной проверки реальных законных прав и production-инфраструктуры уполномоченный издатель может принять самостоятельное решение GO и разрешить отдельный PR на публичные адреса фильмов и на оплату. V30 не публикует видео, не касается `src/osaMediaCatalog.ts`, не меняет SSH и ничего не отправляет в интернет.

## Воспроизводимые проверки и безопасность

```bash
node --test scripts/osa-cinema-v30-external-attestations.test.mjs
node --check scripts/osa-cinema-v30-external-attestations.mjs
node --check scripts/osa-cinema-v30-sign-approval.mjs
```

Тесты генерируют **только синтетические** ключи и поддельные учебные PDF-байты, проверяют неправильную подпись, другое видео, изменение документа, символические ссылки, дублирующиеся роли/ключи, просроченные утверждения и запрет ложного GO. Ни ключи, ни персональные документы, ни коммерческие фильмы не должны попадать в тестовые артефакты. Технический SHA-256 сам по себе не заменяет правовую экспертизу, независимую редакторскую приёмку и реальное развёртывание.
