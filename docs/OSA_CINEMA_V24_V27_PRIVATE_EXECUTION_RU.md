# OSA CINEMA V24–V27 — полноценный технический контур до релизного решения

Дата: 25.10.2026. Работа выполнена **без публикации приватных видео**, без хранения лицензионных договоров в GitHub и без изменений платного checkout. Текущая публичная интерактивная версия V15 не заменяется.

## 1. Что входит в техническую реализацию

- **V24:** реальная проверка четырёх отдельных видео MP4 и четырёх действительных WebVTT, соответствия V16-исходникам и указанным SHA-256, проверка FFprobe длительности, H.264, AAC, размеров, полное декодирование FFmpeg, проверка времени/читаемости субтитров. Символические ссылки, неверный размер, подмена, повторение имён, невалидные таймкоды и недостающие редакции блокируют приёмку. Успех означает ТОЛЬКО `TECHNICAL_CANDIDATE_READY_NOT_LICENSED`.
- **V25:** связь каждого фактически использованного источника с каждой редакцией финального фильма; проверка 4/4 идентичностей исходников, 4/4 зависимостей и локальных PDF-кандидатов документального подтверждения прав (байты, SHA-256, отсутствие симлинков). Программа не понимает условия лицензий: даже идеально заполненная папка означает `DOCUMENT_BYTES_COMPLETE_LEGAL_HOLD`, **не** юридическое разрешение.
- **V26:** реальная проверка приватного HTTP-плеера на строго локальном адресе `127.0.0.1`: отказ без сессии, ответ HEAD `200`, корректный `video/mp4`, `Accept-Ranges`, GET `206`, точные первые/последние байты мастер-файла, неверный диапазон `416`. Не делает запросов к публичным хостам; производственная HTTPS-проверка и физические телефоны остаются отдельной процедурой.
- **V27:** сводный протокол с контрольными SHA доказательств, индивидуальными блокерами по 4 фильмам, 8 внешними разрешениями и безусловным `NO_GO` до реального подписанного решения издателя. Приватная автономная HTML-панель открывает JSON на ПК без сетевых запросов, отображает состояние и экспортирует несекретный краткий отчёт.

## 2. Нужные приватные входные материалы

Папка `PRIVATE_ROOT/` на компьютере владельца:

```
PRIVATE_ROOT/
  masters/        # финальные четыре MP4 с точными SHA
  captions/       # четыре прослушанных и синхронизированных WebVTT
  rights/         # реальные PDF-основания прав на каждый фактический источник
```

Отдельно от `PRIVATE_ROOT` хранятся **частные** `final-candidates.json` и `used-source-rights.json`.

Схема `final-candidates.json`: `schemaVersion:1`, `project:"OSA CINEMA"`, `publicationAuthorized:false`, `commercialRightsCleared:false`, `assets` — ровно 4 объекта. Каждый содержит:

- `id`: существующий V16 `osa-v15-trailer-ru`, `osa-v15-trailer-en`, `osa-v15-directors-ru`, `osa-v15-directors-en`;
- `locale`: `ru` или `en`; `edition`: `trailer-workprint` или `directors-workprint`;
- `sourceSha256`: SHA соответствующего V16-исходника, **не придумывать**;
- `masterName`, `captionName`: имена реальных файлов без путей;
- `masterSha256`, `captionSha256`: реальные рассчитанные SHA-256;
- `masterBytes`, `width`, `height`, `durationSeconds`: реальное измерение;
- `audioLanguageClaim`: предполагаемый язык речи, совпадающий с `locale`. **Надпись не доказывает фактический язык**.

Схема `used-source-rights.json`: `schemaVersion:1`, `project:"OSA CINEMA"`, `releaseAuthorized:false`, `editions` (4 записи: `finalId`, `finalSha256`, `sourceIds:[...]`), `sources` (каждый фактически использованный видео/музыкальный/голосовой/графический источник). Поля источника: `id`, `type` (`video`, `photograph`, `music`, `voice`, `graphics`, `logo`, `stock`, `ai-generated`, `other`), `sourceSha256`, `evidenceFile`, `evidenceSha256`, `commercialRightsApproved:false`, `evidenceHumanReviewed:false`. В записях нет имён людей, договоров, юридического заключения и чужих персональных данных.

## 3. Команды для независимой технической приёмки

Из корня GitHub-репозитория:

```bash
node scripts/osa-cinema-v24-final-master-qc.mjs --root /PRIVATE_ROOT --plan /PRIVATE/final-candidates.json --report /PRIVATE/reports/v24.json --strict-technical
node scripts/osa-cinema-v25-rights-evidence.mjs --root /PRIVATE_ROOT --usage /PRIVATE/used-source-rights.json --masters /PRIVATE/final-candidates.json --report /PRIVATE/reports/v25.json
```

Локальный защищённый просмотр должен быть поднят инструментом V21 для того же проверенного MP4. Тест V26 выполняется только на `http://127.0.0.1:PORT/media`; cookie передаётся через окружение **не печатать**:

```bash
node scripts/osa-cinema-v26-loopback-delivery-qc.mjs --url http://127.0.0.1:PORT/media --source /PRIVATE_ROOT/masters/NAME.mp4 --sha256 ACTUAL_64_HEX --report /PRIVATE/reports/v26-ru-full.json --strict
```

Нужно **четыре** отдельных V26 протокола, один на точный SHA каждой редакции. Затем передайте JSON-массив четырёх протоколов в V27:

```bash
node scripts/osa-cinema-v27-release-board.mjs --v24 /PRIVATE/reports/v24.json --v25 /PRIVATE/reports/v25.json --v26 /PRIVATE/reports/v26-all.json --out /PRIVATE/reports/v27.json --strict-publish
```

`--strict-publish` ожидаемо возвращает отказ. Это защита от ошибочного публичного выпуска, а не ошибка программы. Откройте `tools/osa-cinema-v27-private-release-board.html` двойным щелчком и выберите `v27.json`.

**Важно:** пока реальные финальные медиа/субтитры/лицензии не предоставлены и юридически не утверждены, нельзя корректно создать эти приватные отчёты для настоящего фильма. В GitHub CI используются *только синтетические тестовые видео и документы*, без приватных владельческих MP4.

## 4. Незаменимые внешние критерии V27

1. Независимое юридическое заключение по коммерческим правам на **каждый фактически используемый** материал.
2. Прослушанная и подтверждённая фактическая речь RU/EN на всём временном диапазоне.
3. Подпись режиссёра и звукорежиссёра на точных финальных SHA.
4. Человеческая проверка RU/EN субтитров на правильность речи, тайминга и экране телефона.
5. Реальная HTTPS-доставка только разрешённых мастер-файлов; MIME, Range, безопасность и SHA доказаны.
6. Независимые Chrome/Android и Safari/iPhone тесты на настоящих устройствах (не имитировать приёмку скриншотом).
7. Отдельная подпись издателя на полный релизный комплект с SHA, датой и условиями.
8. Доказанный rollback, мониторинг срабатывания и пострелизный аудит.

Без любого из восьми пунктов результат **NO-GO**. Даже после них официальный release/deploy выполняется отдельной управляемой процедурой, а не запуском этой CLI или редактированием JSON.
