# Изолированный кабинет получателя

Работает в полном серверном комплекте на `/deliveries`. Платежи, внешняя рассылка и публичный сервис не подключены. Этот кабинет отделён от внутреннего проекта и от прежней передачи участнику проекта.

## Создание

1. Создайте выпуск Studio, пройдите структурные проверки и получите положительный разбор другого редактора.
2. В контракте включите Studio и Business. Получателю нужен зарегистрированный аккаунт на этом же сервере. Добавлять его в участники проекта не требуется.
3. Откройте `/workspace` → проект → «Кабинет получателя». Выберите выпуск, укажите логин, отдельное название, описание и инструкцию для получателя.
4. Проверьте передаваемый HTML или внешнюю ссылку. Сгенерированный HTML содержит цель, аудиторию, задачи и критерии исходного снимка. Подтвердите состав материалов явно и создайте передачу.
5. Получатель самостоятельно входит в `/deliveries` или открывает адрес конкретной передачи. Письма, приглашения и публичные ссылки без авторизации не создаются. Знание адреса не даёт доступа другому аккаунту.

Нельзя передать выпуск без последнего положительного разбора, без явного подтверждения состава или с повреждённым HTML. Одному аккаунту нельзя создать вторую действующую передачу того же выпуска. После отзыва можно создать новую запись. Максимум — 100 записей на проект.

## Данные и права

Пакет содержит только отдельные название, описание, инструкцию, исходную версию, копию выбранного HTML с SHA-256 либо внешнюю ссылку и собственную историю обсуждения. Сервер не копирует полный снимок проекта, финансовые записи, источники, учебные практики, решения, внутренние разборы, идентификатор проекта или токены. Текст выбранного HTML передаётся целиком по явному разрешению отправителя; автоматически удалить из него частные формулировки сервер не может.

Содержимое пакета фиксируется при создании. Поздние изменения проекта или исходного HTML не переписывают уже переданный файл. Сервер сверяет SHA-256 копии при чтении. Это проверка байтов, не сертификат качества. Предпросмотр ограничен iframe sandbox без разрешения скриптов. Внешняя ссылка не проверена сервером и может со временем изменить содержимое.

Получатель не становится участником проекта: внутренние API проекта, его экспорт, чужие передачи и переписка остаются недоступными. Сам факт роли наблюдателя в проекте тоже не открывает изолированные передачи. Внутренние материалы и переписку по этой передаче могут читать только получатель и действующие редакторы/владелец проекта.

Полный экспорт проекта содержит эти передачи только для редактора/владельца. Наблюдатель получает пустой раздел. В том числе поддерживается экспорт отозванной записи, которую другой редактор ранее адресовал самому владельцу проекта.

## Получение и поддержка

Только получатель подтверждает получение материалов. Подтверждение не является оплатой, покупкой или дополнительной приёмкой качества. Ответ API не выдаёт получателю объект внутреннего проекта.

Первое сообщение открывает обсуждение. Команда может взять его в работу и предложить решение; получатель или команда могут закрыть предложенное решение и повторно открыть обсуждение. Закрытое обсуждение нельзя дополнять без открытия. История неизменяемая: сообщения и смены статуса добавляются отдельными записями. Вместо внутренних имён сотрудников используются подписи «Вы», «Получатель» и «Команда проекта».

На передачу предусмотрено до 50 сообщений и 100 общих записей истории. Сообщение — 10–4000 символов; основание статуса/отзыва — 10–2000. При конфликте версии текст остаётся на экране. Обновите передачу, прочитайте изменения и явно подтвердите использование сохранённого текста для новой версии; автоматического переноса на новую версию нет.

## Отзыв и выключение модуля

Редактор проекта может отозвать передачу с пояснением. Получатель после этого не видит пакет в списке, не читает его и не повторяет старые запросы даже с прежним ключом. Команда сохраняет историю. Отключение Business временно закрывает доступ получателю; включение снова открывает неотозванные записи.

Отзыв роли редактора закрывает его служебный доступ. Отзыв не удаляет ранее скачанные файлы и не меняет внешнюю ссылку: её содержимое контролирует владелец внешнего ресурса. Чтобы прекратить дальнейший доступ, отзывайте передачу, а не только внутреннюю роль — получатель может вообще не иметь такой роли.

## Надёжность и проверка

У каждой передачи отдельная серверная версия. Действие, история и ключ операции записываются одной транзакцией. Два одновременных подтверждения дают один успех и один конфликт; повтор того же ключа не добавляет запись. После отзыва проверка доступа выполняется заново до возврата старого ответа.

Незавершённый запрос сохраняется в сессии вкладки вместе с текстом для повтора и принадлежит конкретному аккаунту. Пароли и резервные коды в этот журнал не попадают. При возвращении из истории с несохранённым текстом отправка блокируется до проверки аккаунта; смена аккаунта очищает текст и выбранный пакет. Данные можно скачать в JSON, они входят в закрытую копию SQLite. Реальная браузерная приёмка этих состояний пока не выполнена.

94 HTTP/SQLite теста включают 82 прежних регрессии и 12 сценариев кабинета: отсутствие членства, запрет внутренних API, редактирование состава, согласие и положительный разбор, чужой аккаунт/наблюдатель, повтор и отзыв, гонка, поддержка, копия HTML, отключение Business, экспорт и восстановление. Проверка полного комплекта отдельно выполняет создание изолированной передачи и подтверждение из аккаунта получателя. Это не независимый аудит безопасности и не проверка реальных покупателей.
