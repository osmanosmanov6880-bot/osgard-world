# INHERIT R3 — реальный пилот, удержание и готовность к монетизации

**Состояние:** инструкция по использованию реализованного функционала. Никаких реальных D1/D7, платёжной конверсии, CAC, LTV и дохода она не подтверждает без добровольных данных.

## 1. Что включено в R3

- Первая игровая сессия: три действия (выбрать → оставить след → передать поколение), с явным пропуском и без изменённых игровых правил.
- Добровольная исследовательская панель на русском, английском и упрощённом китайском в «Наследии».
- Согласие **по умолчанию выключено**. Без согласия новый журнал исследования не создаётся.
- После согласия сохраняются только сессии, типовые игровые действия, оценки 1–5 и выбранная *гипотетическая* цена чисто косметического набора; серверных вызовов нет.
- Случайный код участника создаётся только после согласия и используется для исключения повторных экспортов. Экспорт и удаление выполняются вручную. Не собираются координаты объектов, имена игроков, текст сообщений или IP-адреса.
- D1 и D7 определяются по **календарным дням UTC после даты согласия**: отдельно считаются участники, уже достигшие соответствующего дня, и участники, вернувшиеся именно в этот день. Недостигшие срока не записываются как не вернувшиеся.
- Коммерческое предложение Founder Pass **не списывает деньги**. Выбор цены $0/$1.99/$4.99/$7.99 — лишь предпочтение в опросе.

**Оговорка:** в INHERIT существует отдельная ранее внедрённая локальная история игровых событий `inherit-analytics-v1`. Новый журнал не собирает, не экспортирует автоматически и не отправляет её. Полное упразднение всей старой локальной аналитики требует отдельной проверки совместимости.

## 2. Как протестировать

1. Открыть `https://osgard.world/games/inherit/` в режиме локального мира с пустым сохранением.
2. Следовать трём шагам обучающей панели; игровой бюджет реально уменьшается при размещении и восстанавливается при подтверждённой передаче. В режиме аккаунта без разрешения панель не подменяет права.
3. Открыть «Наследие» → «Исследование». До согласия ключ `inherit:pilot-research:v1` отсутствует; кнопка включения неактивна.
4. Отметить согласие и включить исследование. Сделать несколько ходов и отправить поколение; проверить счётчики сессий, следов и наблюдаемых переходов.
5. Заполнить стандартизованный опрос: понятность, намерение вернуться, значимость передачи (1–5), предпочтение и цену. **Не использовать данные как реальные покупки.**
6. Проверить переключение языков RU / EN / 中文, мобильную клавиатуру и отсутствие горизонтального переполнения.
7. Нажать экспорт JSON. Он содержит случайный идентификатор, даты и разрешённые типы событий, но не текст, географию, аккаунты и координаты.
8. Нажать «Удалить все данные». Ключ исследования исчезнет; обычный игровой мир и прежние сохранения останутся.
9. При недоступном LocalStorage исследование не включается и не заявляет о сохранении; сама игра продолжает работать.

## 3. Обработка добровольных отчётов

Участник должен **самостоятельно** передать созданный файл организатору по отдельному безопасному каналу, после информирования о цели и сроке хранения. В игре нет кнопки отправки отчёта.

Локально в копии репозитория:

```sh
mkdir -p pilot-exports pilot-report
# Только добровольно полученные JSON-файлы складываются в pilot-exports/
node scripts/inherit-pilot-report.mjs --input pilot-exports --as-of 2026-11-01 --out pilot-report
```

Получаются `inherit-pilot-scorecard.json` и `inherit-pilot-scorecard.md` с **агрегатами без кодов участников**. Исходные файлы хранить в закрытом каталоге, не добавлять в GitHub, не загружать в публичные инструменты. Рекомендуемый процесс — доступ только команде исследования, удаление исходников по заранее объявленному сроку (например, через 30 дней после окончания пилота), отдельный порядок отзыва ранее переданных файлов. Удаление из браузера участника не удаляет файл, который он уже кому-то передал.

Повторные экспорты с одинаковым кодом участника учитываются один раз: используется наиболее полный валидный журнал. Неверные файлы отклоняются. Перед публикацией результатов требуется отдельно оговаривать размер и смещение добровольной выборки.

## 4. Метрики и ограничения

| Метрика | Определение | Что нельзя заключать |
|---|---|---|
| First trace | Доля добровольных экспортов с событием first_trace_placed после согласия | Конверсия всех посетителей сайта |
| Generation advanced | Наблюдаемое увеличение номера поколения на устройстве | Гарантированная серверная передача или реальная многопользовательская игра |
| D1 | Вернувшиеся ровно на следующий календарный день / участники, достигшие срока | Общая D1 всего продукта |
| D7 | Вернувшиеся ровно в седьмой календарный день / участники, достигшие срока | MAU, LTV или органическая популярность |
| Survey clarity | Средний балл понятности 1–5 по ответившим | Объективная оценка всей аудитории |
| Price intention | Ответ на вопрос о максимальной гипотетической цене | Оплата, предварительный заказ, конверсия в покупку |

Для фактического MAU, конверсии продаж, маркетинговых затрат и CAC нужна **иная**, отдельная инфраструктура, учитывающая согласие, приватность и правовые основания обработки данных. В R3 такой серверной аналитики и платёжного провайдера нет.

## 5. 90-дневная коммерческая валидация

**Дни 1–14.** Проверить публикацию и доступность (desktop/mobile/оффлайн), провести 10–15 наблюдений за первым сеансом, исправить затруднения, не меняя основную механику без данных.

**Дни 15–30.** Пригласить через сообщества и личные приглашения 100–300 добровольцев при наличии ресурсов. Запросить согласие только после объяснения, что собирается и зачем. Протестировать понятность передачи поколения.

**Дни 31–60.** Добровольно собирать экспорты, проверять D1/D7, рассчитывать воронку, отдельно получать интервью о том, ради чего люди возвращаются. Не выдавать результаты экспортировавших за всю аудиторию.

**Дни 61–90.** При подтверждённом удержании и реальной готовности платить — сформировать отдельный дизайн платёжного шлюза, налогов, возвратов, учёта лицензий на косметику и защиты от двойных списаний. Только после отдельного решения владельца и юридической проверки подключать реальные платежи. При слабом удержании — дорабатывать игровой цикл.

### Критерии решения (гипотезы, не фактические результаты)

- Первый след создаётся без подсказок большинством участников пилота; трудности фиксируются в живых наблюдениях.
- D7 не оценивается до истечения семи дней, а объём и смещение добровольной выборки всегда указываются.
- Готовность платить нельзя считать доказанной одним опросом: потребуются реальные контролируемые предложения и безопасная платёжная инфраструктура.
- Решение **INVEST / VALIDATE / PIVOT / STOP** принимается после реальных данных, а не на основании 126+ зелёных инженерных тестов.

## 6. QA-команды

```sh
npm run qa:inherit-research
npm run qa:inherit-world-cycle
npm run qa:inherit-i18n
npm run qa:inherit-account
npm run qa:inherit-handoff
npm run build
```

Browser QA: `scripts/ecosystem-browser.spec.mjs` в CI на desktop и mobile. Production: только через проверяемый `deploy-frontend.yml` с механизмом отката.

**Честная граница завершения:** программная часть пилота и его отчётность реализуемы в одном релизе. Фактическое исследование рынка, семидневное удержание и платёжная выручка зависят от настоящих пользователей и времени.
