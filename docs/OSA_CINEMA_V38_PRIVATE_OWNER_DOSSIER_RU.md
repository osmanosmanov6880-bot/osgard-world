# OSA CINEMA V38 — единая закрытая техническая приёмка, без публичной премьеры

Дата: 25 октября 2026. **Записанный фильм и коммерческий выпуск: NO-GO.**

## Что делает V38

Одна команда вызывает действующие модули:

1. **V35** — проверка неизменности подлинных Git blob-хешей V16, V18 и V20, не синтетических QA-заглушек.
2. **V36** — проверка закрытого набора отчётов V29 и внутренних SHA-256-связей.
3. **V37** — потоковая проверка *реальных локальных байтов* четырёх MP4 и четырёх WebVTT по V28 и первичной WebVTT-разметки.
4. **V30 — только если есть утверждённые исходные доказательства** — проверка заявлений, восьми независимых Ed25519-подписей и PDF по их SHA-256 с **внешне доверенным** отпечатком реестра публичных ключей.
5. После проверки медиа и подписей **повторно** перечитываются исходные V35/V36 документы; подмена между проходами вызывает отказ.

Никакие личные материалы, видео, субтитры, документы о правах или секретные ключи не отправляются на сервер. Скрипт работает только локально, ничего не публикует и не пишет на диск. Итоговый JSON выводится в консоль и не содержит ключей или медиа-байтов.

## Windows: проверка без внешних подписей

Предварительно установите Node.js 22+, распакуйте/получите актуальный GitHub checkout OSA CINEMA и выполните в PowerShell из корня репозитория:

```powershell
node .\scripts\osa-cinema-v38-owner-release-dossier.mjs --repo-root "C:\OSA\osgard-world" --receipts-dir "D:\OSA_PRIVATE_REPORTS" --masters-dir "D:\OSA_PRIVATE\film\masters" --captions-dir "D:\OSA_PRIVATE\film\captions"
```

Папки фильма и отчётов должны существовать, быть на локальном носителе, находиться **вне** репозитория и содержать настоящие материалы конкретного владельца. Требуются четыре финальных MP4, четыре WebVTT и отчёты настоящего локального прогона V29. На Linux/macOS рабочие папки: `0700`, отдельные файлы: `0600`. Сетевые пути и символические ссылки не допускаются.

Если независимые согласования действительно собраны, добавьте к этой команде **все четыре аргумента**: `--registry <путь-реестра-публичных-ключей> --registry-sha256 <независимо полученный SHA-256 самого JSON> --attestations <путь-к-подписанным-заявлениям> --evidence-dir <путь-к-PDF>`. Нельзя получать доверенный SHA-256 из того же недоверенного архива с заявлением. **Никогда не добавляйте секретные ключи или PDF в GitHub.**

## Коды завершения

- `0` — **только** целостность приватного технического комплекта подтверждена; поле `releaseDecision: NO_GO` остаётся неизменным.
- `1` — хотя бы один обязательный технический контроль отверг доказательства; ничего не считается проверенным.

V38 никогда не устанавливает `publicationAuthorized`, `rightsCleared`, `paidCheckoutEnabled` или флаг производства в `true`. Криптографическая подпись доказывает контроль ключа над заявлением, но **не** компетентность подписанта, достоверность содержания PDF, коммерческие права или человеческую приёмку. Даже восемь технически подлинных подписей оставляют все независимые правовые, художественные и production-проверки открытыми.

## Проверки

- Негативные сценарии: подмена V16/V18/V20, нестыковка отчётов V29, изменение MP4/VTT, неверный внешний отпечаток публичного реестра, поддельная Ed25519-подпись, пропущенная роль, попытки установить фиктивное `GO`, неизвестные CLI-флаги, неполные аргументы.
- Интеграционные тесты V29 + FFmpeg + FFprobe + V30 используют **только синтетические** MP4, WebVTT, PDF и одноразовые тестовые ключи; они не подменяют реальные подтверждения владельца.
- Тесты GitHub Actions запускаются на Ubuntu, macOS и Windows; реальные закрытые материалы в CI не включены.

## Что ещё потребуется для законной премьеры

Четыре действительно утверждённых MP4 и четыре WebVTT; независимое человеческое прослушивание RU/EN, финальный монтаж и аудиоприёмка; подтверждённые коммерческие права на звук, музыку, изображения, голоса и графику; проверка полномочий подписантов и юридическая оценка документов; реальный HTTPS/браузеры/устройства, откат и мониторинг; отдельное издательское разрешение на точные SHA-256 релизных файлов. Эти условия **не могут** быть автоматически закрыты данным скриптом.
