# INHERIT R5 — достоверность наблюдений D1/D7/D30 и окончательная готовность пилота

**Дата:** 21 октября 2026 г.  
**Затронутые функции:** анализ *только добровольно предоставленных* локальных экспортов INHERIT.  
**Не затронуты:** игровой мир, сохранения, онлайн-права, платежи, серверный API, сторонние игры.

## Исправленная проблема

В R3/R4 за числитель D1/D7 брались зафиксированные повторные сессии, но знаменателем были все добровольцы, для которых дата D1/D7 уже прошла на момент открытия отчёта. Если отчёт был экспортирован на D0 и открыт организатором на D7, на устройстве **не было данных**, позволяющих утверждать, что человек не вернулся. Однако прежняя логика могла записать такого участника в «не вернулся». Это не доказанный невозврат, а недостаток наблюдений.

R5 вводит явную классификацию для каждого календарного дня после согласия: **D1, D7 и D30**.

| Тип данных | Обязательное доказательство |
|---|---|
| Зафиксированный возврат | В валидном экспортированном журнале есть \`session_opened\` ровно в нужный UTC-день |
| Нет наблюдаемой сессии при полном охвате | В журнале нет события нужного дня; экспорт сделан **после завершения** этого UTC-дня; журнал непрерывный и без удаления старых событий |
| Недостаточно данных | Экспорт слишком ранний, журнал был обрезан после переполнения, либо невозможно доказать наблюдение всего нужного периода |
| Срок ещё не наступил | На выбранную дату \`as-of\` нужный день не начался |

**Важно:** «Нет наблюдаемой сессии» не значит «человек точно никогда не возвращался»: исследование относится только к этому браузеру и согласованному периоду, а не ко всем устройствам и аккаунтам.

### Формула доли

\`\`\`
доступный охват = наблюдаемые возвраты + доказанное отсутствие локальной сессии
доля возвратов при охвате = наблюдаемые возвраты / доступный охват
полнота наблюдений = доступный охват / достигшие срока
доля с зафиксированным возвратом = наблюдаемые возвраты / достигшие срока
\`\`\`

Если \`доступный охват = 0\`, в интерфейсе стоит **«н/д»**, а не 0%. Если есть участники с недостатком данных, они перечислены отдельно; их нельзя автоматически засчитывать как невозвраты.

И даже \`100%\` при полном охвате не доказывает D7 всей аудитории: экспорты передают только согласившиеся и заинтересованные люди. Это может создавать сильную ошибку отбора. Такие цифры — описательная статистика добровольных экспортов, **не измерение общей конверсии или аудитории**.

### Псевдонимные экспортные файлы

- Коды участников используются только временно для исключения повторных экспортов. Итоговый JSON/Markdown **не содержит их**.
- Обязательно валидируется дата \`generatedAt\`; экспорт, датированный до согласия или до включённых в него событий, отклоняется.
- Для одного участника выбирается наиболее полный валидный журнал; при равном количестве событий — более поздний экспорт, позволяющий подтвердить более длинное окно наблюдения.
- Если журнал был ограничен 512 событиями и ранние сессии вытеснены, отсутствие события не считается подтверждённым невозвратом.
- \`as-of\` отсекает будущие события и ответы из исторического отчёта, даже если файл экспортирован позднее.
- Файлы обрабатываются только в памяти вкладки или локальной Node CLI. Встроенной загрузки на сервер нет.

## Решение о дальнейшем развитии

Новый \`evidence.status\` — диагностический флаг, а не маркетинговая оценка.

| Статус | Значение | Действие |
|---|---|---|
| \`NO_EXPORTS\` | Нет валидных добровольных экспортов | Не делаем выводов |
| \`AWAIT_D7\` | Для выборки ещё не наступил седьмой день | Ждём, не объявляем D7 |
| \`MISSING_FOLLOWUP\` | У части людей не подтверждена продолжительность наблюдения | Просим только добровольные дополнительные экспорты, не изобретаем нули |
| \`SMALL_VOLUNTARY_SAMPLE\` | Мало случаев с пригодным D7-охватом | Увеличиваем выборку, проводим интервью |
| \`DESCRIPTIVE_ONLY\` | Есть больше наблюдений | Описываем именно выборку экспортировавших, не заявляем product-market fit |

\`readyForPayments\` всегда **false**: никакая анкета или тестовая метрика не разрешает включать платежи автоматически.

### 90-дневный план — что код не может заменить

1. **Дни 1–14:** реально пригласить 10–15 людей на наблюдение за первой игровой сессией, фиксировать с отдельным согласием проблемы первого хода и передачи поколения.
2. **Дни 15–30:** разослать приглашения в разрешённых сообществах или подключить свои соцсети. Цель 100–300 добровольных приглашений — это план, не фактически набранная аудитория.
3. **Дни 31–60:** принимать добровольные экспорты по отдельному согласованному каналу, считать охват и D1/D7/D30. Запрашивать повторный экспорт можно **только добровольно** — не заставлять людей возвращаться ради статистики.
4. **Дни 61–90:** описать качественные интервью и сегменты, определить INVEST / VALIDATE / PIVOT / STOP. При интересе к оформлению проверить реальную готовность платить отдельно от ответов анкеты.
5. Перед любыми оплатами: законный продавец, налоговые и потребительские условия, платежный провайдер, возвраты, подтверждение/отмена лицензий и юридическая проверка. Только после явного решения владельца компании может быть активирован платёжный контур. В R5 он отключён.

**Нельзя за один программный проход честно завершить прошедший D30, публикации в неподключённые аккаунты, реальные интервью, подтверждённые покупки, LTV или прибыль.** Синтетические QA-файлы не считаются реальными участниками.

## Проверки перед выпуском

\`\`\`sh
npm run qa:inherit-research
npm run qa:inherit-pilot-launch
npm run qa:inherit-followup
npm run qa:inherit-world-cycle
npm run build
\`\`\`

В \`qa:inherit-followup\` проверяется: ранний экспорт, экспорт внутри целевого дня, отрицательный результат с достаточным окном, настоящий D30, дубли, переполненный журнал, повреждённые даты, исторические фильтры, отсутствие идентификаторов, отсутствие ложного разрешения платежей.

Chromium E2E дополнительно проверяет визуальные колонки охвата и отсутствие сетевой отправки. После выпуска \`deploy-frontend.yml\` заново выполняет QA, активирует только проверенный архив и побайтно сравнивает опубликованные файлы исследования с GitHub-версией релиза.

Для пользовательских данных действует уже установленное правило: отдельное согласие на передачу файлов организатору и удаление исходников по заранее установленному сроку. Стирание из браузера не удаляет копию, уже переданную другому лицу.
