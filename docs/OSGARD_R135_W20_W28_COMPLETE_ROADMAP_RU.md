# OSGARD R135 — производственная карта W20–W28

Дата исходной базы: 2026-10-25. Стартовая версия: **W19**, Godot 4.4.1,
проверенный WebGL на `https://osgard.world/games/r135-service/`. Это
интерактивная обучающая 3D-симуляция обслуживания и диагностики, **не**
реальный аппаратный контроллер и **не** подтверждённая AAA-игра.

## Непересматриваемые контракты
- Учебные механизмы: привод прежде люка, полное открытие/закрытие, безопасное
  сканирование, три независимые диагностические неисправности.
- Существующие HERO/ECO GLB + PBR исходники не заменяются сомнительными ассетами.
- Сохранения W14 (`r135_challenge_record.cfg`) и W19 обучения
  (`r135_luxury_tutorial_v1.cfg`) не очищаются при смене настроек.
- Для любого публичного изменения нужны: реальные Godot импорты, native smoke,
  проверка WebGL в ПК/мобильном Chromium, исходные скриншоты, контрольные суммы,
  независимый release pin, защищённый SSH и live HTTP smoke.
- Software Chromium SwiftShader ≠ FPS/нагрев на физическом телефоне.
  Кинематографический стиль ≠ фотореализм AAA. Никаких «100% готово» без протокола.

## W20 — Профиль игрока и настоящие настройки (первый внедряемый этап)
**Пользователь получает:** русский интерфейс по умолчанию, сохранение RU/EN,
ECO/HERO и настройки доступности без сброса курса, видимый интерактивный
экран настроек (не декоративная кнопка). Учёт `?lang=ru/en` как временного
приоритета URL, в остальных случаях восстановление предпочтений.
**Критерии:** строгая v1-схема, отклонение повреждённых и слишком широких
значений, отдельный файл профиля, минимум 44 CSS px для активных мобильных
кнопок, управление доступно на 360×780, 390×844, 932×430 и 1366×768;
старые восемь команд работают. Godot-native регрессионный тест.

## W21 — Обучение, которое объясняет причины ошибок
- Шесть глав дополняются короткими демонстрациями цели, причины, действия,
  доказательства и безопасного результата.
- Контекстный разбор каждой ошибки, безопасный повтор сценария, понятное
  завершение на ПК/тач. Независимое восстановление курса и статистики.
- Acceptance: 10 тестеров понимают причину и верное действие по каждому
  из трёх сценариев; не менее 8/10 обходятся без подсказки тестировщика.

## W22 — Игровой цикл и вариативность
- Новые задачи не сводятся к перекрашиванию маркеров. Выбор узла, диагностическая
  развилка, дополнительные признаки неисправности, последствия неверного шага.
- Честный scoring, рестарт, «лучшая попытка», возобновление после закрытия.
- Acceptance: 3 принципиально разные механики/ситуации, причинно-следственная
  симуляция, автоматизированный полный цикл игры, ручное сравнение ретеншена.

## W23 — Арт и премиальная лаборатория
- Художественный bible: индустриальный премиальный реализм, copper/cyan,
  акцент на материале и форме, без нечитаемого bloom.
- Реальные измеримые изменения: текстуры с корректными лицензиями, лоды,
  инструменты для бликов/теней, камера/свет; не 3D-макет вместо механики.
- Budget: separate ECO/HERO; fail if original GLBs modified, if render raises
  unacceptable mobile frame time, or if diagnostic target becomes unreadable.
- Честный статус: «улучшено», но не «AAA», пока независимый art review не согласован.

## W24 — Звук, анимации, доступность
- Лицензированные/свои SFX привода, люка, сканирования и результатов;
  лимит громкости, субтитры/текстовая альтернатива, настройки звука.
- Нет autoplay громкого аудио, нет потери информации при reduced motion.
- Acceptance: все интерактивные звуки отражают реальные состояния симулятора;
  тест клавиатуры, touch, screen-reader ограничений и низкого контраста.

## W25 — Настоящая мобильная приёмка
- Физический Android + iPhone, браузеры Chrome/Safari, портрет и ландшафт,
  термальная устойчивость, энергопотребление, WebGL потеря контекста.
- Сбор *фактических* p50/p95 frame time, peak RAM и ошибок на конкретных
  устройствах; без переноса SwiftShader FPS на железо.
- При проблемах: динамическое качество/ограничение DPR, диагностика GPU; ECO
  обязателен для слабых устройств.

## W26 — Интернационализация и продуктовая аналитика
- Полный аудит RU/EN длинных строк и ошибок; дополнительные языки только
  после проверки переводов и доступности.
- События обучения и отказа только с разрешения пользователя; privacy-first,
  без идентифицирующего трекинга и отправки содержимого локальных сохранений.
- Acceptance: нет «полурусских» экранов, основные задачи проверены людьми.

## W27 — Бета и качество
- Реальный пилот 20–50 пользователей, короткие наблюдаемые сессии, 3 сценария,
  устройства и повторное посещение; баги с репродукцией и приоритетом.
- Производительность и краши измерены на живом трафике с согласия,
  критические дефекты = 0 перед расширением, регрессия сохранений = 0.
- Доля завершивших обучение и повторные сессии — в отчёт, не в маркетинговое
  обещание. В зависимости от спроса либо углубить симулятор, либо изменить план.

## W28 — Production v1
- Подписанный и фиксированный архив; отложенное переключение live только после
  независимой QA и защищённого SSH, проверка точных исходных WASM/PCK/manifest
  через HTTP; обратный путь к последней безопасной версии.
- Учебная и эксплуатационная документация; отдельная юридическая маркировка
  симуляции; лицензии на ассеты, политика данных, доступность.
- Финальный протокол: игра работает с нуля на ПК и Android/iPhone, 3 кейса,
  сессия/сохранение/повтор, доказательства приемки, реальные метрики.

## Порядок
W20 → W21 → W22 → W23/W24 параллельно после заморозки механик →
W25 → W26 → W27 → W28.

**Граница текущего спринта:** реализовать и проверить W20 в ветке. W21–W28 —
этапы утверждённого технического плана, но не выдаются за написанный код или
опубликованный релиз.
