# OSGARD Core — серверный пилот

Core добавлен к существующему сайту, без изменения опубликованного сайта и GitHub. Это работающий серверный пилот, не коммерческий production-релиз.

## Быстрый запуск

1. Распакуйте полный архив `OSGARD-REDESIGN-THREE-BRANDS.zip`.
2. При установленном Python 3.10+ запустите `START-CORE-WINDOWS.bat` (Windows) или `python3 START-CORE.py`.
3. Откройте `http://127.0.0.1:4173/workspace`.
4. Создайте аккаунт. Используйте отдельный пароль: на `/account` подготовьте и активируйте резервные коды. Почтовое восстановление, MFA и администрирование пользователей ещё не реализованы.
5. Создайте проект. Задайте цель, аудиторию, бюджет, срок и критерии.
6. Разрешите модули и конкретные действия. Сохраните условия, затем примите контракт отдельным сохранением.
7. В Learning выберите практику, запишите результат на новой задаче и сохраните отметки. Гостевые отметки переносятся только по явной кнопке импорта.
8. В Studio создайте HTML-прототип или укажите внешний артефакт. Откройте «Мои файлы» для предпросмотра и скачивания. Завершите задачи, отметьте критерии, повторно примите изменённый контракт.
9. Выполните предварительную проверку. Фоновая проверка сохраняется в очереди и продолжится после перезапуска Core. Отчёт относится к конкретной версии, а не к последним несохранённым изменениям.
10. Зафиксируйте внутренний выпуск. Это запись проверки, не публикация. После него можно сохранить задачи и критерии как личный шаблон.
11. В Business подготовьте предложение, запишите реальные расходы и создайте черновик заказа. Деньги не списываются, заказ не считается оплаченным.
12. Откройте `/learning/campus` для личной практики, итоговой сдачи, разбора и расписания. Подробности в `LEARNING-PILOT.md`. Во вкладке «Результат» запишите сравнимые наблюдения с исправлениями и помощью человека. В истории проверьте версии, участников и экспорт.

Обычный `START-WINDOWS.bat` по-прежнему запускает только статический сайт. На Cloudflare Pages статический ZIP показывает интерфейс Core и понятное сообщение о неподключённом сервере; Python там не выполняется.

## Запуск из исходников

```sh
npm ci
npm run build
python3 server/core_server.py --root dist --port 4173
```

В режиме Vite `npm run dev` API не проксируется. Для полного сценария используйте собранный сайт и Core на одном адресе.

База по умолчанию: `~/.osgard-core/core.sqlite3`, вне публичной папки сайта. Можно задать `--database /absolute/private/path/core.sqlite3`. Не удаляйте её при обновлении исходников. Сервер по умолчанию слушает только loopback.

Для доступа с другого устройства нужен один постоянно работающий сервер, внешний HTTPS reverse proxy и настройка `--public-origin https://your-domain.example` без завершающего слеша. Не запускайте встроенный HTTP-сервер напрямую в публичном интернете: TLS, лимиты соединений, эксплуатация и развёртывание в этом проходе не выполнялись. Данные двух отдельных локальных серверов автоматически не объединяются.

## Данные и разрешения

- SQLite WAL — достоверное серверное состояние. Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций, отдельная случайная соль.
- Bearer-сессия на 8 часов. В SQLite хранится хеш токена. В браузере токен хранится в sessionStorage; при запрете этого хранилища сессия живёт только в памяти вкладки. Отзыв сессии через выход проверяется сервером.
- Регистрация и вход ограничены 20 попытками за 15 минут на IP текущего процесса. Это защита пилота, не распределённый anti-abuse. TLS и безопасная среда сервера обязательны для внешнего размещения.
- Владелец добавляет существующий аккаунт как редактора или наблюдателя. Приглашения и письма не отправляются. Доступ распространяется на весь проект; согласия Learning/Studio/Business не являются разделением полей между участниками.
- Проверка прав выполняется на сервере для каждого проекта, файла, истории, задания и экспорта. Отозванный редактор не может повторно получить старый ответ операции.
- Изменения содержат ожидаемую версию. При конфликте сервер возвращает 409, не затирая чужую работу. Редактор хранит несохранённые изменения до обновления; перед уходом выводится системное предупреждение браузера.
- Каждый изменяющий запрос получает уникальный ключ. Ключ и ответ записываются в одной транзакции с результатом. Повтор с тем же содержимым возвращает сохранённый результат; другое содержимое с тем же ключом отклоняется.
- Клиент сохраняет незавершённый запрос для явного повтора в текущей вкладке. Если sessionStorage заблокирован, повтор доступен только до перезагрузки. Удаление такого запроса не отменяет уже сохранённое действие.
- Фоновая очередь выполняет только чистые локальные проверки, без сетевых запросов, произвольного кода, AI и платежей. После старта сервера незавершённая проверка возвращается в очередь. Используйте один процесс Core на базу.

## Проверка и выпуск

Проверяются принятие контракта, согласие Studio, разрешение локальных проверок, наличие и отметки критериев, ссылка или созданный HTML-файл, сроки источников и бюджет. Содержимое внешних URL не загружается. Отметки критериев — утверждения пользователя, не независимые тесты. SHA-256 созданного HTML вычисляет сервер; для внешнего файла хеш вводит пользователь.

HTML-генератор использует фиксированный шаблон с экранированием текста. Предпросмотр — iframe без разрешений sandbox. Он не реализует бизнес-логику продукта. Файлы сохраняются на сервере и включаются в экспорт.

Внутренний выпуск сохраняет версию результата, файл/ссылку и отчёт. Обычное восстановление старой версии не отменяет расходы, черновики заказов, выпуски и наблюдения. Восстановление базы целиком, напротив, возвращает состояние всей системы на дату резервной копии.

## Экономика и измерения

Все суммы — целые минимальные денежные единицы: копейки/центы. Расход не может превысить принятый бюджет. После денежных записей валюта проекта фиксируется. Расходы вводит человек, списания не выполняются. Выручка равна нулю до появления подтверждённых платежей; черновики в неё не входят. Вклад = подтверждённая выручка − возвраты − введённые расходы. Категории включают вычисления, платёжные расходы, наставников и поддержку.

Скорость = сумма исходного времени / сумму основного времени с инструментом, исправлений и помощи человека. Доля успеха учитывает и неуспешные наблюдения. Размер и состав выборки показываются. 3× и 85% — цели, не доказательство превосходства. Цена программы $79 и когорты $499 остаётся гипотезой на `/learning/pricing`.

## Экспорт и резервное копирование

«Экспорт» скачивает JSON проекта, версии, журнал, созданные HTML-файлы и результаты очереди, без паролей и токенов. Гостевые браузерные данные экспортируются отдельно на `/data`. JSON содержит личные материалы проекта; храните его как собственные данные. Шаблон переносит только формулировки задач и критериев, без покупателя, источников, расходов, согласий и отметок выполнения. Независимая сертификация шаблона отсутствует.

Для согласованной копии всей SQLite-базы (в том числе во время работы сервера):

```sh
python3 CORE/core_backup.py backup /private/core.sqlite3 /private/backups/core-2026-10-16.sqlite3
```

Из исходников путь скрипта — `server/core_backup.py`. Копия создаётся в новом файле, проверяется `integrity_check`, печатается SHA-256. База содержит хеши паролей, активных сессий и резервных кодов: не кладите её в PAGES, Git, ZIP раздачи или публичное хранилище.

Восстановление: остановите сервер, выполните `core_backup.py restore backup.sqlite3 restored.sqlite3`, запустите Core с `--database` на новый файл. Существующий файл никогда не перезаписывается. Потеря действий после даты копии возможна; процедуры непрерывного восстановления и резервирования ещё не внедрены.

Лимиты пилота: 100 проектов и 100 шаблонов на владельца, 500 версий проекта, 50 HTML-файлов, 200 фоновых проверок, 500 расходов/наблюдений, 100 заказов/выпусков, 512 КиБ актуальных данных проекта. История JSON-экспорта ограничена 12 МиБ текста снимков; для большей истории нужна копия SQLite. Эти лимиты ограничивают прототип, а не подтверждают нагрузочную ёмкость.

## Проверки и остающаяся работа

`npm run qa:core-api` выполняет реальные HTTP/SQLite интеграционные сценарии во временной базе. Браузерный проход, доступность с другого физического устройства, внешнее HTTPS-развёртывание, нагрузочное тестирование, независимый аудит безопасности, реальные платежи/возвраты/выдача доступа и пилот с учениками не выполнены. Тесты не содержат платёжных или AI-вызовов.

## Учебное продолжение

Сервер дополнен модулем `core_learning.py` и каталогом `curriculum.json`. Новые таблицы создаются без удаления существующих аккаунтов и проектов. Согласие Learning требуется для учебного модуля. Личные записи, сдачи, разборы и расписание входят в полный экспорт и копию SQLite, сохраняются при восстановлении обычной версии проекта. Платёжная часть отложена.

## Сводки учебных пилотов

Добавлен модуль `core_pilot_reports.py` и таблица назначений разборов. Панель `/learning/organizer` читает только доступные проекты с разрешением Learning. Инструкция: `PILOT-ORGANIZER.md`. Новые таблицы создаются без удаления существующих данных. Назначения входят в экспорт и SQLite-копию.

## Доступ к аккаунту

Страница `/account`: собственные сессии, смена пароля, отзыв других сессий и восстановление по заранее активированным кодам. Подробности и ограничения — `ACCOUNT-ACCESS.md`.

## Приёмка выпуска Studio

Откройте `/workspace` → проект → «Приёмка». Другой редактор может разобрать каждый критерий конкретного выпуска с пояснениями. Материалы JSON содержат исходный контракт, сохранённый HTML и историю разборов. Подробности: `STUDIO-ACCEPTANCE.md`. Новый выпуск не наследует приёмку старого; внешние URL не проверяются сервером.

## Передача и поддержка

В `/workspace` → «Передача» можно зафиксировать передачу разобранного выпуска уже добавленному участнику. Получатель подтверждает получение и создаёт обращение; редактор отвечает и фиксирует решение. Новые права, письма и платежи не создаются. Личные процессы показывают происхождение исходного разбора и предварительный состав переноса. Инструкция: `DELIVERY-WORKFLOW.md`.

## Итоговая сборка и рабочий центр

Начните с `QUICK-START-RU.md`. `/workspace/overview` объединяет состояние проектов, очередь, расходы и следующий шаг. Реальное состояние исполнителя относится только к текущему процессу сервера. `FINAL-READINESS.md` описывает реализованный объём и открытые пункты. Для исходников: `npm run qa:local-release`; результат — `LOCAL-RELEASE-CHECKS.json`. Публичный запуск, браузерная приёмка и реальный пилот отдельно не выполнены.

## Ограниченный доступ получателя

Чтобы передать материалы без выдачи роли проекта, используйте «Кабинет получателя» в `/workspace`. Существующий аккаунт получателя открывает `/deliveries`, подтверждает получение и обсуждает конкретный пакет. Полный проект ему не открывается. Перед созданием явно проверяется состав HTML/ссылки. Инструкция: `CLIENT-PORTAL.md`. Платежи не подключены.

## Команды

В `/teams` создайте пространство и добавьте существующие аккаунты. Проект подключает только его владелец, одновременно имеющий права управления командой. Доступ выдаётся ко всему проекту, а не только к результату. Личные и командные роли независимы; для ограниченного пакета используйте `/deliveries`. Инструкция: `TEAMS.md`.

## Производственная конфигурация

Compose теперь включает отдельный Core API, приватный том SQLite, health-check, ограниченный контейнер и маршрут Nginx `/api/core/`. Это подготовленная конфигурация, а не подтверждение фактического запуска. Сначала проверьте `CORE-PRODUCTION.md`, TLS и обратный прокси, затем выполните резервное копирование и проверенное восстановление на целевом сервере.
