# OSA CINEMA V32 — крупный практический блок: последний метр до работы с реальными файлами

## Реализовано

V31 доказала корректность браузерного локального кабинета, но владелец должен был вручную создавать папки и вписывать длинную команду PowerShell. V32 решает именно эту проблему: простая точка входа `START_OSA_CINEMA.cmd`, эквивалент на macOS/Linux, обязательная проверка целостности исходников, подготовка закрытых каталогов, точный список восьми ожидаемых файлов, диагностический отчёт, проверка реальных кодеков и субтитров, запуск V31 без секретов в URL/аргументах.

### Архитектура

1. **Hash gate** — `osa-cinema-v32-package-integrity.mjs` сверяет байты исходного комплекта с подписанным по содержанию (но не по издателю) `CHECKSUMS.sha256`, запрещает опасные пути, ссылки и дубли.
2. **Folder gate** — `preparePrivateWorkspace` создаёт папки `masters`, `captions` и отдельную папку отчётов; не кладёт ни одного ненастоящего MP4/VTT, реестр прав или ключи.
3. **Inventory gate** — `inspectOwnerWorkspace` проверяет абсолютные пути, реальную файловую систему, восемь точных имён, пустые/лишние/опасные элементы и наличие Node, FFmpeg, FFprobe.
4. **Real media gate** — `--full` вызывает существующий V28, который самостоятельно проверяет H264/AAC через FFprobe, глубоко валидирует VTT и вычисляет SHA-256 каждого материала.
5. **Protected owner gate** — пароль считывается из терминала без эха и передаётся в `startPrivateOwnerConsole` напрямую, без ENV, URL или argv. Браузер открывает только случайный порт `127.0.0.1`. Внутри работают V29/V30, уже проверенные CI.
6. **Fail-closed** — любые недостающие или изменённые файлы останавливают дальнейший запуск. Сам диалог или тесты не помечают права/голос/премьера как «одобрено».

### Ожидаемые файлы (не включены в ZIP)

- `masters/osa-v15-directors-ru.mp4`, `...-en.mp4`, `osa-v15-trailer-ru.mp4`, `...-en.mp4`;
- соответствующие четыре `captions/*.vtt`;
- отдельное закрытое хранилище настоящих лицензий и подписей для V30 — по мере появления;
- `reportsRoot` должен находиться вне `mediaRoot` и не быть символьной ссылкой.

### Доказуемость

- Настоящее тестовое H.264/AAC создаётся FFmpeg при запуске тестов. Это только техническая заглушка для испытания конвейера.
- Проверяется реальный отказ на отсутствующем файле, вредоносной ссылке, испорченном WEBVTT, лишнем MP4, содержимом с неверным SHA-256.
- Проверяется реальный запуск V31 по loopback, вход по паролю + cookie, запрет непрошедшего входа и отзыв сессии после выхода.
- Архив независимо распаковывается и сверяется по всему `CHECKSUMS.sha256`.

### Отделение от публичной премьеры

Даже когда все **8/8** исходников приняты и V29/V30 формируют технические отчёты, требуется независимое человеческое утверждение оригинальных авторских прав и договоров, качества произнесённого RU/EN, синхронности субтитров, реального HTTPS-CDN, устройств, отката, роли издателя и подписанного разрешения на конкретные SHA-256. Любое отсутствующее доказательство = **NO-GO**. Статус V32 не является лицензией и не активирует checkout или публичный медиакаталог.

### Важная оговорка о V18-материалах старого инженерного архива

В предоставленной локальной копии старого QA-файла `docs/OSA_CINEMA_V18_PRIVATE_FOUR_TRACK_QA.json` обнаружен тестовый SHA-256 из 64 букв `a` и четыре пустых описания аудиодорожек. Это **не доказательство проверки настоящего V18-мастера**. V32 намеренно отображает предупреждение `TEST_FIXTURE_NOT_ACTUAL_MEDIA_EVIDENCE` и всегда указывает `verifiedRealPrivateMaster=false`, даже если синтетические и новые реальные технические файлы проходят V28. Подлинное происхождение исходных видеоматериалов должен подтвердить владелец из проверенного исходного архива/оригинальных медиа и независимых подписанных протоколов. Подмена фиктивного SHA на неподтверждённое «красивое» значение запрещена.


### V32.1 — частные каталоги, границы распакованной программы

Дополнительный проверенный fail-closed контроль запрещает размещать настоящие фильмы и отчёты в каталоге самой программы либо её предке. Запрещаются UNC-сетевые пути, а на POSIX существующие закрытые папки с правами доступа для группы/прочих требуют предварительного `chmod 700`. Проверка выполняется до создания новых папок; никакие реальные байты и юридические документы не включаются в тестовый архив.
