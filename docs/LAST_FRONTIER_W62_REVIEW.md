# LAST FRONTIER W62 — воспроизводимые тестовые сборки Godot

**Только программный review-кандидат. Production HOLD.** Рабочее название пересекается с названием другой игры в Steam и российским «Последним Рубежом» — перед коммерческим использованием нужен юридический аудит.

## Что реально создано

В отдельной ветке находятся независимый упаковщик `tooling/last-frontier/release_package.py`, набор отрицательных тестов, W62 Git-source guard и автоматический GitHub workflow.

Если GitHub CI завершится успешно, он должен подготовить из **того же нового коммита**:

- `LAST_FRONTIER.exe` — настоящий Godot Windows x64 EXE, экспортированный с новым именем;
- `LAST_FRONTIER.pck` — обязательные ресурсы того же Windows-экспорта;
- `Web/index.html`, `index.js`, `index.wasm`, `index.pck` и дополнительные оригинальные Godot Web-файлы;
- `CANDIDATE_MANIFEST.json` со списком файлов, размерами, SHA-256 и только флагами software review / production HOLD;
- `LAST_FRONTIER_REVIEW_<первые 12 символов SHA>.zip`, `SHA256SUMS.txt`, `build-report.json`.

Внутренний W58/W61 OSGARD/OBSIDIAN архив не перезаписывается, старые имена классов не меняются, старые проверки и сейвы сохраняются. Windows EXE и PCK переименованы **в паре**, иначе стандартный Godot standalone может потерять пакет ресурсов.

## Приёмка W62 в GitHub

1. Привязать новый Git HEAD к исходному W61 `44763563db4f1b005bf9a01fe8f5fee4383c0332`, проверить реальную Git-историю, 14 защищённых исходных blob SHA и отсутствие каких-либо изменений игровой логики.
2. Запустить Python-отрицательные тесты на фальсификацию исходного SHA, повреждённый PCK/EXE/WASM, неполные манифесты, symlink, path traversal и ложные флаги публикации.
3. Выполнить настоящую сборку Godot 4.4.1, 169 тестов оригинальных миссий, native W61 RU/EN интерфейс и WebGL/Windows export.
4. Проверить браузерным Chromium геймплей **шести** реальных экспортированных миссий, не подменяя их статическими снимками или HTML-макетом.
5. Создать ZIP дважды из одних и тех же исходных байтов и сравнить SHA-256; дополнительно прочитать оригинальные байты каждого ZIP-элемента и сопоставить с манифестом.
6. Отдельный Windows Server 2022 runner скачивает **настоящий новый** `LAST_FRONTIER.exe` и `.pck`, проверяет SHA-256 и запускает EXE. Headless Windows CI не является пользовательским GPU-бенчмарком.

Загрузки будут доступны как **GitHub Actions artifacts** в отдельном черновом PR W62. Это не «релиз в продажу»: GitHub Releases, Steam, osgard.world, DNS/CDN и VPS не изменяются.

## Проверка вручную на компьютере

1. Возьмите исходный W62 артефакт со страницы успешного CI, распакуйте его.
2. Сначала сравните ZIP с `SHA256SUMS.txt`, затем запустите Windows EXE с `LAST_FRONTIER.pck` в той же папке.
3. Пройдите шесть миссий; проверьте RU/EN, камерные ракурсы, HERO/ECO и пятиэтапный индикатор.
4. На реальной Windows GPU, Android и iPhone измерьте не менее 30 минут работы, покадровое время, худший 1%, память, нагрев и падения. Никаких выводов из эмуляторов о реальном железе.
5. Сохраните исходные скриншоты, модели устройств, параметры драйверов и независимые отчёты; персональные данные не публикуйте в открытом GitHub.
