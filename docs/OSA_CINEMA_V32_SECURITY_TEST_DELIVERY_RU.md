# OSA CINEMA — дополнительная финальная приёмка V32 (локальная)

## Что действительно изменено

1. В `osa-cinema-v32-first-run.mjs` реализована независимая проверка каждого существующего родительского каталога: относительные/вложенные/подменённые пути останавливают подготовку; неизвестная папка фильма или отчётов не может оказаться за символической ссылкой.
2. В `osa-cinema-v32-package-integrity.mjs` добавлен отказ при распаковке даже правильного по внутренним SHA-256 комплекта под символической ссылкой в родительском пути.
3. Новые тесты симулируют такие подмены и подтверждают отсутствие созданных данных за ссылкой.
4. Новый скрипт `launchers/OSA_V32_SAFE_GITHUB_IMPORT.mjs` безопасно готовит **только локальную Git-ветку и коммит** 11 разрешённых файлов V32 (а при использовании V33 — 14 файлов), сохраняя действующий V18 QA. Пять отдельных сквозных тестов проходят на собственном офлайн Git bare remote и настоящем `git fetch`/`git commit`, без обращения к GitHub в интернете.

## Границы

Это приёмка ПО на синтетических видео. Она не проверяет настоящие права, достоверность речи RU/EN, принадлежность подписей к уполномоченным лицам, production HTTPS и реальные устройства Windows/macOS. Настоящих пользовательских MP4, WebVTT, частных ключей и PDF-договоров в ZIP нет.

Статус в любом отчёте: `NO_GO`, `publicationAuthorized=false`, `paidCheckoutEnabled=false`. Отсутствие GitHub plugin access не равно выполнению PR или публикации.


### V32.1 — частные каталоги, границы распакованной программы

Дополнительный проверенный fail-closed контроль запрещает размещать настоящие фильмы и отчёты в каталоге самой программы либо её предке. Запрещаются UNC-сетевые пути, а на POSIX существующие закрытые папки с правами доступа для группы/прочих требуют предварительного `chmod 700`. Проверка выполняется до создания новых папок; никакие реальные байты и юридические документы не включаются в тестовый архив.
