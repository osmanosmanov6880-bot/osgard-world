## 1. Что за игра

**Жанр:** одиночный кинематографический системный триллер / пазл, научно-фантастический промышленный объект. **Фантазийные параметры**, не инструкция по оборудованию. У игрока одна последняя смена в автономном научном комплексе A7. Каждая попытка стабилизировать один узел создаёт последствия для других. История проявляется через изменение мира, свет, звуки, журналы и последствия реальных действий.

**Проверяемое конкурентное отличие:** осмысленная последовательность ограниченных действий с изменением нескольких взаимозависимых показателей и визуальной обратной связью. Нужно слепое сравнение W63/W64 с линейной диагностикой W62; пока это гипотеза, не доказанная уникальность.

**Микроцикл:** прочитать обстановку → выбрать одно из 5 действий → увидеть его эффект в 3D → после второго решения встретить новое событие → оценить последствия → изменить стратегию → дойти до 6-го цикла → получить основанный на состоянии финал. Ошибки объяснимы и воспроизводимы.

## 3. Технический дизайн

**Разделение:** `A7CascadeCore` — детерминированная машина состояний, не знает про рендер и ввод. `A7CascadeScreen` — настоящие Control-кнопки и локализация, переводит игрока к моделям. `A7CinematicStage` — настоящий `Node3D`, `MeshInstance3D`, `Camera3D`, `Light3D`, читает state и изменяет геометрию/эмиссию/освещение, не имеет права менять правила. `w64_browser_acceptance.py` — реальный браузерный ввод плюс чтение read-only state только для QA.

**Обязательные UX состояния:** ожидание, выбранное действие, изменение игрового мира, окончание цикла, критическое событие, победа, провал, reset. На телефоне hero уменьшается, панель настоящая и прокручиваемая. В режиме ECO отключаются дополнительные объекты/свет и снижается внутреннее разрешение. В режиме reduced motion замораживается декоративная 3D-анимация, но показатели по-прежнему обновляются.

**Контракты:**
- Скрипт визуализации не вызывает `choose`/изменение модели и не пишет сейвы.
- Значения HEX/шкалы не являются физическими нормами. Всё вымышлено.
- WebGL QA не получает control API: исходные действия отправляются через обычные нажатия клавиш на canvas, а состояние только читается.
- Новая сборка должна иметь **собственный точный Git SHA**, защищённые исходники, автоматическую проверку Web export и оригинальные скриншоты.
- Никакой серверной регистрации/телеметрии без прозрачного согласия.

## 4. Ритм дальнейшего производства

**Крупный проход A — W64 (сейчас):** 3D-сцена, три камеры, сигналы опасности, реактивные объекты, HERO/ECO/reduced motion, UI, оригинальные native и браузерные тесты. **DONE = все обязательные Jobs PASS и исходный W63 тест PASS.**

**Проход B — W65:** полноценная причинная драматургия: 6 сообщений инцидентов, локализованные внутренние логи, различимые предупреждения для выбора, оригинальный микросаунд, объяснение поражений. DONE = игрок получает причину ошибки, а не только красный цвет; QA обоих языков.

**Проход C — W66:** два взаимосвязанных помещения, небольшой маршрут перемещения и один уникальный системный объект с конфликтом ресурсов. DONE = существует вторая стратегия, измеряемый выигрыш, не более двух минут обучения.

**Проход D — W67:** подлинный 10–15-минутный эпизод, нарратив, варианты концовки, модульный 3D-уровень, сохранение и загрузка. DONE = 12 независимых слепых тестов; собраны анонимизированные данные; сравнение предпочтений с W62.

**Проход E — W68:** доступность, звук, контроллер, производительность, реальная графическая приёмка и исправления. DONE = измерения на конкретных моделях реального оборудования, согласованные бюджеты качества, никаких непроверенных '8K/60FPS' заявлений.

**Проход F — RELEASE CANDIDATE:** legal clearance, экономика, трейлер из настоящего геймплея, реальные бета-тестеры, страница магазина, Windows installer/portable, SHA256/provenance, пользовательский rollback. DONE = отдельное человеческое разрешение и релиз по конкретному коммиту.

Это **план**, а не объявление о выполнении B–F.

## 5. Измерения, которые определят судьбу проекта

| Сигнал | Цель пилотного эксперимента (не достигнуто) | Принятие решения |
|---|---|---|
| First-time clarity | ≥ 10/12 описывают цель и первые 2 действия без помощи | Не прошли → переработать обучение |
| Reachability | ≥ 9/12 способны завершить 6 циклов после разумного обучения | Не прошли → баланс/телеграфирование последствий |
| Cause/effect | ≥ 9/12 могут назвать один причинный компромисс между двумя системами | Не прошли → новый UI + 3D сигнал |
| Replay intent | ≥ 7/12 добровольно пробуют заново и ищут другой маршрут | Не прошли → глубина механик слабая |
| A/B preference | W64 предпочитают старому W62 как минимум 8/12 | Не прошли → 3D-обёртка не оправдывает расходы |
| Perf / real hardware | Цели FPS/1% low утверждать только после замера на выбранных устройствах | Нет замера → нет GPU GO |

Это исследовательские критерии небольшого пилота, не статистическая гарантия коммерческого успеха.
