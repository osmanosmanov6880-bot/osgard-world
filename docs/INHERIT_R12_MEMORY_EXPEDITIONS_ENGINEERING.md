# INHERIT R12 — экспедиции памяти: верни прошлое настоящим игровым ходом

**Сборка:** INHERIT / Quiet Reach • R12  
**Принцип:** никакой фальсификации следов, игроков, сохранений или подтверждений сервера.  
**Встроено:** \`/games/inherit/\`, кнопка «✧ Экспедиции памяти» в панели игровых инструментов.  
**Режимы:** RU / EN / 简体中文, desktop / mobile, поддержка клавиатуры, reduced-motion и PWA v24.

## 1. Почему это полноценная игровая механика

До R12 игра показывала историю поколений, предлагала новые места и позволяла изучать связи. Но игрок не мог использовать **исторический снимок как осмысленную цель** для нового действия. Новая механика связывает три уже существующих элемента: архив поколения, настоящую геометрию острова и обычное размещение предмета.

В «Экспедициях памяти» есть **два типа задач, полученных из реальных данных мира**:

| Тип | Условия возникновения | Что делает игрок |
|---|---|---|
| Вспомнить место | В старом сохранённом снимке был объект данного типа и координат; в нынешнем мире такого объекта рядом больше нет | Выбирает тот же вид предмета и добровольно ставит похожий след в исторически зафиксированную точку |
| Дополнить наследие | Объект из старого снимка всё ещё существует в текущем мире и одно новое размещение действительно способно увеличить число сочетаний по правилам «Наследия» | Выбирает предлагаемый совместимый вид предмета и сам ставит его рядом |

Когда у острова **нет реальных старых снимков**, задач нет: отображается объяснение, как создать первые настоящие исторические кадры. Когда старое место уже представлено в текущем мире, игра не заявляет, что оно «исчезло». Когда новое сочетание уже есть, оно не выдаётся за новую возможность.

## 2. Игровой сценарий

1. Откройте INHERIT. Поставьте настоящий предмет; при необходимости передайте поколение обычной кнопкой.
2. Нажмите «✧ Экспедиции памяти». Вы увидите цели только из доступных сохранённых снимков.
3. Выберите найденное место или сохранившийся исторический след.
4. Посмотрите на мини-карту: мягкая зелёная отметка показывает архивный объект, золотая — возможное место нового игрового действия.
5. Нажмите «Выбрать инструмент и отметить место». Это **не игровой ход**; бюджет, \`objects\`, \`pending\` и номер поколения неизменны.
6. Вернитесь к острову и **сами нажмите** возле золотой отметки. Существующий игровой обработчик применит проверку бюджета, текущего режима и прав аккаунта.
7. Только если мир реально изменился одним соответствующим новым предметом, появится сообщение, что похожий след обнаружен. Проверка также сверяет геометрию и, для совместимых пар, фактический прирост правила «Наследия».
8. Передача поколения и серверное подтверждение выполняются **отдельно существующей кнопкой**. Сообщение о размещении не говорит, что сервер принял поколение или реальный будущий игрок увидел его.

## 3. Реальные границы доказательств

- Текущая версия данных не позволяет доказать, что объект из старого снимка и похожий новый объект — **одна и та же сущность**. Система обещает лишь восстановить похожую геометрию и тип.
- Старый снимок не гарантирует, что кто-то действительно уничтожил объект, не устанавливает автора, дату исчезновения или событие другого игрока.
- Источник данных: \`InheritGenerationAtlas.getFrames(world)\` плюс существующий \`InheritLegacyEngine.derive\`.
- Прогноз становится результатом только после обычного хода. События для исследовательского пилота не отправляются автоматически.
- Экспедиция никогда не вызывает \`InheritGame.apply\`, \`InheritAccount.saveGeneration\`, \`fetch\`, \`localStorage.setItem\` и не изменяет сохранения самостоятельно.
- В аккаунтном режиме действуют прежние полномочия Core; обходов API и прямой записи в чужой мир нет.
- Расходование бюджета происходит только исходным обработчиком клика. Наведение, просмотр, переключение языка и выбор цели ничего не тратят.

## 4. Защита от плохих сохранений и производительность

Применяются строгие правила допустимых объектов и поколений из уже работающего атласа: только десять типов, конечные координаты 0–100, целые неотрицательные номера поколений.

Код работает с верхними границами:
- не более 450 текущих объектов и 24 самых поздних валидных архивных кадров для быстрой необязательной рекомендации;
- не более 96 гипотетических проверок совместимости;
- не более 8 рекомендуемых целей;
- все рекомендуемые координаты попадают в реальные допустимые пределы размещения острова.

При превышении лимита результат явно обозначается как ограниченный. Пропущенные архивы не заменяются синтетическими записями.

## 5. Подтверждение фактического хода

Pure-функция \`InheritMemoryExpeditions.verify(goal,before,after,legacy)\` требует одновременно:
- неизменного номера текущего поколения, одного нового предмета, сокращения игрового бюджета ровно на единицу;
- сохранения ранее существовавших предметов и появления именно рекомендованного типа неподалёку от рекомендованной координаты;
- прироста \`pending\`, если оно было доступно до и после;
- для исторического места — отсутствия такого предмета раньше и близости к зафиксированным координатам;
- для наследственной пары — реального увеличения соответствующего правила существующего Legacy-движка.

Любой изменённый мир, который этим условиям не соответствует, **не получает сообщения об успехе**. Это локальное подтверждение размещения, не криптографическое доказательство авторства или факт серверного подтверждения передачи.

## 6. Проверки, запуск и контроль релиза

\`\`\`sh
npm run qa:inherit-expeditions
npm run qa:inherit-atlas
npm run qa:inherit-network
npm run qa:inherit-compass
npm run qa:inherit-handoff
npm run qa:inherit-account
npm run build
\`\`\`

E2E на desktop/mobile: настоящая попытка поставить предмет и получить правило «Тихая роща»; размещение похожего предмета в месте из старого снимка; отсутствие результата до ручного клика; пустая история; нулевой бюджет в аккаунтном режиме; переключение RU/EN/ZH; отсутствие изменения сохранения от нажатия «подсказка».

CI проверяет JS и PWA v24. Production \`deploy-frontend.yml\` требует green checks, контрольную сумму архива, SSH-активацию с откатом и **побайтное соответствие** всех трёх новых модулей на публичном сайте. После этого игрок может открыть \`https://osgard.world/games/inherit/\` и воспользоваться новой функцией.

## 7. Что ещё не следует объявлять завершённым

Это полноценное расширение интерактивного браузерного игрового цикла, но не AAA-фотореализм и не серверная история происхождения каждого предмета. Реальные удержание D1/D7/D30, платежи, рост аудитории и доказательства спроса требуют добровольных пользователей и независимой коммерческой валидации; ни один успешный CI-тест не превращается в реального игрока.

Следующий предметный рубеж после R12 — удобство существующих действий на мобильном экране, дальнейшее развитие конкретных целей игрока на основании наблюдений и проверка того, почему люди возвращаются к передаче мира.
