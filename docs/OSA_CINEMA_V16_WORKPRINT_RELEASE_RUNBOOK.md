# OSA CINEMA V16 — реальные исходные фильмы, закрытая приёмка и выпуск

Дата: 25 октября 2026. Статус: **техническая подготовка готова, публикация записанного фильма заблокирована**.

## Подтверждено без предположений

Продукт OSGARD \`/osa-cinema\` публикует интерактивную V15, а не записанный фильм. Production Chrome на master прошёл 8/8 тестов ([run 40177975722](https://github.com/osmanosmanov6880-bot/osgard-world/actions/runs/40177975722)).

В пользовательской библиотеке обнаружены и проверены реальные файлы:
- RU и EN 45-секундные превью (1280×720, H.264/AAC);
- RU и EN режиссёрские 3:59-монтажи (1920×1080, H.264/AAC).

Все четыре реальных файла доступны для локального QC, но **не хранятся в этом репозитории**. Их точные размеры, SHA-256, длительности и кодеки закреплены в \`docs/OSA_CINEMA_V16_WORKPRINT_MANIFEST.json\`. Никакие Runway/CDN JWT-ссылки не включены.

**Важный предел:** у всех четырёх MP4 аудио language tag = \`und\`. Наличие аудиопотока и различие RU/EN по хешу ещё не доказывает язык речи. Субтитров в контейнерах нет. Право коммерческого распространения и окончательное одобрение монтажей не представлены. Нельзя переименовать файлы в «готовый фильм» на основании качества кодека.

## Блок 1 — работающий приватный процесс редакторской оценки

Управление исходниками должно происходить **вне публичного сайта**. Для локальной редакторской работы создан самостоятельный HTML-инструмент \`OSA_CINEMA_PRIVATE_REVIEW_ROOM.html\` (передаётся владельцу отдельно, файл не загружает MP4 в сеть): выбор RU/EN workprint, локальная проверка SHA-256, просмотр, отметки времени и замечаний, импорт чернового VTT, экспорт частного протокола решения в JSON.

Чек-лист в HTML — **сбор замечаний**, не разрешение на коммерческий выпуск. Он не вносит никаких изменений в опубликованный сайт.

## Блок 2 — проверяемая неизменность мастер-файлов

Скрипт:

\`\`\`bash
node scripts/osa-cinema-v16-workprint-qa.mjs \
  --root /path/to/private/four-mp4 \
  --report /path/to/private/OSA_CINEMA_V16_QA.json
\`\`\`

Читает четыре файла с диска, сверяет реальные размеры и SHA-256 с реестром, проверяет FFprobe-длительности, видео и аудиокодеки, исходное разрешение и языковые теги. Отчёт по умолчанию **не заканчивается ошибкой** при законно заблокированных файлах: он описывает, что именно не готово.

\`--strict-ready\` предназначен только для релизного шлюза: возвращает ненулевой код, пока остался хотя бы один блокер.

\`\`\`bash
node scripts/osa-cinema-v16-workprint-qa.mjs \
  --root /path/to/private/four-mp4 \
  --approvals /path/to/private/verified-approvals.json \
  --report /path/to/private/release-gate.json \
  --strict-ready
\`\`\`

Поля частного файла утверждения отражены в \`docs/OSA_CINEMA_V16_APPROVAL_TEMPLATE.json\`. Подтверждающие документы нужно хранить локально под \`evidence/\`, субтитры — под \`captions/\`; нельзя коммитить договоры с персональными данными, конфиденциальные исходники и лицензии в открытый код.

## Блок 3 — не подделывать юридическое и редакторское одобрение

Перед выпуском каждого файла необходимы:
1. Документ о правах и разрешении на коммерческий показ для видео/музыки/голоса.
2. Финальная редакторская оценка именно того SHA-256 и соответствующего монтажа.
3. Личная проверка языка реального звука, а не текстовой пометки «RU»/«EN».
4. Настоящий WebVTT с таймкодами по реальному звуку, ручная проверка его содержания.
5. Постоянный HTTPS-источник (не Runway signed URL) и фактическая независимая проверка доставки.

Частные JSON-галочки не являются лицензионным соглашением: независимый проверяющий должен подтвердить действительность документов и достоверность оценок. Система **никогда не выдаёт автоматически право на публикацию**.

## Блок 4 — публикация и финальный тест настоящего видео

После закрытия блокеров: сохранить master MP4, VTT и credits в постоянном HTTPS-хранилище, добавить реальные адреса/длительности/языки в \`public/osa-library/media-inventory.csv\` и \`public/osa-library/media-manifest.json\`, затем только по утверждённым файлам включить \`src/osaMediaCatalog.ts\`. Выполнить \`npm run qa:osa-media-release\`, \`npm run qa:osa-media-availability\`, \`npm run qa:osa-media\`, \`npm run qa:osa-narration\`; проверить реальные MP4, VTT, HTTP Range, ошибку 404, тишину и мобильные браузеры.

Не смешивать четыре workprint-предпросмотра с восемью готовыми фильмами: четырёхминутный монтаж — единый материал, а интерактивный курс — восемь образовательных сцен.

## Блок 5 — выпуск и завершение проекта

При подтверждённой доставке видео обновлять OSGARD только через **новый текущий master**, сохраняя SSH activation lock и игры. Отдельный \`chatgpt.site\` остаётся самостоятельным сайтом и не меняется через GitHub-merge. До независимых подтверждений записанных видеороликов, коммерческих прав, корректного RU/EN звука и субтитров **финальный релиз фильма закрыт**.

Для CI: \`node --test scripts/osa-cinema-v16-workprint.test.mjs\` проверяет предохранители. Само отсутствие файлов в CI ожидаемо, поэтому реальные 120MB частные мастера не загружаются в GitHub Actions.
