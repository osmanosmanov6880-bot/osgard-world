# INHERIT R8 — «Живая история острова»

**Дата:** 21 октября 2026 года  
**Основа:** опубликованные R6 «Атлас поколений» и R7 «Момент наследования».  
**Состояние:** реализация в отдельной GitHub-ветке; публичный статус подтверждается только после зелёных CI и production workflow на конкретном SHA.

## Какую проблему решаем

В R6 пользователь мог вручную сравнить два сохранённых состояния. Однако изменения между несколькими поколениями приходилось мысленно восстанавливать из десятков отдельных чисел. R8 добавляет **наглядное воспроизведение последовательности реально сохранённых кадров** внутри существующего Атласа.

Игра не генерирует вымышленные промежуточные события, персонажей, время, авторов или чужую активность. Это интерактивное перелистывание *состояний сохранения*, а не видеозапись действий игроков или серверно заверенная цепь хранителей.

## Реализованные инструменты

- Панель «Остров сквозь поколения» в существующем модальном Атласе.
- Ручное управление **Назад / Вперёд**, ползунок для перехода к конкретному доступному кадру и «К настоящему».
- **Добровольное** автовоспроизведение доступных состояний с паузой. Оно не запускается само, останавливается при скрытии вкладки, закрытии Атласа, уходе со страницы и достижении конца.
- Настройка \`prefers-reduced-motion: reduce\` полностью запрещает автовоспроизведение. Ручные переходы остаются доступными с клавиатуры.
- Для каждого кадра показаны номер реально сохранённого поколения и его тип (**снимок** либо **текущее состояние**, включая потенциально незавершённые изменения). Никакие промежуточные анимационные кадры не считаются новыми поколениями.
- Карта следов: зелёный — сохранённые/сохранившиеся, золотой — появившиеся, коралловый — исчезнувшие. Считает объекты по типу и координатам, корректно учитывая дубли.
- До 180 маркеров для быстрого просмотра на телефоне; итоговые числа рассчитаны по всему валидному состоянию (до 10 000 объектов).
- Пустые состояния и предупреждения о пропущенных архивных поколениях, устаревших/повреждённых снимках и различии архивного и текущего состояния в *одном* поколении.
- RU / EN / 简体中文 без новых внешних зависимостей и фоновых запросов.

## Честная граница фактов

\`generation-timelapse-core.js\` использует \`InheritGenerationAtlas.getFrames(world)\` и \`compare(world, previous, current)\`. Этот проверенный алгоритм читает только \`world.snapshots[].objects\`, \`world.objects\`, типы, координаты и номер поколения.

Если доступны сохранения поколений 173 и 178, промежуток 174–177 помечается как **неизвестный**. Это не четыре нулевых поколения. Если архивный снимок и текущий мир оба относятся к поколению 178, это не подтверждает новую передачу. Начальный кадр — исходный доступный снимок, не «+N новых следов».

Любой эффект от проигрывателя ограничен DOM: он не вызывает \`InheritGame.apply\`, \`persist\`, \`fetch\`, \`localStorage\`, \`sendBeacon\`, не расходует бюджет, не отправляет поколение и не предоставляет доступ к чужому миру. Аккаунтные права и реальный handoff-контроллер остаются без изменений.

## Инструкция для проверки

1. Открыть \`https://osgard.world/games/inherit/\` и обновить страницу после релиза R8.
2. Нажать **«Атлас поколений»**. В его верхней части открыть «Остров сквозь поколения».
3. Если в сохранении есть несколько кадров, воспользоваться «Вперёд» и «Назад». Пролистать ползунком; посмотреть изменения на карте.
4. Нажать «Смотреть историю» — воспроизведение должно идти только по реальным кадрам и остановиться в конце. Кнопка «Пауза» завершает цикл без изменения игры.
5. Закрыть Атлас клавишей Escape и открыть повторно; убедиться, что таймер не продолжает работать.
6. В системных настройках включить «Меньше движения». Автовоспроизведение должно стать недоступным, ползунок — остаться рабочим.
7. В обычном локальном мире реально оставить след и передать поколение. Снова открыть Атлас и увидеть добавленный снимок/новое состояние.
8. Переключить язык на EN / 中文. Все новые элементы и предупреждения должны локализоваться.
9. Проверить, что **простое перелистывание** не изменило содержимое сохранения, номер поколения, бюджет или права аккаунта. Реальный ход в шаге 7, разумеется, меняет игру.

## Автоматические проверки

\`\`\`sh
npm run qa:inherit-timelapse
npm run qa:inherit-atlas
npm run qa:inherit-handoff-moment
npm run qa:inherit-world-cycle
npm run qa:inherit-account
npm run qa:inherit-followup
npm run build
\`\`\`

Playwright на desktop/mobile проверяет реальное размещение и передачу, последовательность настоящих кадров, таймер автовоспроизведения, ESC, RU/ZH, целостность мира, клавиатуру и запрет автопроигрывания при reduced-motion.

PWA-оболочка обновляется до **v20**. Проверка production после SSH-активации побайтно сверяет \`generation-timelapse-core.js\`, \`generation-timelapse.js\`, \`generation-timelapse.css\` с файловым составом коммита.

## Что ещё не следует утверждать

R8 не является полноценным 3D Godot/Unreal-таймлапсом, MMO-хранилищем авторских действий, видеозаписью реальных игроков или независимым доказательством серверного владения. Пока нет подтверждённых данных реальных участников, нельзя заявлять рост D1/D7/D30, выручки или платёжной готовности из-за этой механики. Для этого остаётся 90-дневный добровольный исследовательский пилот R4/R5.

**Следующий приоритет после проверки игровой пользы:** исследовать, понятнее ли людям передача и последствия своих действий благодаря таймлапсу; затем принять решение об углублении механики предметов, времени и совместного владения на основании обратной связи, а не числа закоммиченных файлов.
