# OSA CINEMA V62 — EVIDENCE ROOM / CONTROLLED PEER REVIEW

Дата подготовки: 29 октября 2026.
База: V61 PR #661. Ветка: feature/osa-cinema-v62-evidence-room-20261029.
Статус на момент авторинга: инженерный кандидат; полноту приёмки подтвердит только CI точного SHA. Это **не** публичный видеорелиз.

## Что внедрено

**А. Отдельный серверный реестр материалов.** Новый \`server/core_cinema_evidence.py\` расширяет SQL ядро действующего OSGARD Core. В \`cinema_evidence\` сохраняются метаданные: фильм, сцена, тип, название, описание, заявленная HTTPS-ссылка, *объявленная пользователем* SHA-256, версия, автор и статус. Таблица \`cinema_evidence_reviews\` хранит историю внутренних решений и не изменяет акт V53.

**Б. Двухсторонняя рабочая проверка.** Автор или владелец отправляет запись на проверку; решить может только другой действующий редактор или владелец. Возврат на исправление открывает новую версию с сохранением прошлых решений. \`internally_reviewed\` означает прочитанные реквизиты и не означает осмотр файла, независимую правовую экспертизу или разрешение на публикацию.

**В. Авторизация и надёжность.** Новые GET/POST \`/api/core/cinema/spaces/:id/evidence\` обслуживаются через существующий Bearer OSGARD Core, проверки Origin и Host, хранилище SQLite с транзакциями и общий журнал операций. Строго проверяются права на каждый запрос и при повторе Idempotency-Key после исключения пользователя, ожидаемые \`expectedVersion\` и \`expectedItemVersion\`. Внешний редактор не может переписать чужой документ; viewer — только читает. При конкурирующих проверках одна запись побеждает, другая получает 409.

**Г. Интерфейс.** В серверном кабинете V61 появился лениво загружаемый раздел «Реестр / Evidence room» с настоящим сетевым доступом, RU/EN, фильтрацией по статусам, созданием записи, редактированием черновика, отправкой коллеге на проверку, вердиктом с обязательным обоснованием, историей и выгрузкой JSON. Дизайн адаптирован к 320 px. Не добавлена демонстрационная база с вымышленными событиями.

**Д. Правило правды.** Реестр не принимает поля \`releaseAuthorized\`, \`publicVideoUrl\`, \`rightsIndependentlyVerified\`; не загружает документы и не скачивает источники. SHA-256 — *строка, которую сообщил пользователь*, хеш содержимого файла сервером не вычисляется. Проверка другого участника не является независимой экспертизой. ZERO WINDOW остаётся 0 из 13 отснятых сцен; права и публичный HTTPS-показ не подтверждены.

## Принцип приёмки

- \`scripts/core-cinema-v62-evidence-smoke.py\`: реальные HTTP/SQLite тесты с регрессиями Core и V61, изоляцией, отзывом доступа, двумя участниками, сохранением SQLite, конфликтами версий, запретом фальшивых релизов.
- \`scripts/osa-cinema-v62-evidence.spec.mjs\`: Chromium через реально запущенный Core — браузерное создание документа, чужая проверка, наблюдатель, RU/EN и 320 px.
- \`scripts/osa-cinema-v62-build-preflight.mjs\`: noindex, фактическая сборка, модуль SEO и доказательство сохранённого NO-GO.
- GitHub Actions: .github/workflows/osa-cinema-v62-evidence.yml.

## Нельзя считать завершённым

Production-grade облако, выделенные хранилища секретов, managed Postgres, SSO, KMS, автоматические бэкапы, реальный CDN, загрузка мастер-файлов, юридический документооборот, независимая проверка прав, фактическая кинотеатральная или онлайн-премьера, надёжность SLA.

**Назначение V62:** серверное управление *описаниями* материалов и внутренним review, без притворства, что фильм уже произведён и выпущен.
