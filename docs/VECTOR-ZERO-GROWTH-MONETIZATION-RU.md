# OSGARD PLAY — VECTOR//ZERO: рост и монетизация

**Статус: экспериментальный план, не прогноз выручки.** Игра остаётся бесплатной. Цель первого цикла — доказать прохождение, возврат на следующий день и органические приглашения до подключения рекламных и платёжных SDK.

## Что меняется в 1.1.0

- Исправлены две ошибки текущей страницы: элемент objective-status отсутствовал, хотя оболочка OSGARD проверяет его наличие; обработчик resize обращался к неопределённому ctx вместо canvas-контекста x.
- Ежедневный контракт использует валидированную UTC-дату и детерминированный hash для одинакового кода и целевого времени в диапазоне 9–15 секунд. Геометрия уровня пока не меняется от даты: seed задаёт контракт/цель, а не процедурную генерацию уровня.
- Ссылка-вызов включает дату и, при отправке результата, время игрока. Приём вызова фиксируется только после нажатия «Начать», а не при открытии ссылки.
- После результата игрок может поделиться URL через Web Share/буфер обмена и скачать PNG-карточку 1200×630. Карточка не выдаётся за серверно подтверждённый рекорд.
- Результаты и личный рекорд хранятся локально. Глобальный рейтинг пока не заявляется: серверной проверки результата нет.
- First-party события складываются в очередь OSGARD (osgard.core.events.v1 / pending.v1) без внешних SDK и без user ID. При отсутствии storage механика продолжает работать.
- Добавлен явно подписанный sponsor CTA для запроса партнёрства. Он ведёт в OSGARD bot, а не имитирует платёж или показ рекламы.

## Модель монетизации — по очереди

1. **Спонсорские испытания / branded challenge** — первый коммерческий эксперимент. Продавать маркированное оформление недельного/месячного испытания только после соглашения с партнёром. Метрики: CTA → начатый диалог → квалифицированный лид → договор → оплаченный счёт.
2. **Косметические supporter-паки** — позже, после появления надёжного entitlements-контура. Никаких преимуществ в физике за деньги.
3. **Opt-in rewarded ads** — позже, если появится рекламный провайдер с проверяемым callback и consent. Реклама не должна прерывать точный манёвр.
4. **Обычные показы** — не включать до доказанного удержания, consent/legal review и измерения чистого RPM. Не считать показы до запуска рекламной сети.

Ни реклама, ни платежи, ни подписка сейчас не активированы. Это осознанное ограничение, а не скрытый доход.

## Как считать цель $1 млн в год

$1,000,000 годовой валовой выручки — это примерно **$83,333/месяц**. Следующие сценарии показывают требуемый масштаб, а не прогноз:

- Только реклама при условном чистом eCPM $4: около **20.8 млн оплаченных показов в месяц**.
- Только реклама при условном чистом eCPM $8: около **10.4 млн оплаченных показов в месяц**.
- Только подписка по условным $4.99 в месяц: примерно **16,700 активных подписчиков**, до налогов, платёжных комиссий и возвратов.
- Только спонсорство по условным $5,000 за кампанию: около **17 оплаченных кампаний ежемесячно**.

Это арифметика при заданных предположениях. Пока нет посещений, стартов, D1/D7-возврата, приглашений, оплаченных показов и реальных договоров — утверждать, что путь к $1 млн доказан, нельзя.

## План эксперимента на 30 дней

**Дни 1–3 — качество:** исправить boot/resize, проверить прохождение на desktop и телефоне, поставить smoke test в npm run qa:vector-zero-growth.

**Дни 4–10 — базовая воронка:** измерить game opened → started → completed; отдельно проверить iframe readiness. Не собирать имена, email, точную геолокацию или рекламный идентификатор.

**Дни 11–20 — вирусная гипотеза:** включить ежедневную цель, share URL и PNG-карточку. Измерить share-created, invite-accepted, долю стартов по shared-link и завершение приглашённых сессий. Сравнить с обычными сессиями.

**Дни 21–30 — B2B тест:** предложить маркированное спонсорское испытание 5–10 релевантным партнёрам; учитывать только квалифицированные переговоры, договоры и оплату. Если спроса нет, не строить рекламную инфраструктуру заранее.

## Условия продолжения

Продолжать инвестиции в рост, если игра стабильно проходит smoke tests, игрок понимает механику, приглашённые действительно запускают и завершают сессию, а хотя бы один канал даёт измеримые возвращения или лиды. Если share clicks есть, а invite starts нет — переделать предложение, не накручивать приглашения. Если D1/D7 слабый, сначала улучшать основной игровой цикл.

## KPI

- Start rate = старты / загрузки игрового клиента.
- Completion = победные завершения / начатые сессии.
- D1 и D7 = вернувшиеся игроки / когорта первого старта.
- Share rate = успешные share/copy действия / завершённые сессии.
- Invite conversion = старты по src=challenge / переходы по challenge links.
- Sponsor funnel = CTA → квалифицированные переговоры → договор → оплаченный счёт.
- Не смешивать gross, net, просмотры рекламы, клик по спонсору и выручку.

## Privacy

First-party измерение хранит только тип события, код дневного испытания, время/ранг забега и placement CTA. Имена, email и ID пользователя не создаются. Если позднее появятся сторонние аналитика/реклама, сначала нужны понятное уведомление, соответствующий consent и legal review. Справочник по защите данных игровой аналитики: https://www.gameanalytics.com/trust/privacy-faq.
