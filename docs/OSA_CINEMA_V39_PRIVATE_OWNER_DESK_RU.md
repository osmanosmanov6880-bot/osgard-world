# OSA CINEMA V39 — настоящий закрытый кабинет для проверки фильма

**Статус:** техническая проверка владельца, не разрешение на выпуск. Показ фильма, публикация в интернете и платная подписка остаются **NO-GO**.

## Что сделано

У OSA CINEMA теперь есть отдельный локальный кабинет владельца с одной кнопкой «Проверить файлы и отчёты». Работает только по `http://127.0.0.1:ПОРТ`, без внешних API, CDN и сервера в интернете. Авторизация с одноразовым CSRF, защищённым cookie и сроком жизни сеанса 45 минут. Пять неудачных паролей временно блокируют вход. После выхода cookie отзывается.

Нажатие кнопки вызывает настоящий единый аудит V38: неизменность исторических V16/V18/V20, целостность V29, сверку байтов **4 MP4 + 4 WebVTT**, при отдельной настройке — 8 криптографических утверждений V30. Закрытые файлы **не обслуживаются** HTTP-сервером; ответ содержит только числа и `NO_GO`. Нет функций воспроизведения фильма, просмотра оригинальных правовых документов, оплаты или публикации.

## Самый простой запуск Windows

1. Установите Node.js **22+** и FFmpeg / FFprobe. Получите **актуальный GitHub checkout V39**, а не старый V34 автономный ZIP.
2. Подготовьте отдельно от папки с кодом три локальные приватные папки: отчёты V29 с `CHECKSUMS.sha256`, четыре финальных MP4 (`masters`), четыре WebVTT (`captions`). До этого у владельца должны быть действительные отчёты V29 и технический V38.
3. Дважды щёлкните `START_OSA_CINEMA_V39.cmd`. Ответьте на три запроса с путями и введите приватный пароль от 16 символов. Он не записывается в файл и не выводится в терминал.
4. Откройте **точный адрес `http://127.0.0.1:PORT`**, который выведет программа, и войдите с тем же паролем. Нажмите «Проверить файлы и отчёты».
5. После проверки загрузите обезличенный JSON-отчёт с названием `OSA_CINEMA_V39_PRIVATE_NO_GO.json` при необходимости. Закройте терминал для завершения локального сервера.

**macOS/Linux:** в терминале из корня проекта выполните `sh ./START_OSA_CINEMA_V39.sh`. Для владельца папки и файлы должны иметь права доступа `0700` и `0600`; сама программа эти права скрытно не меняет.

### Запуск вручную (без мастер-скрипта)

Пароль подаётся **только** через локальную переменную среды `OSA_CINEMA_OWNER_PASSWORD`, никогда через параметр процесса. Обязательные аргументы:

```sh
node scripts/osa-cinema-v39-owner-desk.mjs \
  --repo-root /absolute/path/to/osgard-world \
  --receipts-dir /absolute/private/reports \
  --masters-dir /absolute/private/masters \
  --captions-dir /absolute/private/captions
```

Для независимых подписей V30 можно добавить четыре связанные настройки V38: `--registry`, `--registry-sha256`, `--attestations`, `--evidence-dir`. `--registry-sha256` нельзя брать из самого неподтверждённого архива; он должен прийти доверенным независимым каналом.

## Защита

- Сервер жёстко привязан к `127.0.0.1`; запрещены запросы с чужим Host и cross-origin POST.
- Пароль проверяется через `scrypt` и `timingSafeEqual`. Cookie имеет `HttpOnly` и `SameSite=Strict`; CSRF обязателен.
- Ответы `no-store`, CSP без внешних источников и с `media-src 'none'`.
- Нет маршрута для раздачи файлов, даже после авторизации. Папки и имена файлов не выводятся ни в ответах API, ни в ошибках.
- Одновременно выполняется только один аудит; до завершения отчёт недоступен. Неудачная новая проверка скрывает прежний отчёт.
- Для тестов используется внедрение функции аудита; в обычном запуске **всегда** выполняется V38 из исходников проекта.
- Синтетические MP4, VTT, PDF или ключи из тестов **не являются** настоящими источниками фильма, правами или разрешением издателя.

## Граница готовности

Тесты подтверждают программную интеграцию, но не фактические материалы владельца, физические Windows/macOS устройства, достаточность юридических документов, человеческую редакционную приёмку и реальную HTTPS-производственную эксплуатацию. Для публичного выпуска по-прежнему нужен отдельный независимый комплект доказательств и отдельное решение правомочного издателя; этот кабинет не умеет превращать `NO_GO` в `GO`.
