# OSA CINEMA V27 — сквозная проверка, не релиз

## Зачем нужен этот крупный блок

Ранее V24, V25, V26 и V27 были испытаны независимо. Теперь один сценарий проверяет их взаимную совместимость от начала до конца. Испытания не подключают публичный сервер, не читают пользовательские кинофайлы и не подделывают лицензионное решение.

## Что создаётся при тестировании

* Временная директория с **четырьмя разными синтетическими MP4** (настоящие H.264 + AAC), по одному на RU/EN полный фильм и RU/EN превью. Каждый имеет отдельный SHA-256.
* Четыре коротких учебных WebVTT. Их правильные таймкоды подтверждаются машиной, но тексты не претендуют на реальный дубляж.
* Четыре учебных PDF с явной пометкой `NOT A LICENSE`. Их можно хешировать, но ими нельзя подтверждать коммерческие права.
* Четыре локальных HTTP-сервера на `127.0.0.1`. Они возвращают 401 для гостей, 200 для авторизованного HEAD, 206 для реальных байтов и 416 для неверного диапазона.

## Критерии приёмки

1. Программа V24 полностью декодирует все четыре видео, сверяет SHA и валидирует WebVTT; статус только «technical candidate».
2. Программа V25 регистрирует четыре существующих PDF и всегда пишет, что правовая проверка **не** выполнена.
3. Программа V26 подтверждает корректные HTTP-ответы и совпадение выданных байтов со своими синтетическими MP4.
4. Программа V27 связывает четыре отчёта в единый объект: *техническая репетиция пройдена*, но `NO_GO`, `paidCheckoutEnabled=false`, `publicFilmPublicationAuthorized=false` и восемь обязательных человеческих/production-гейтов.
5. Подмена байта MP4, PDF или HTTP-ответа и попытка фальсифицировать публикационный флаг обязаны вызывать запрет.

## Запуск

```bash
node --test scripts/osa-cinema-v27-integrated-chain.test.mjs
```

Для полной локальной проверки требуется FFmpeg/FFprobe в PATH. Тесты генерируют только временные данные, завершают HTTP-серверы и удаляют файлы после прогона. GitHub Actions повторяет тот же сценарий в отдельном Linux-окружении.

## Что необходимо для настоящей премьеры

Четыре реальных финальных MP4, четыре синхронизированных утверждённых WebVTT, независимое прослушивание RU/EN и режиссёрская приёмка, достаточные коммерческие лицензии и согласия, отдельная production-проверка HTTPS/доступности на настоящих устройствах, испытанный откат и явное согласие издателя на точные релизные хеши. **Пока отсутствует хотя бы один пункт — фильм и оплаты не активируются.**

## Усиление V26: полная побайтовая доставка

Проверка первых и последних диапазонов MP4 недостаточна: середина файла может быть подменена. Поэтому V26 дополнительно делает полный авторизованный `GET /media` строго на числовой адрес `127.0.0.1`, потоково считает SHA-256 всего HTTP-тела, сверяет полный размер и заголовки. Неверная середина, неполное тело или другой хеш означает `STAGING_DELIVERY_HOLD`. V27 не принимает техническую доставку без совпавшего **полного** digest. Это подтверждает исключительно локальную синтетическую репетицию, не готовность настоящего production-CDN и не права на фильм.
