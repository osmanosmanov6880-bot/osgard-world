# NEBULA R40 — изолированная HTTPS-приёмка

Этот этап публикует кандидат отдельно от действующей R38. Адрес QA не считается финальным релизом.

1. Убедитесь, что новейший CI PR #375 завершился **success** и сформировал артефакт `nebula-r40-on-device-candidate`.
2. В GitHub Actions запустите `NEBULA R40 isolated device QA staging` с ID успешного запуска в поле `source_run_id`.
3. Workflow проверяет идентичность текущего PR, целостность SHA-256, происхождение игровых файлов и активирует только собственную staging-папку.
4. После подтверждения Nginx тестовая игра будет доступна по `https://osgard.world/games/remix/nebula-r40-qa/`.
5. Сравните её с публичной R38: `https://osgard.world/games/remix/arena-v2/nebula-3d/`.
6. Соберите 108 оригинальных 20-секундных JSON, 12 настоящих кадров, замеры нагрева и письменный осмотр двух Android и одного iPhone.
7. Выпуск R40 поверх R38 разрешён только после аппаратного допуска и отдельного обновления production-allowlist.

QA-адрес потенциально общедоступен; нельзя размещать в игровой сборке приватные данные или ключи. Для доступа с телефона может потребоваться обычная HTTPS-конфигурация домена.

В случае ошибки GitHub CI, SHA-256, SSH, диска или внутреннего HTTP-проверочного запроса workflow останавливается. Опубликованную директорию R38 он не изменяет.
