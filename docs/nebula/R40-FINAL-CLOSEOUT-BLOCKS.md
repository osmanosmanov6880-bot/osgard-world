# NEBULA R40 — финальное закрытие большими блоками

## Состояние релиза
- Публичная игра остаётся на проверенном R38. Лаборатория локальных сравнений R39/R40 работает в production, не отправляет пользовательские JSON на сервер.
- R40 candidate: [PR #342](https://github.com/osmanosmanov6880-bot/osgard-world/pull/342) — 96 реальных трёхмерных светильников объединены в три MultiMesh. Встроена маркировка JSON `NEBULA_R40_BRIDGE_BATCH_3X32`.
- Визуальный браузерный кадр 1280x720 был получен в hosted Chromium через `canvas-readback-early`. Он **не** доказывает ни аппаратный FPS, ни качество iPhone/Android, ни фотореализм. В архиве QA был тайм-аут отдельного метода захвата Godot.
- [PR #350](https://github.com/osmanosmanov6880-bot/osgard-world/pull/350) проверен CI и объединён в ветку R40: новый порядок настоящих методов захвата.
- [PR #346](https://github.com/osmanosmanov6880-bot/osgard-world/pull/346), [PR #349](https://github.com/osmanosmanov6880-bot/osgard-world/pull/349), [PR #354](https://github.com/osmanosmanov6880-bot/osgard-world/pull/354) объединены с `master`: проверка версии JSON, офлайн-фильтр аппаратной приёмки, контроль рывков 1% Low/P99.

## Блок А — программная приёмка (код и безопасность)
1. Проверить именно **последний коммит** PR #342: Godot native, физическая структура мостов, WebAssembly, настоящий браузерный полёт, мобильные касания, безопасность лаунчера, коммерция, frontend.
2. Получить из GitHub Actions `nebula-r40-on-device-candidate` и сверить целостность. Запустить кандидата только в частном тестовом окружении, отдельно от production R38.
3. Получить реальные пиксели в Chromium и проверить вручную, что мосты, светильники и UI видны. Кадр из SwiftShader — только дополнительная диагностика.

## Блок Б — настоящие Android и iPhone
Матрица минимум: **3 физических телефона × 2 ориентации × 3 профиля × 2 сборки × 3 повтора = 108 оригинальных JSON**. Минимум 12 настоящих снимков (каждый телефон × обе ориентации × две сборки).
- По крайней мере два разных Android (включая слабый) и один настоящий iPhone Safari.
- Сохранять одинаковые маршруты полёта, разрешение, ориентацию, профиль MAX/HIGH/ECO и условия нагрева/заряда.
- Оригинальные R40 JSON обязаны содержать `build_variant`. Не использовать старые R40-архивы без этой метки.
- Назначить человека для осмотра каждого устройства и записи замечаний о свете, коллизиях, интерфейсе и управлении.
- Данные устройств должны оставаться в локальном/контролируемом QA-хранилище, без публикации персональных идентификаторов.

## Блок В — численная приёмка
Из корня репозитория:
```sh
node scripts/nebula-r40-device-progress.mjs /path/to/private/manifest.json
node scripts/nebula-r40-field-release-gate.mjs /path/to/private/manifest.json
```
Первый инструмент показывает **неполноту**, второй — строго проверяет 108 файлов на независимость, режим, ориентацию, версию, программный GPU, разброс и регрессии FPS/P95/1% Low/P99. Даже `PASS` второго инструмента не удостоверяет происхождение физических данных или честность осмотра.

## Блок Г — визуальная приёмка и оптимизация
- Сравнить R38/R40 на тех же телефонах при видимых мостах, городе и корабле. Не заменять геометрию картинками.
- Проверить свет, контраст HUD, readability, глубину кадра и нагрев на продолжительном прохождении.
- Если FPS/1% Low/P95/P99 или внешняя сцена деградируют, **не выпускать R40**; исправить конкретную причину и повторить парные тесты.

## Блок Д — выпуск в production и откат
**Запрещено считать R40 завершённым без физической матрицы.**
1. После заключения QA и письменного допуска объединить PR #342 в актуальный `master`.
2. Запустить установленный GitHub Actions экспорт Godot и дождаться CI **на итоговом merge-коммите**.
3. Через уже используемый SSH workflow опубликовать с механизмом отката; проверить `index.wasm`, `index.pck`, HTTPS, маршруты игры и лаборатории в Nginx.
4. На физических телефонах повторно проверить один полёт и 20-секундный тест; при серьёзной регрессии откатить к последнему подтверждённому R38.
5. Записать версии, реальные доказательства, результат и ответственного в релизный журнал.

**Неизвестное:** сейчас нет подтверждённых замеров реальных Android/iPhone и независимой аппаратной визуальной приёмки. Не обещать 60 FPS или AAA-фотореализм.
