## C. Аппаратная матрица — не выполнена
- Требуется 2 Android + 1 iPhone, обе ориентации, MAX/HIGH/ECO, R38 и R40, три отдельных 20-секундных запуска: минимум 108 оригинальных JSON.
- 12 настоящих скриншотов, проверка света и физики, плавности, нагрева и UX, отдельное заключение инженера.
- Для локальной проверки использовать scripts/nebula-r40-field-release-gate.mjs.
- Для связывания первичных данных SHA-256 без публикации файлов использовать scripts/nebula-r40-production-preflight.mjs.
- Автоматические тесты, синтетические показатели и SwiftShader не подтверждают аппаратную производительность.

## D. Production-allowlist — намеренно закреплён за R38
- Файл .github/nebula-production-allowlist.json имеет approved_variant=R38 и approval=null.
- Любая попытка обновить игровые байты без соответствия allowlist должна завершаться отказом.
- Отдельный проверенный release PR и решение человека обязательны перед переводом на R40.

## E. Финальная публикация — пока удерживается
После реальной приёмки: утверждённый протокол, PR продвижения, повторный CI, резервная копия, публикация по SSH, HTTP/WebAssembly smoke и возможность отката. До этого R40 остаётся тестовой QA-версией, а не новым production.


## F. Усиленная проверка происхождения будущего R40-релиза

Защита `scripts/nebula-production-artifact-guard.mjs` для потенциального `approved_variant=R40` дополнительно требует точного совпадения метаданных `approval.candidate_pr`, `approval.candidate_head_sha` и `approval.source_run_id` с изолированным QA-манифестом `.github/nebula-r40-qa-one-shot-source.json`. Также `approval.ci_artifacts_sha256` обязан содержать четыре SHA-256: `index.html`, `index.js`, `index.wasm`, `index.pck` — строго для оригинальных файлов подтверждённого CI-кандидата.

Проверка сопоставляет каждый опубликованный файл с разрешённым Git blob и отдельным CI SHA-256, а не только с самодекларированной меткой «R40». Ни тест с искусственными данными, ни корректные хеши сами по себе **не доказывают физических измерений и не разрешают публикацию**. Требуются настоящие результаты, независимое заключение, новый проверенный PR и безопасное переключение с откатом.

До этого `approved_variant=R38` и `approval=null` остаются неизменными; **не подменять production из тестовых веток #375/#403**.

## G. Автоматическая проверка после frontend-деплоя

Workflow `.github/workflows/nebula-r40-live-byte-parity.yml` слушает событие `workflow_run` от **OSGARD frontend deploy**, завершившегося на `master`. Проверка работает без SSH и использует только read-only доступ GitHub.

- Если frontend-деплой завершился с ошибкой, следующий запуск **FAIL** и не подтверждает сохранность QA.
- Если публикация выполнена успешно на `master` (`push` или `workflow_dispatch`), повторяется сравнение четырёх HTTPS-файлов действующей разрешённой игры и четырёх файлов тестовой R40 с закреплёнными SHA-256. Пропавшая QA-директория, SPA-заглушка или иной WASM/PCK дают **FAIL**.
- Совпадение файлов доказывает только **тождество опубликованных байтов**, а не FPS, 3D-качество или подлинность физических измерений.
- Ручной запуск: Actions → **NEBULA R38/R40 public HTTPS exact-byte integrity** → Run workflow.

Устранение найденных серверных проблем требует отдельного защищённого процесса; read-only workflow не меняет опубликованную игру. До независимой аппаратной приёмки нельзя менять production-allowlist `R38` или объединять игровой кандидат #375.
