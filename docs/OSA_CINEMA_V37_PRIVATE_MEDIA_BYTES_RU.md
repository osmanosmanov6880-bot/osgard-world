# OSA CINEMA V37 — проверка байтов восьми реальных локальных MP4/WebVTT

Дата: 25 октября 2026 года. Состояние записанного фильма: **NO-GO** для публикации и оплаты.

## 1. Что проверяется

V36 уже сверяет закрытые отчёты V28/V24/V26/V29 (и при наличии V25/V27) между собой.
V37 после успешной V36-проверки **читает байты самих файлов** в двух закрытых папках:
четырёх финальных `*.mp4` и четырёх `*.vtt`, указанных в `V28_CANDIDATE_MANIFEST.json`.

- Сверяются все четыре MP4 SHA-256 и точный размер с V28.
- Сверяются все четыре WebVTT SHA-256; начало каждого должно содержать WEBVTT и временную реплику.
- Чтение потоковое — архивы и файлы кино не нужно загружать в память целиком.
- Запрещены символические ссылки в родительских каталогах, жёсткие ссылки на файлы, лишние имена, смешанные рабочие папки и неполные комплекты.
- В POSIX файловые права для трёх корневых папок должны быть `0700`, а для восьми файлов — `0600`. На Windows для ACL требуется отдельная проверка администратором.
- Проверка завершается ошибкой при несоответствии байтов, размере, правах и недопустимом WebVTT.
- Отчёт не содержит пути к приватным файлам и не записывает ни одного видеобайта в GitHub.

## 2. Запуск владельцем

Нужны Node.js 22+, предварительно созданные V29-отчёты и восемь **настоящих** финальных файлов, принадлежащих владельцу.
Из корня проекта (Node.js не требует установки npm-пакетов для V37):

**Windows PowerShell:**

```powershell
node .\scripts\osa-cinema-v37-verify-private-media.mjs --receipts-dir "D:\OSA_PRIVATE_REPORTS" --masters-dir "D:\OSA_PRIVATE\masters" --captions-dir "D:\OSA_PRIVATE\captions"
```

**Linux/macOS:**

```bash
node ./scripts/osa-cinema-v37-verify-private-media.mjs --receipts-dir "$HOME/osa_private_reports" --masters-dir "$HOME/osa_private/masters" --captions-dir "$HOME/osa_private/captions"
```

Директории нужно указывать реальные, не сетевые. Для POSIX проверьте `chmod 700` на папках и `chmod 600` на своих файлах. Не копируйте материалы в папку Git-репозитория.

Технический PASS означает только, что **8 локальных файлов совпали с текущими V28/V29 техническими квитанциями**. Он не удостоверяет подлинность автора этих квитанций. Для этого требуется независимый канал доверия и подтверждённые оригиналы.

## 3. Раздельные обязательные блокеры

1. Человеческая редакционная приёмка реальных RU/EN дорожек и субтитров на финальных файлах.
2. Подтверждённые коммерческие права на каждый фрагмент, музыку, голос, изображения и договоры.
3. Независимая проверка полномочий издателя и подписей V30, а не только совпадение криптографических сумм.
4. Физические Windows/macOS/телефонные тесты владельцем, production HTTPS, мониторинг и восстановление.
5. Отдельное правообладательское разрешение на конкретные SHA-256 финального релиза.

Без них флаги **`publicationAuthorized=false`, `rightsCleared=false`, `paidCheckoutEnabled=false`** остаются неизменными. V37 не предоставляет веб-публикацию, платёжный экран и кнопку `GO`.

## 4. Испытания и границы

Автоматические тесты используют заведомо синтетические файлы и защищённые тестовые квитанции.
Интеграционный тест через настоящий V29 применяет FFmpeg и четыре сгенерированных MP4, но **не проверяет материалы правообладателя**.
Проверка начала WebVTT не доказывает синхронизацию всех реплик или соответствие произнесённому языку.
Проверка прав `0600` не удостоверяет платформенные ACL Windows и не распознаёт все варианты подключённого сетевого диска.

**Итог:** лучшее техническое средство для точного офлайн-контроля восьми файлов; выпуск фильма остаётся отдельным правовым и производственным решением.
