# OSA CINEMA V29 — финальная приватная техническая приёмка за один запуск

## Что уже реально работает

V29 объединяет давно реализованные инструменты, которые до этого требовали ручного запуска: **V28 → V24 → V21 → V26 → V25 (при наличии документов) → V27 (при наличии документов)**.

1. Берёт ровно четыре реальные кандидатные MP4 и четыре WebVTT с компьютера правообладателя. Каждая редакция должна быть отдельно RU/EN, длинный фильм/превью.
2. V28 строит реестр файлов и SHA-256 без ручного ввода; проверяет H.264/AAC, размеры, длительность и WebVTT.
3. V24 полностью декодирует четыре MP4. Если один исходник не проходит проверку, **приватная видеодоставка даже не запускается**.
4. V21 запускает отдельный временный HTTP-сервер для каждой редакции **только на `127.0.0.1`**, генерирует сильный пароль в оперативной памяти, получает одноразовый CSRF-токен и защищённую cookie-сессию. Пароль не сохраняется.
5. V26 подтверждает отказ анонимному пользователю, корректные HEAD/200/206/416, MIME, длительную побайтовую сверку всего тела и SHA-256; затем V29 выходит из сессии и проверяет её аннулирование. Серверы закрываются после каждого фильма.
6. При наличии **реального** реестра использования источников `--rights-usage`, V25 проверяет байты PDF, связи документов с версиями и точные SHA-256. Это техническая проверка наличия файлов, **не** заключение о действительности лицензий.
7. V27 строит итоговую доску при наличии V25. Результат в любом случае **NO-GO**, пока независимые редакторы, юрист, издатель и production-команда не предоставят свои действительные разрешения и результаты проверки настоящего хостинга.

## Где держать реальные фильмы

**Только приватная папка владельца, вне репозитория GitHub:**

```
PRIVATE_DIR/
  masters/
    osa-v15-directors-ru.mp4
    osa-v15-directors-en.mp4
    osa-v15-trailer-ru.mp4
    osa-v15-trailer-en.mp4
  captions/
    osa-v15-directors-ru.vtt
    osa-v15-directors-en.vtt
    osa-v15-trailer-ru.vtt
    osa-v15-trailer-en.vtt
  rights/                            # только при наличии реальных доказательств
    source-license-01.pdf
    ...
```

Все восемь имён должны совпадать с V16. Символические ссылки, отсутствующие, подменённые и лишние файлы в `masters` и `captions` отклоняются. Редакционный фильм не следует переименовывать в готовый релиз без проверки.

## Одна команда — Windows PowerShell

Из корня репозитория (`node --version` должен показать Node 22+, `ffmpeg -version` и `ffprobe -version` должны работать):

```powershell
node scripts/osa-cinema-v29-owner-preflight.mjs --root 'D:\OSA-PRIVATE\film' --out 'D:\OSA-PRIVATE-REPORTS\RUN-001' --originals docs/OSA_CINEMA_V16_WORKPRINT_MANIFEST.json
```

Для Linux/macOS:

```bash
node scripts/osa-cinema-v29-owner-preflight.mjs --root "$HOME/OSA-PRIVATE/film" --out "$HOME/OSA-PRIVATE-REPORTS/RUN-001" --originals docs/OSA_CINEMA_V16_WORKPRINT_MANIFEST.json
```

Отчётная директория должна быть **новой**, не внутри исходной папки. Повторный запуск требует нового имени `RUN-002` — существующие отчёты не перезаписываются. Выводы `V28`, `V24`, `V26`, `V29` и файл `CHECKSUMS.sha256` создаются только после завершения всех четырёх медиапроверок. Права доступа к отчётам закрыты (на системах, поддерживающих POSIX mode).

## Зафиксировать конкретные финальные байты и проверить документы

После первой проверки сохраните на закрытом носителе `RUN-001/V28_CANDIDATE_MANIFEST.json`. **Не меняя MP4 или WebVTT**, повторите проверку с параметром `--pinned-plan`. Это связывает новый результат с исходными SHA-256 и размерами; любая подмена MP4, WebVTT или смена метаданных приводит к ошибке **до проверки доставки**.

```powershell
node scripts/osa-cinema-v29-owner-preflight.mjs --root 'D:\OSA-PRIVATE\film' --out 'D:\OSA-PRIVATE-REPORTS\RUN-002' --pinned-plan 'D:\OSA-PRIVATE-REPORTS\RUN-001\V28_CANDIDATE_MANIFEST.json' --rights-usage 'D:\OSA-PRIVATE\rights-usage.json'
```

`rights-usage.json` — частный реестр реальных источников, ссылок на **точные** финальные версии и SHA-256 настоящих PDF (формат описан в V25). Не подставляйте синтетические документы из тестов. Каждый PDF нужно прочитать и отдельно юридически оценить. `V25_RIGHTS_BYTES_QA.json` и `V27_FINAL_NO_GO_BOARD.json` появятся только при предоставлении `--rights-usage`; без него V29 честно указывает отсутствие реестра прав.

## Отчёты, которые можно проверять независимо

- `V28_CANDIDATE_MANIFEST.json` — точные MP4/VTT SHA-256, длительность, формат и связь с исходниками V16.
- `V24_MEDIA_QA.json` — полное декодирование и проверка субтитров.
- `V26_PRIVATE_DELIVERY_QA.json` — четыре проверки защищённой локальной HTTP-доставки, включая SHA-256 всего потока.
- `V25_RIGHTS_BYTES_QA.json` — только если представлены реальные файлы/реестр; никак не означает, что лицензия действительна.
- `V27_FINAL_NO_GO_BOARD.json` — только с V25; все восемь внешних разрешений остаются обязательными.
- `V29_OWNER_PREFLIGHT_NO_GO.json` — единая матрица SHA-256/состояний и список блокирующих условий.
- `CHECKSUMS.sha256` — хеши созданных JSON, чтобы заметить их случайное изменение. **Это не электронная подпись и не подтверждение владельца.**

Ключи/пароли/видеобайты не отправляются в GitHub, публичный сайт или удалённое хранилище. Программа не слушает внешние IP и не оставляет временные серверы включёнными.

## Приёмка и ограничения

```bash
node --test scripts/osa-cinema-v29-owner-preflight.test.mjs
```

Тесты создают четыре **синтетических** H.264/AAC MP4, четыре WebVTT и фальшивые PDF с пометкой `NOT A LICENSE`; они должны продемонстрировать, что техническая цепочка работает, но коммерческий выпуск остаётся заблокированным. Реальную речь они не анализируют, iPhone/Android не заменяют и права собственности не подтверждают.

Параметр `--strict-publication` преднамеренно возвращает код выхода **2** даже при полностью зелёной технической приёмке. Не интерпретируйте этот код как неисправность программы: он подтверждает, что записанный фильм ещё не авторизован для премьеры.

**Финальная граница:** юридическая очистка всех источников, режиссёрский и звуковой просмотр RU/EN, синхронизированные и утверждённые WebVTT, production HTTPS с реальными устройствами/откатом и отдельное письменное разрешение издателя на точные SHA-256 восьми файлов. Только после этого отдельный человек может разрешить выпуск. Код V29 никогда не меняет публичный медиакаталог и не включает оплату.
