# OSGARD Core — проверка резервной копии и восстановленных операций

**Статус:** офлайн-инструмент и локальные регрессионные испытания. Production-копии не читались, рабочая база не восстанавливалась, реальные RTO/RPO не измерялись.

Улучшенная версия [PR #104](https://github.com/osmanosmanov6880-bot/osgard-world/pull/104). Входом служит **уже готовый согласованный snapshot**, а не файл действующей SQLite.

## Проверка файла

Оператор получает согласованную резервную копию через существующий SQLite backup API: `server/core_backup.py backup SOURCE NEW_DESTINATION` или штатный `scripts/backup-core-production.sh`. Копирование активного SQLite-файла обычным `cp` не является протоколом резервирования.

```sh
python3 scripts/verify-core-backup.py /private/backups/core.sqlite3 --sha256 EXPECTED_64_HEX_DIGEST --json
```

Вместо `EXPECTED_64_HEX_DIGEST` указывается доверенный хеш, зафиксированный при резервировании. Без `--sha256` скрипт подтверждает совпадение исходного файла и собственной копии, но не её происхождение.

Проверка выполняется так:

1. Компоненты пути открываются на POSIX через directory descriptors и `O_NOFOLLOW`. Симлинки, FIFO, устройства и пустые файлы отклоняются. Наличие любого `-wal`, `-shm` или `-journal`, даже пустого, требует создать отдельный согласованный snapshot.
2. Байты источника копируются в отдельный временный каталог с приватными правами. Из тех же байтов рассчитывается SHA-256; проверяются размер и идентичность источника до/после копирования.
3. SQLite открывает только **временную копию** в read-only/immutable режиме. Выполняются `integrity_check`, `foreign_key_check`, проверка версии 1 и базовых таблиц/колонок Core, включая журналы идемпотентности и платежей.
4. В отчёт попадают метаданные, хеш и длительность проверки. Пользовательские строки, схема SQL, имена таблиц и секреты не выводятся. Временный каталог удаляется. Ошибка даёт код выхода `2`.

`--sqlite-only` — явный диагностический режим для произвольной SQLite. Он проверяет целостность и связи, но устанавливает `core_schema_checked=false`; это не подтверждение совместимости Core.

Успех проверки означает сохранность и базовую совместимость этого snapshot. Он не доказывает полноту бизнес-данных, доступность offsite-копии или восстановление всего приложения. `application_restore_validated=false`, `rto_seconds=null`, `rpo_seconds=null` остаются явными в отчёте.

## Обязательные испытания восстановления операций

```sh
python3 -m unittest discover -s tests -p test_core_backup_recovery.py -v
python3 -m unittest discover -s tests -p test_core_restored_operations.py -v
python3 -m py_compile scripts/verify-core-backup.py tests/test_core_backup_recovery.py tests/test_core_restored_operations.py
```

Первый набор использует временные SQLite-фикстуры: корректный snapshot; хеши; повреждения; пустая схема; симлинк файла и родительской директории; FIFO; WAL/journal; нарушенные foreign keys; неверная Core-схема; текущая Core-схема; получение полноценного snapshot из активного WAL.

Второй набор выполняет настоящие `Store`, backup API и повторное открытие SQLite. Платёжная граница заменена `FakeProvider`; конструирование реального SDK-провайдера принудительно блокируется. Внешних аккаунтов, сетевых запросов и денежных операций нет.

| Сбой | Что проверяет восстановление |
| --- | --- |
| Checkout создан провайдером, ответ потерян | Повтор после snapshot/restore использует прежний durable provider key; создаётся одна сессия |
| Refund создан провайдером, ответ потерян | После restore существует один возврат; повтор webhook не меняет учёт второй раз |
| Истёк допустимый интервал неизвестного Checkout/Refund | После restore возвращается `reconciliation_required`; новая операция не создаётся |
| Потерян ответ сборки или внутреннего выпуска | Повтор сохранённого ключа после restore возвращает прежний artifact/release; количество остаётся 1 |
| Запрошена внешняя публикация | Core отклоняет неподдерживаемое действие и после restore; внешний publisher этим тестом не проверен |

Сроки хранения ключей у внешнего провайдера ограничены: [Stripe API v1](https://docs.stripe.com/api/idempotent_requests) допускает удаление ключа после минимум 24 часов. Текущий Core использует более короткий `RETRY_WINDOW` и требует сверки просроченного неизвестного результата. Нельзя считать старый ключ бессрочной гарантией.

## План реального восстановления

1. Зафиксировать момент сбоя, версию приложения, время последней надёжной копии и ожидаемый хеш. Получить копию из независимого хранилища, проверить её этим инструментом.
2. Запустить Core на отдельном изолированном хосте с восстановлением **в новый путь**. Держать новые платежи и внешние публикации выключенными; защитить исходную копию от изменений.
3. Проверить вход/права, проекты, сохранённые версии, файлы, обучение, выдачу доступа и аудит. Проверить повтор незавершённого запроса из сохранённого журнала с исходным ключом, не придумывая новый.
4. Сверить события провайдера и publisher **после времени snapshot** до включения новых операций. Snapshot, снятый до внешнего списания/публикации, не содержит его ключа: локальный restore сам по себе не предотвращает повтор. Неизвестные операции переводятся на сверку.
5. Измерить RTO от начала восстановления до успешных обязательных пользовательских сценариев; RPO — фактический интервал потерянных подтверждённых данных. Длительность `integrity_check` не равна RTO.
6. Только после сверки провести переключение трафика по процедуре с возможностью отката. Сохранить подписанный оператором отчёт, список проверок и измеренные RTO/RPO в закрытом хранилище.

## Хранение и доступ

Резервные файлы могут содержать хеши паролей, сессии и персональные данные; не добавляйте их в GitHub и общие логи. Используйте закрытые права, шифрованную независимую копию, определённый срок хранения и сигнализацию об устаревании/ошибке backup-job. Перед повторным использованием доступа замените приватный ключ, ранее опубликованный в переписке; сам инструмент ключи не читает и не меняет.

Изменения ограничены скриптами, тестами и документацией. Production Compose, Nginx, серверные API, платёжные настройки и база данных этим патчем не изменяются.
