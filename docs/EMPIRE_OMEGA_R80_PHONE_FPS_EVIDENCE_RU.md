# EMPIRE Ω R80 — достоверность FPS на физических Android/iPhone

Обновление 25 октября 2026. **Это инструмент приёмки, не отчёт об успешных испытаниях реальных телефонов.**

## Суть изменения

Ранее R50 мог принять вручную вписанные p95/p99 и короткую видеозапись с контрольной суммой, даже когда не было исходных измерений производительности Godot. R80 запрещает считать такой JSON достаточным основанием для технической оценки.

Теперь для каждого устройства оператор должен предоставить ТРИ исходных файла в одной папке:

1. `android.json` либо `ios.json` — сведения о модели, версии ОС, браузере, тестировщике, UTC времени, разрешении, source_commit, время прогрева, FPS, SHA-256 двух файлов.
2. `original-godot-benchmark.json` — точный файл, скачанный штатной кнопкой **«СКАЧАТЬ JSON»** из действующей EMPIRE Ω после штатного 20-секундного замера через **«ЗАМЕР 20 С»** (диагностика HUD); нельзя переписывать или пересчитывать данные вручную.
3. `physical-session.webm` или `physical-session.mp4` — непрерывное видео с открытием страницы, демонстрацией устройства, прохождением активного игрового сцены и запуском замера.

В `android.json` или `ios.json` должны быть поля:

```json
{
  "schema": "empire-omega-r50-physical-v1",
  "source_commit": "ПОДСТАВЬТЕ_40_СИМВОЛОВ_ИЗ_ОПУБЛИКОВАННОГО_release.json",
  "os_family": "android",
  "physical_device": true,
  "model": "ФАКТИЧЕСКАЯ МОДЕЛЬ",
  "os_version": "ФАКТИЧЕСКАЯ ВЕРСИЯ",
  "browser": "ФАКТИЧЕСКИЙ БРАУЗЕР",
  "operator": "ИМЯ ТЕСТИРОВЩИКА",
  "capture_utc": "2026-10-25T15:00:00Z",
  "warmup_s": 2.0,
  "capture_s": 20.0,
  "frame_count": 1200,
  "p95_frame_ms": 32.0,
  "p99_frame_ms": 40.0,
  "viewport_width": 390,
  "viewport_height": 844,
  "benchmark_file": "original-godot-benchmark.json",
  "benchmark_sha256": "РЕАЛЬНЫЙ_SHA256_ОТ_ИСХОДНОГО_JSON",
  "recording_file": "physical-session.webm",
  "recording_sha256": "РЕАЛЬНЫЙ_SHA256_ОТ_ВИДЕО"
}
```

**Важно:** пример содержит вымышленные числа **только для демонстрации формата**. Не копируйте их в реальную приёмку. Все числовые поля должны точно соответствовать настоящему скачанному Godot JSON.

## Проверить доказательства

```bash
python3 scripts/omega_r80_hardware_evidence.py \
  --report /path/to/phone/android.json \
  --source-commit СТРОГО_40_HEX_ИЗ_PUBLIC_RELEASE_JSON \
  --output /path/to/phone/verdict.json
```

Требуются: оригинальный R36 Godot JSON, совпадающие p95/p99, p50≤p95≤p99, исходное число кадров, частота, соответствие разрешения, доля медленных кадров, время, формат и SHA-256 видео. Подмена данных, неверный SHA-256, режим браузерной эмуляции, другой коммит или испорченная структура файла вызывают `HOLD` и код возврата 1.

Проверьте текущую версию на `https://osgard.world/games/omega-3d-preview/release.json` (без кэша). Фактическая версия может измениться. **Нельзя считать SHA текущей ветки GitHub SHA опубликованной игры.**

## Независимая аппаратная экспертиза и выпуск

Даже полный машинный проход возвращает только `EVIDENCE_READY_FOR_INDEPENDENT_HARDWARE_REVIEW` и `production_go=false`. Это не проверка, что видео без склеек или сделано на конкретной модели: SHA-256 свидетельствует об неизменности **представленного** файла, но не об истинности его происхождения.

Внешний тестировщик должен лично сверить модель и ОС телефона, исходную страницу, запускаемую игру, целостность записи и показатели. Требуются **отдельные** Android и iPhone, а также все оставшиеся R50/R73/R75 условия (40 человеческих миссий и художественная приёмка). Только после внешнего подписанного решения возможен финальный GO.

Автоматизированные регрессионные тесты создают синтетический JSON и поддельное видео **лишь для проверки отказов**. Они не представляют реальные полевые испытания.
