# REMIX Unity: недоступная игровая сцена и проверка запуска

Дата проверки: 17 октября 2026 года. Проверена опубликованная сборка
`REMIX-webgl3`, Unity `6000.6.3f1`, без изменения исходных файлов движка.

## Решение для посетителя

Обычный маршрут `/games/remix/player/` показывает, что Unity-версия временно
недоступна, и предлагает перейти в `/games/remix/`. Страница не загружает
загрузчик Unity, данные, JavaScript framework или WebAssembly и не показывает
пустое поле как готовую игру. Это ограничение конкретного экспорта Unity.
Статус сервисной консоли REMIX проверяется отдельно её собственными запросами.

Переход в REMIX сохраняет только допустимые поля приглашения: `challenge`,
положительный целочисленный `seed`, допустимый `ref` и `lang=ru|en`.
Без корректного идентификатора испытания `seed` и `ref` не переносятся.
Параметры `diagnostic`, `api`, токены и произвольные поля не передаются.
Русский язык используется по умолчанию; `lang=en` переводит сообщение,
навигацию и диагностические состояния на английский.

Явный `?diagnostic=1` оставляет возможность исследовать сохранённый экспорт.
Даже после успешного `createUnityInstance` текст сообщает о запуске движка,
а игровой процесс остаётся обозначен как недоступный. Этот адрес не является
пользовательской кнопкой запуска рабочей игры.

## Что установлено на исходной сборке

[Первый браузерный запуск](https://github.com/osmanosmanov6880-bot/osgard-world/actions/runs/39022901898)
проверял commit `b9879e853c38217db69e4ed904f62fbddeec127c`.
Chromium запускался в GitHub Actions с программным WebGL через SwiftShader.
Статические файлы обслуживались отдельным контейнером с реальным `nginx.conf`
проекта, включая выдачу файлов `.gz` по URL без расширения сжатия.

| Проверка | Наблюдение |
| --- | --- |
| Данные, framework, WASM | HTTP 200, корректный MIME, `Content-Encoding: gzip`; декодированные хеши совпали с экспортом |
| Инициализация Unity | Обещание движка разрешилось; измеренный единичный запуск занял 1134 мс |
| Ошибки страницы и сети | В этом запуске отсутствовали |
| Контекст | Настоящий WebGL 2, не подмена canvas |
| Кадр через 6 секунд после готовности | Визуально чёрное поле; 99,8336% пикселей попали в один цветовой диапазон |
| Вызовы рисования после готовности | Счётчик оставался 180; за интервал ввода не появилось ни одного нового вызова |
| ArrowRight и Space | Дошли до сфокусированного canvas; движение персонажа, изменение счёта или игрового состояния не подтверждены |
| Изменение скриншота после ввода | Возникла рамка фокуса. Это не доказательство изменения игровой сцены |

Тест содержимого сцены завершился ошибкой. Шесть остальных сценариев прошли:
отсутствующий загрузчик с повторным запуском настоящего движка, ошибка загрузки
данных, отсутствие WebGL, синхронная ошибка инициализации, остановка прогресса
с последующим успешным окончанием и защита от позднего обещания после фатального
сообщения. Проверка потери WebGL-контекста также дошла до корректного состояния
ошибки в сценарии реального движка.

Артефакт `12097427909`, ZIP SHA-256:
`4aa0475d7f3950c8cfb0a60fdcee046caadaf93a58d34cfbf73581eec9282516`.
Он содержит настоящие скриншоты, trace, сетевые ответы и сообщения консоли.
Это лабораторная проверка программного рендера; она не является оценкой
скорости или совместимости всех пользовательских устройств.

## Содержимое сцены

Отдельное чтение исходного архива через UnityPy `1.25.4` обнаружило в `level0`
три GameObject. Все три имеют пустое имя и `m_IsActive=false`.
Они содержат камеру, источник света и `Remix.Bootstrap.RemixServerBootstrap`.
Ссылка последнего: MonoBehaviour с path ID 12 →
`globalgamemanagers.assets`, path ID 526. Камера находится в `(0, 2, -8)`;
все три Transform имеют корректные масштабы. В сцене нет MeshRenderer,
MeshFilter, Sprite или Canvas.

Это согласуется с сохранённым `unity-webgl-build.log`: импортированная
`Assets/Scenes/Main.unity` содержит GameObject версии 1 ниже поддерживаемой
версии 6. Наличие скомпилированного класса само по себе не доказывает, что
он создаёт рабочую игру. Исходный C#-проект в этом репозитории отсутствует.

## Отклонённый эксперимент

`scripts/remix-unity-reactivation-candidate.py` создаёт отдельный кандидат,
проверяя исходный SHA-256 и точную структуру сцены. Он меняет только три
декодированных байта `level0`: `m_IsActive` объектов 1, 2, 3, по смещениям
726, 774, 822. Остальные декодированные файлы контейнера и оболочки остаются
побайтно равны исходным. Скрипт отказывается перезаписывать существующие файлы
и повторно проверяет результат после упаковки.

Кандидат `c44574178bef66f393c81483a666ad9ef84ad91b0235326f4ae6232bdf2e955c`
создавался только во временной папке и отдельной копии `dist` в CI.
[Экспериментальный запуск](https://github.com/osmanosmanov6880-bot/osgard-world/actions/runs/39023160181)
прошёл доставку файлов и достиг готовности движка. Последние trace-кадры
содержали ровное тёмно-серое поле. Затем браузерный target перестал отвечать;
тест зарегистрировал `Target crashed` и превысил лимит 180 секунд.
Предшествующей JavaScript-ошибки или ошибки сетевого запроса в журнале нет.
Причина падения конкретного C#-метода этим экспериментом не установлена.

Эксперимент отклонён. Он не заменяет исходный публичный экспорт и не является
восстановленной игрой. Артефакт `12097940708`, ZIP SHA-256:
`7c81523d000264db96fd4cd52717a6336126f9ced65687fdd211449e3b781432`.

## Автоматические проверки и ручная диагностика

`build-status.json` закрепляет доступность и SHA-256 всех четырёх используемых
файлов экспорта. `scripts/remix-unity-status-check.mjs` отклоняет неизвестный
или изменившийся файл. Новая сборка требует явного пересмотра статуса после
проверки реального содержимого и управления.

Автоматический workflow **REMIX launcher safety and recovery** проверяет
недоступный обычный маршрут, отсутствие загрузки движка, безопасный перенос
приглашения и обработку ошибок диагностического запуска. Его успешный результат
не означает успешного игрового процесса Unity.

```sh
node scripts/remix-unity-status-check.mjs
node scripts/remix-unity-status-check.mjs --self-test
npm run build
node scripts/remix-unity-status-check.mjs dist
bash scripts/check-nginx-unity-browser.sh --grep-invert 'actual gzip build'
```

Проверка настоящей сцены вынесена в отдельный workflow
**REMIX Unity playability diagnostic (manual)**, запускаемый только через
`workflow_dispatch`. Она сохраняет самостоятельный ошибочный результат для
нынешнего экспорта. Необязательный `include_reactivation` воспроизводит
отклонённый эксперимент в отдельном job, без публикации.

```sh
bash scripts/check-nginx-unity-browser.sh --grep 'actual gzip build'
```

Оба браузерных запуска требуют подготовленного окружения CI с Docker,
`@playwright/test@1.58.2`, `pngjs@7.0.0` и Chromium. Диагностические действия
ограничены 15 секундами; финальный запрос состояния страницы — 5 секундами.
Сохраняются сведения о падении target, сеть, консоль и доступные кадры.

Для снятия недоступности нужны рабочая игровая сцена, управляемое изменение
игрового состояния и проверка соответствующего экспорта на реальном движке.
Сетевые результаты, сохранения и совместимость телефонов требуют отдельных
подтверждений; успешная выдача WASM или готовность движка их не заменяет.
