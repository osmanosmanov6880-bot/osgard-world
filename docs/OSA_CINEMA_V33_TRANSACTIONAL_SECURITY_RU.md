# OSA CINEMA V33 — безопасное хранение, диагностический протокол и передача исходников

**25 октября 2026 года — инженерный релиз (локально). Записанный фильм: NO-GO.**

## Что изменено относительно V32.1

1. **Полная предварительная проверка без записи.** Перед `prepare` проверяются не только корни `film/` и `reports/`, но и существующие `film/masters/`, `film/captions/`: символьные ссылки в предках, не-каталоги, небезопасные POSIX-права. Реальные материалы не изменяются.
2. **Компенсирующий откат.** Каждая вновь созданная директория записывается в список. Если подготовка прервана, выполняется `rmdir` только новых **пустых** папок в обратном порядке. Существующие папки и файлы не удаляются, доступы владельца не изменяются автоматически. Это не защита от враждебных параллельных процессов или нестабильных файловых систем: проверка и создание не являются одной атомарной OS-транзакцией.
3. **Диагностическая пара JSON + SHA-256.** Контрольные суммы проверяются после записи; если второй файл не записался, неоконченный JSON удаляется. Отдельно проверяются все поля `publicationAuthorized=false`, `rightsCleared=false`, `paidCheckoutEnabled=false`, `releaseDecision='NO_GO'`, поэтому диагностический объект с поддельной «одобренной премьерой» не может быть сохранён.
4. **Дополнительные независимые тесты.** `scripts/osa-cinema-v33-hardening.test.mjs`: вредоносные `masters`/`captions`, неверные права, ошибка диска с откатом, поддельные release-флаги, потеря sidecar. Тесты используют только временные папки и не создают фильм.
5. **CI Windows/macOS/Linux.** `.github/workflows/osa-cinema-v33-hardening.yml` проверяет новые механизмы на каждой ОС; существующие тесты V32/V31 остаются отдельной частью инженерной приёмки.

## Запуск на своём компьютере

Установите Node.js 22+, FFmpeg/ffprobe. Распакуйте полный ZIP в отдельный каталог и запустите `START_OSA_CINEMA.cmd` (Windows), либо `sh ./START_OSA_CINEMA.sh` (macOS/Linux). Мастер должен быть остановлен, если он обнаруживает недостоверное место хранения или недостающие 8 файлов.

## Безопасная интеграция с `osmanosmanov6880-bot/osgard-world`

В автономном архиве находится локальный импортер `launchers/OSA_V32_SAFE_GITHUB_IMPORT.mjs`. Он после проверки исходного ZIP и актуальности репозитория переносит только **14 строго разрешённых новых файлов** в отдельную Git-ветку и создаёт только локальный коммит. Нельзя переписывать действующие `V18_PRIVATE_FOUR_TRACK_QA.json`, `V20_PRIVATE_RELEASE_POLICY.json`, договоры, реальные MP4/VTT или приватные ключи. Импортер не делает `push`, `merge` или публикацию фильма. Исходный программный пакет содержит `CHECKSUMS.sha256`, но этот список **нельзя** копировать в GitHub поверх исходного дерева: он описывает именно закрытый архив, а не весь репозиторий.

При открытии PR требуется сравнить зависимости V20/V28/V31 с актуальным `master`: локальный автономный пакет может включать их снимки другого времени. Проверить CI, историю изменений и ручную экспертную оценку до любого merge.

## Строгий остаточный запрет

Техническая исправность программы не означает готовность произведения. До публичной премьеры нужны: 4 утверждённых видео MP4 и 4 WebVTT со сверенными хешами; подтверждение RU/EN-озвучки и звука человеком; договоры на музыку, голос, видео и изображения; проверка подписантов и права коммерческого использования; подтверждённая production HTTPS-среда, физические устройства, мониторинг и rollback; отдельное подписанное решение издателя для конкретных файлов. **Никакие тестовые файлы и предыдущие отчёты не заменяют эти документы.**
