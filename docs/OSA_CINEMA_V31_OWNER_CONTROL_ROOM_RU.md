# OSA CINEMA V31 — локальный кабинет владельца (приватный релизный контроль)

## 1. Что появилось на практике

Вместо цепочки независимых команд V29/V30 создан закрытый адаптивный русскоязычный интерфейс, доступный исключительно с компьютера владельца по адресу `http://127.0.0.1:PORT`. Это приложение работает локально и не публикуется на osgard.world. Оно НЕ содержит платной витрины, кнопки премьеры, выдачи лицензий, загрузки материалов в облако или сервиса подписи чужими ключами.

Две настоящие операции интерфейса:

- **Проверить четыре фильма** — запускает существующую V29 как отдельный процесс, используя реальные локальные файлы. V29 вызывает V28 (точные 4 MP4 + 4 WebVTT и SHA-256), V24 (полное декодирование), V21 (проверенный браузерный HTTP Range-сервер с паролем), V26 (проверка байтов 200/206/416, полнота SHA-256); опционально V25/V27 (реестр документов о правах и NO-GO). Сгенерированные JSON протоколы и `CHECKSUMS.sha256` доступны для скачивания только после входа в локальный кабинет.
- **Проверить Ed25519** — становится активной только при заранее настроенных реальных владельцем `--pinned-plan`, `--rights-usage` и четырёх параметрах доверенного реестра подписантов. Вызывает существующую V30, проверяет подписи на конкретные хеши 4 MP4/4 WebVTT. Чужие приватные ключи сервер никогда не принимает. **Даже восемь криптографически проверенных подписей оставляют решение NO-GO до реального юридического и production-релиза.**

Веб-кабинет не показывает и не раздаёт сами видео, реальные лицензии или секретные ключи. Он работает с локальными отчётами. Сами MP4 можно проверять в отдельном приватном проигрывателе V21.

## 2. Что должно лежать на компьютере владельца

Требования: Windows, macOS или Linux; Node.js 22+, FFmpeg и FFprobe в PATH. Запускайте из корня репозитория `osgard-world` или полной копии инженерного комплекта, содержащей скрипты V19–V31.

```
D:\OSA_PRIVATE\film\masters\osa-v15-directors-ru.mp4
D:\OSA_PRIVATE\film\masters\osa-v15-directors-en.mp4
D:\OSA_PRIVATE\film\masters\osa-v15-trailer-ru.mp4
D:\OSA_PRIVATE\film\masters\osa-v15-trailer-en.mp4
D:\OSA_PRIVATE\film\captions\osa-v15-directors-ru.vtt
D:\OSA_PRIVATE\film\captions\osa-v15-directors-en.vtt
D:\OSA_PRIVATE\film\captions\osa-v15-trailer-ru.vtt
D:\OSA_PRIVATE\film\captions\osa-v15-trailer-en.vtt
D:\OSA_PRIVATE_REPORTS\
```

Две папки — с медиа и с отчётами — должны быть **разными**, не одна внутри другой. Имена файлов должны соответствовать V16. Это **финальные кандидаты**, а не автоматически лицензированные материалы. Не копируйте закрытые MP4/ключи в публичный GitHub.

## 3. Одна команда для Windows PowerShell

Из корня проекта выполните:

```powershell
$env:OSA_CINEMA_OWNER_CONSOLE_PASSWORD = Read-Host "Новый приватный пароль (не менее 16 символов)"
node scripts/osa-cinema-v31-owner-console.mjs --root "D:\OSA_PRIVATE\film" --reports-root "D:\OSA_PRIVATE_REPORTS" --originals "docs/OSA_CINEMA_V16_WORKPRINT_MANIFEST.json"
```

Терминал выведет `OSA_CINEMA_V31_OWNER_CONSOLE http://127.0.0.1:<порт>`. Откройте адрес в браузере **на том же компьютере**, войдите с введённым паролем и нажмите **«Запустить полную проверку»**. Проверка не мгновенная; сервер показывает состояние. После окончания скачайте пакет JSON и `CHECKSUMS.sha256`. Не закрывайте терминал до завершения операций; для остановки нажмите `Ctrl+C`.

Linux/macOS: используйте переменную `OSA_CINEMA_OWNER_CONSOLE_PASSWORD`, аналогичные `--root`, `--reports-root`; не передавайте пароль параметром командной строки. Сетевая привязка жёстко фиксирована на `127.0.0.1`.

## 4. Как включить проверку подписей только при наличии реальных документов

Сначала **отдельно** зафиксируйте SHA-256 реального V28-манифеста, независимый ключевой реестр и документальное покрытие всех источников. Специалисты должны подписывать утверждения собственными Ed25519-ключами вне этого сервера. В примере ниже файлы хранятся локально и существуют заранее:

```powershell
$env:OSA_CINEMA_OWNER_CONSOLE_PASSWORD = Read-Host "Пароль кабинета"
$pin = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef" # ЗАМЕНИТЬ на проверенный SHA-256 реестра, полученный из независимого канала
node scripts/osa-cinema-v31-owner-console.mjs --root "D:\OSA_PRIVATE\film" --reports-root "D:\OSA_PRIVATE_REPORTS" --pinned-plan "D:\OSA_PRIVATE_APPROVALS\frozen-v28.json" --rights-usage "D:\OSA_PRIVATE_APPROVALS\rights-usage.json" --registry "D:\OSA_PRIVATE_APPROVALS\trusted-registry.json" --registry-sha256 $pin --attestations "D:\OSA_PRIVATE_APPROVALS\signed-approvals.json" --evidence-dir "D:\OSA_PRIVATE_APPROVALS\signer-pdfs"
```

**Не используйте демонстрационный хеш из примера.** Он служит только указанием формата. Настоящий SHA-256 публичных ключей фиксируется доверенным лицом независимо от файла, а не вычисляется из файла после получения на той же машине. Восемь подписей — доказательство криптографической целостности заявлений, но не наличия реальных прав или достоверности текстов договоров.

## 5. Что проверено тестами

- Проверка пароля, CSRF, противодействие подделке формы, ограничение перебора, отзыв сеанса, строгий Host и одноразовый вход.
- Реальные синтетические H.264/AAC MP4 и четыре WebVTT, полный прогон V29, настоящий локальный 200/206/416 + SHA-256, скачивание результатов после входа, запрет подмены отчёта.
- Восемь независимых тестовых Ed25519-ключей, подлинные байты тестовых PDF, обнаружение последующей подмены подписанного документа, жёсткий NO-GO.
- GitHub Actions отдельно запускает Node-тесты и реальный Chromium на 1440 px и 390 px. Видео и юридические документы владельца в GitHub отсутствуют.

## 6. Финальная граница: что остаётся неподтверждённым

Техническая проверка не способна проверить достаточность коммерческих прав, подлинность и полномочия реальных подписантов, качество произнесённой RU/EN-речи, художественную приёмку, воспроизведение на физических устройствах, реальный публичный HTTPS, откат и правомочность решения издателя. Все эти внешние подтверждения должны быть привязаны к точным 4 MP4 и 4 WebVTT SHA-256 до отдельной, контролируемой production-публикации.

**Отсутствует кнопка «Опубликовать» намеренно. Решение остаётся NO-GO, пока указанные доказательства не получены и не проверены людьми.**
